# 第28章 午後演習①：ネットワーク更改の事例を読む

ここからは本番形式の演習です。オリジナルの架空事例（拠点追加のルーティング設計・冗長化の見直し・無線LANと802.1X）を午後問題の読み方で読み、設問に答えます。第27章の「設問から先に読む」手順を実際に使ってみてください。

## 1. 事例演習: 拠点追加とルーティング設計

本番の午後問題と同じ作りのオリジナル事例です。🔴 まず下の設問（quiz）に目を通し、「何が問われるか」を決めてから本文を読んでください。構成図の代わりに、機器とアドレスの対応を表で示します。

---

**〔A社のネットワークと拠点追加〕**

A社は、従業員400名の機械部品メーカーである。東京の本社と大阪営業所を持ち、両拠点は通信事業者のIP-VPN網で接続されている。A社のネットワーク構成の概要を次に示す。

| 場所 | 機器 | セグメント |
|---|---|---|
| 本社 | コアスイッチ L3SW1、WANルータ R1、ファイアウォール FW1 | サーバ用 VLAN10: 172.16.1.0/24、PC用 VLAN20: 172.16.2.0/24 |
| 大阪営業所 | WANルータ R2 | PC用: 172.16.11.0/24 |

インターネット接続は本社のFW1に集約しており、大阪営業所のPCがインターネットを利用するときの通信は、R2からIP-VPN網を経由して本社に届き、L3SW1、FW1の順に経由して外部へ出る。経路制御はすべて静的経路で行っており、R2にはデフォルトルートとして本社向けの経路だけを設定している。L3SW1のデフォルトルートはFW1向けである。

このたびA社は、名古屋営業所（PC用セグメント: 172.16.12.0/24、WANルータ R3）を新設することになった。情報システム部のM主任と部員のNさんが構成を検討した。

Nさん: 静的経路のままでは、拠点を追加するたびにL3SW1、R1と既存の全拠点のルータに経路を手作業で追加する必要があります。今後も拠点は増える計画です。

M主任: では、①**R1、R2、R3とL3SW1でルーティングプロトコルのOSPFを動作させる**構成にしよう。エリアは当面、バックボーンエリアの単一エリアでよい。

Nさん: 各拠点のインターネット向け通信はどうしますか。

M主任: ②**デフォルトルートはR1からOSPFで各拠点に広告する**。ただし、FW1はOSPFに参加しないものとし、L3SW1とFW1の間は従来どおり静的経路とする。

---

本文を読み終えたら、下線①②の「目的」と「そうしなければ何が困るか」を自分の言葉で言えるか確認してから設問に進みましょう。

### 確認問題

**問1.** 下線①（OSPFの導入）の目的として、最も適切なものはどれでしょう？

1. IP-VPN網の通信を暗号化するため
2. 拠点追加時に各機器へ経路を手作業で追加する作業と設定漏れをなくすため
3. インターネット回線の帯域を増やすため
4. VLAN10とVLAN20を統合するため

<details><summary>答えと解説</summary>

正解: **2**

直前のNさんの発言に「拠点を追加するたびに全機器へ手作業で経路追加が必要」という課題があり、OSPFはこれを経路の自動広告で解決します。暗号化はルーティングプロトコルの機能ではなく、帯域増強やVLAN統合とも無関係です。本番の記述なら「拠点追加時に各機器へ経路を手動設定する作業と設定漏れをなくすため」（31字）のように、下線直前の課題を使って書きます。

</details>

**問2.** 名古屋営業所のPCがインターネット上のWebサイトを閲覧するときの通信経路として、正しいものはどれでしょう？

1. R3 → インターネット（名古屋から直接外部へ出る）
2. R3 → IP-VPN網 → R2 → インターネット
3. R3 → IP-VPN網 → R1 → L3SW1 → FW1 → インターネット
4. R3 → FW1 → R1 → インターネット

<details><summary>答えと解説</summary>

正解: **3**

本文に「インターネット接続は本社のFW1に集約」とあり、大阪の例と同様に、名古屋の通信もIP-VPN網で本社R1に届き、L3SW1、FW1の順で外部へ出ます。名古屋や大阪から直接外部へ出る構成ではなく、FW1は本社のL3SW1の先にあるのでR3の直後を通ることもありません。本番の記述なら「R3からIP-VPN網を経由して本社に届き、L3SW1、FW1を経由して外部へ出る」のように機器名を順に並べます。

</details>

**問3.** 下線②のとおり、デフォルトルートをR1からOSPFで広告する必要がある理由として、最も適切なものはどれでしょう？

1. FW1はOSPFに参加しないので、インターネット向けの経路は自動では各拠点に伝わらないため
2. OSPFはデフォルトルート以外の経路を扱えないため
3. IP-VPN網がデフォルトルートを禁止しているため
4. R2とR3が静的経路しか設定できない機種だから

<details><summary>答えと解説</summary>

正解: **1**

本文の「ただし、FW1はOSPFに参加しないものとする」が根拠です。外部への出口となるFW1がOSPFの外にいる以上、インターネット向けの経路（デフォルトルート）は、FW1への静的経路を持つ側のR1が代表して各拠点へ広告する必要があります。OSPFは通常の経路も扱え、IP-VPN網や機種の制約は本文にありません。本番の記述なら「FW1がOSPFに参加せず、外部向け経路が自動では各拠点に広告されないため」（35字）と、注記を根拠に書きます。

</details>

**問4.** 経路制御を静的経路のまま運用し続けた場合の問題点として、最も適切なものはどれでしょう？

1. PCのIPアドレスが毎回変わってしまう
2. 拠点追加や経路変更のたびに全機器で手作業の設定が必要になり、設定ミスや漏れが起きやすい
3. 静的経路ではインターネットに接続できない
4. VLANが使用できなくなる

<details><summary>答えと解説</summary>

正解: **2**

静的経路は追加・変更をすべて人手で行うため、拠点が増えるほど作業量と設定ミス・漏れのリスクが増えます。これが本文でOSPF導入を決めた理由そのものです。静的経路でもインターネット接続もVLANも問題なく使え、PCのアドレスは経路制御方式とは無関係（DHCPの話）です。本番の記述なら「拠点追加のたびに全機器への手作業の経路設定が必要で、設定漏れが生じやすいという問題」（41字）と書きます。

</details>

**問5.** この構成で、L3SW1に設定されているデフォルトルートの向き先（ネクストホップ側の機器）はどれでしょう？

1. R2
2. R3
3. FW1
4. 大阪営業所のPC

<details><summary>答えと解説</summary>

正解: **3**

本文に「L3SW1のデフォルトルートはFW1向けである」と明記されています。社内で宛先が分からない通信＝インターネット向け通信は、出口であるFW1へ送るのが自然な設計です。R2・R3は各拠点のWANルータで、PCが経路の向き先になることはありません。本番でこの種の穴埋めが出たら、本文の該当文をそのまま根拠として「FW1向けのデフォルトルートを設定しているため」のように答えます。

</details>

## 2. 事例演習: 冗長化構成の見直し（VRRP・STP・LAG）

冗長化の事例です。🔴 「どの機器が止まったら、どの通信が、どう切り替わるか」を追いながら読むのがこの種の問題のコツです。設問を先に確認してから本文に進んでください。

---

**〔B社の社内LANの冗長化〕**

B社は、従業員600名の商社である。本社ビルの社内LANは、コアスイッチとしてレイヤ3スイッチのL3SW1とL3SW2の2台を設置し、各フロアのフロアスイッチFS1、FS2（レイヤ2スイッチ）は、それぞれL3SW1とL3SW2の両方に接続されている。PC用セグメントはVLAN20（172.17.20.0/24）であり、社内のPCにはデフォルトゲートウェイとして172.17.20.254が設定されている。

L3SW1とL3SW2はVLAN20でVRRPを構成しており、仮想IPアドレスは172.17.20.254である。優先度はL3SW1が120、L3SW2が100であり、通常時はL3SW1がマスタとして動作する。

フロアスイッチが2台のコアスイッチの両方に接続されているため、L2のループが生じる構成であり、ループの防止にはSTPを使用している。ブリッジプライオリティはL3SW1が最小になるように設定し、①**STPのルートブリッジがVRRPのマスタと同じL3SW1になるように**している。

また、L3SW1とL3SW2の間は、②**2本の物理リンクを束ねてLAGを構成**している。

先日の設計レビューで、ネットワーク担当のNさんが情報システム部のM主任に質問した。

Nさん: L3SW1が故障した場合、PCからデフォルトゲートウェイ宛ての通信はどうなりますか。

M主任: VRRPによってL3SW2が新たなマスタとなり、仮想IPアドレスと仮想MACアドレス宛ての通信を引き継ぐ。PC側の設定変更は不要だ。

Nさん: なるほど。ただ、この構成を見ると、インターネットとの境界にあるFW1は1台のままです。ここは③**単一障害点**になっていませんか。

M主任: そのとおりだ。FWの冗長化は次期更改の課題としよう。

---

「マスタ故障時の動き」「ルートブリッジとマスタをそろえる理由」「LAGの効果」の3点を自分の言葉で説明できるか確認してから、設問へ進みましょう。

### 確認問題

**問1.** L3SW1が故障したとき、PCからデフォルトゲートウェイ宛ての通信が継続できる理由として、最も適切なものはどれでしょう？

1. 各PCのデフォルトゲートウェイ設定が自動的にL3SW2の実IPアドレスに書き換わるため
2. L3SW2がVRRPのマスタに昇格し、仮想IPアドレスと仮想MACアドレス宛ての通信を引き継ぐため
3. STPがVLAN20のIPアドレスを付け替えるため
4. FS1とFS2がルーティングを代行するため

<details><summary>答えと解説</summary>

正解: **2**

PCが向いているのは仮想IPアドレス172.17.20.254です。マスタ故障時はバックアップのL3SW2がマスタに昇格し、同じ仮想IP・仮想MAC宛ての通信を引き継ぐので、PC側は何も変わりません。PCの設定が書き換わる仕組みではなく、STPはL2のループ防止でIPには関与せず、FS1/FS2はL2スイッチなのでルーティングできません。本番の記述なら「L3SW2がマスタに昇格し、仮想IPアドレス宛ての通信を引き継ぐため」（33字）と書きます。

</details>

**問2.** 下線①のように、STPのルートブリッジをVRRPのマスタと同じL3SW1にそろえる目的として、最も適切なものはどれでしょう？

1. PCへのIPアドレス配布を速くするため
2. VRRPの優先度を自動で変更するため
3. PCからデフォルトゲートウェイへの通信が、遠回りの経路を通らないようにするため
4. ブロードキャストを完全になくすため

<details><summary>答えと解説</summary>

正解: **3**

ルートブリッジとVRRPマスタが別の機器だと、STPのブロッキングの結果、PCからマスタへの通信がいったん別のスイッチを経由する遠回りの経路になることがあります。両者をL3SW1にそろえれば、L2の転送経路とL3の出口が一致し、無駄のない経路になります。IPアドレス配布はDHCPの役割、STPはVRRP優先度を変更せず、ブロードキャスト自体をなくす技術でもありません。本番の記述なら「L2の転送経路とデフォルトゲートウェイを一致させ、う回経路の通過を防ぐため」（37字）と書きます。

</details>

**問3.** 下線②（L3SW1-L3SW2間のLAG）の目的として、最も適切なものはどれでしょう？

1. 帯域を拡大しつつ、1本のリンク障害ではリンクダウンとSTPの再計算を発生させないため
2. 2本のリンクでL2ループをわざと作るため
3. L3SW2を常にマスタにするため
4. VLANの数を2倍にするため

<details><summary>答えと解説</summary>

正解: **1**

LAGは複数の物理リンクを論理的に1本に束ねる技術で、帯域の合算と、1本が切れても論理リンクは生き続けるリンク冗長が得られます。論理的に1本なのでループにはならず、STPから見てもトポロジ変更が起きません。VRRPのマスタ選定やVLAN数とは無関係です。本番の記述なら「帯域を拡大し、1本の障害時もトポロジ変更なしで通信を継続するため」（32字）と、効果を2つ入れて書きます。

</details>

**問4.** Nさんが下線③で指摘したとおり、この構成で単一障害点となっている箇所はどれでしょう？

1. L3SW1（故障したら全社の通信が止まる）
2. FS1とFS2の間のリンク
3. FW1（故障したらインターネットとの通信がすべて止まる）
4. PCのLANケーブル

<details><summary>答えと解説</summary>

正解: **3**

L3SWはVRRPで2台化、フロアスイッチからの上り回線も2系統、コア間はLAGと、LAN内は冗長化済みです。一方FW1は1台だけなので、故障するとインターネットとの通信が全面停止します。これが単一障害点（SPOF）です。L3SW1の故障はL3SW2が引き継ぎ、FS1-FS2間の直接リンクは本文の構成に存在せず、PCのケーブルは影響がその1台に限られます。本番の記述なら「FW1が1台構成であり、故障時にインターネット通信が全て停止するため」（34字）と書きます。

</details>

**問5.** この事例で、社内のPCに設定されているデフォルトゲートウェイのIPアドレスはどれでしょう？

1. L3SW1の実IPアドレス
2. L3SW2の実IPアドレス
3. FW1のIPアドレス
4. VRRPの仮想IPアドレス 172.17.20.254

<details><summary>答えと解説</summary>

正解: **4**

本文に「PCにはデフォルトゲートウェイとして172.17.20.254が設定されている」「仮想IPアドレスは172.17.20.254」とあります。実IPアドレスを設定すると、その機器が故障したときに通信が止まり、VRRPの意味がなくなります。FW1はPCと同一セグメントのゲートウェイではありません。本番でこの点を問われたら「障害時も変わらない仮想IPアドレスをゲートウェイとするため」（29字）のように、仮想IPを使う理由まで添えて書けると強いです。

</details>

## 3. 事例演習: 無線LAN導入と認証（802.1X）

無線LANと認証の事例です。🔴 認証方式の変更問題では「今の方式の何が困っていて、新方式はそれをどう解決するか」の対応づけが設問の中心になります。

---

**〔C社の無線LAN更改〕**

C社は、従業員250名の設計事務所である。現在、各フロアに個別に設置した無線APでSSID「C-WLAN」を提供しており、認証はWPA2-PSK（事前共有鍵）方式で、①**全社で共通の1つの事前共有鍵を全端末に設定している**。

社内のセキュリティ点検で、この方式には運用上の問題があると指摘された。情報システム部のM課長と担当のNさんは、無線LANの更改を次のように計画した。

- 無線LANコントローラ（WLC）を導入し、AP20台を集中管理する
- 社員用SSID「C-EMP」の認証をIEEE 802.1Xに変更する。EAP方式には、社員PCに配布するクライアント証明書で認証する②**EAP-TLS**を採用する
- 認証サーバとしてRADIUSサーバを新設する。WLCがオーセンティケータ、社員PCがサプリカントとなる
- 認証に成功した社員PCは、RADIUSサーバからの応答に含まれる属性情報に基づき、社員用のVLAN30（192.168.30.0/24）に収容する
- 来客用に別のSSID「C-GUEST」を用意し、ゲスト用のVLAN40（192.168.40.0/24）に収容する。VLAN40からは③**FWで社内セグメント宛ての通信を禁止し、インターネット宛ての通信のみを許可する**

Nさん: 802.1Xにすれば、社員が退職した場合も安心ですね。

M課長: そうだ。退職者については、RADIUSサーバ側で該当する利用者のアカウントを無効化し、発行済みのクライアント証明書を失効させればよい。全端末の設定を変更して回る必要はない。

---

「PSKの問題点」「802.1Xの3つの登場人物」「ゲストを分離する理由」を押さえてから設問に進みましょう。

### 確認問題

**問1.** 下線①の方式（全社共通の事前共有鍵）がもつ運用上の問題点として、最も適切なものはどれでしょう？

1. 鍵が1つなので通信速度が遅くなる
2. 退職者も鍵を知ったままであり、鍵が漏えいした場合は全端末で鍵の変更が必要になる
3. 事前共有鍵では暗号化が一切行われない
4. APを2台以上設置できない

<details><summary>答えと解説</summary>

正解: **2**

共通PSKは「誰が接続したか」を区別できず、退職者を個別に締め出せません。また鍵が1つでも漏れれば、全端末・全APで鍵を変更して回る必要があり、運用負荷が非常に大きくなります。PSKでも暗号化自体は行われ、通信速度やAPの台数とは無関係です。本番の記述なら「鍵が全端末で共通のため、漏えい時に全端末での鍵の変更が必要になるという問題」（38字）と書きます。

</details>

**問2.** この事例の802.1X構成で、RADIUSサーバが担う役割はどれでしょう？

1. サプリカント（認証を要求する端末）
2. オーセンティケータ（認証の仲介役）
3. 認証サーバ（利用者の認証可否を判定する）
4. DHCPサーバ（IPアドレスを配布する）

<details><summary>答えと解説</summary>

正解: **3**

802.1Xの登場人物は、サプリカント（本事例では社員PC）、オーセンティケータ（WLC）、認証サーバ（RADIUSサーバ）の3つです。RADIUSサーバは利用者の資格情報や証明書を検証し、認証の可否を判定します。本文にも「WLCがオーセンティケータ、社員PCがサプリカント」と明記されています。IPアドレス配布はDHCPの役割で本設問とは別物です。本番でこの3要素の対応づけは頻出なので、「PC=サプリカント、WLC/AP=オーセンティケータ、RADIUS=認証サーバ」と即答できるようにしてください。

</details>

**問3.** 下線②のEAP-TLSを採用する利点として、最も適切なものはどれでしょう？

1. クライアント証明書で認証するため、パスワードの漏えいや使い回しのリスクがない
2. 証明書の配布や管理が一切不要になる
3. 暗号化せずに通信するので高速である
4. 事前共有鍵と併用しないと動作しない

<details><summary>答えと解説</summary>

正解: **1**

EAP-TLSは利用者・端末をクライアント証明書で認証する方式で、パスワードを使わないため、漏えい・推測・使い回しといったパスワード起因のリスクを避けられます。その代わり証明書の発行・配布・失効の管理が必要になる（利点ではなくコスト）点に注意してください。通信は暗号化されますし、PSKとの併用も不要です。本番の記述なら「パスワードを用いず、クライアント証明書で利用者を認証できるため」（31字）と書きます。

</details>

**問4.** 下線③のとおり、ゲスト用VLAN40に通信制限を掛ける目的として、最も適切なものはどれでしょう？

1. ゲスト端末の電池消費を抑えるため
2. 来客の端末から社内のサーバやPCへアクセスされることを防ぐため
3. ゲストのインターネット利用を禁止するため
4. VLAN30の社員端末の台数を減らすため

<details><summary>答えと解説</summary>

正解: **2**

来客の端末はC社の管理外であり、マルウェア感染の有無も分かりません。ゲストをVLAN40に分離し、FWで社内セグメント宛てを禁止することで、万一の際も被害が社内に及ばないようにします。本文のとおりインターネット宛ては許可するので利用禁止ではなく、電池消費や社員端末の台数とは無関係です。本番の記述なら「管理外の来客端末から社内セグメントへのアクセスを防ぐため」（28字）と書きます。

**問5.** 社員の退職時に、その社員が社内無線LANへ接続できないようにする運用として、本文に沿った正しいものはどれでしょう？

1. 全端末の事前共有鍵を変更する
2. SSIDの名前を変更する
3. RADIUSサーバで該当アカウントを無効化し、クライアント証明書を失効させる
4. 退職者の席のLANケーブルを抜く

<details><summary>答えと解説</summary>

正解: **3**

802.1Xでは利用者ごとに認証するため、M課長の発言どおり、認証サーバ側でアカウント無効化と証明書失効を行えば、その利用者だけを確実に締め出せます。全端末の鍵変更が必要なのは旧PSK方式の話で、802.1X移行でまさに不要になった作業です。SSID変更は全員に影響し、LANケーブルは無線接続と無関係です。本番の記述なら「認証サーバで該当者のアカウントを無効化し、証明書を失効させる」（30字）と書きます。

</details>
