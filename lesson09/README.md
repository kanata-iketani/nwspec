# 第9章 ネットワークの全体像（OSI・TCP/IP）

ここからネットワーク本編です。OSI参照モデルとTCP/IP、カプセル化という「共通言語」を手に入れ、PCがWebページを開くまでの通信の全体像を俯瞰する章です。以降のすべての章の土台になります。

## 1. ネットワークとは・OSI参照モデルを手紙でたとえる

ここからネットワーク本編です。**ネットワーク**とは、複数のコンピュータをつないでデータをやり取りする仕組みのこと。通信には「アプリの処理」「確実に届ける管理」「宛先までの経路選択」「電気信号への変換」など多くの仕事が絡むため、役割を**階層（レイヤ）**に分けて整理します。その世界共通の整理表が **OSI参照モデル（7階層）** です。

### 手紙にたとえると

| 層 | 名前 | 役割 | 手紙でいうと |
|---|---|---|---|
| 7 | アプリケーション層 | アプリごとの通信サービス | 手紙の用件そのもの |
| 6 | プレゼンテーション層 | 文字コードなどデータ表現 | 相手が読める言語で書く |
| 5 | セッション層 | 会話の開始・終了の管理 | 文通のやり取りの管理 |
| 4 | トランスポート層 | 端末間で確実に届ける | 書留で確実に届ける |
| 3 | ネットワーク層 | 宛先までの経路選択 | 住所を見て配送ルートを決める |
| 2 | データリンク層 | 隣の機器まで届ける | 隣の郵便局までの輸送 |
| 1 | 物理層 | 電気信号・光として伝送 | トラックや飛行機そのもの |

階層化の利点は、**各層が独立している**こと。トラックを飛行機に変えても手紙の文面を書き直す必要がないように、ある層の技術を入れ替えても他の層は影響を受けません。

> 💡 下の層から「物・デ・ネ・ト・セ・プ・ア」と唱えて番号ごと覚えましょう。🔴 午前Ⅱでは「この機能は第何層か」が定番の出題です。

### 確認問題

**問1.** OSI参照モデルの第3層（ネットワーク層）の主な役割はどれでしょう？

1. ビットを電気信号や光に変換して伝送する
2. 隣接する機器との間でフレームを伝送する
3. 論理アドレスに基づいて宛先までの経路を選択する
4. 文字コードなどデータ表現の違いを吸収する

<details><summary>答えと解説</summary>

正解: **3**

ネットワーク層は、IPアドレスのような論理アドレスを使って複数のネットワークをまたぐ宛先までの経路選択（ルーティング）を担います。電気信号への変換は第1層（物理層）、隣接機器間のフレーム伝送は第2層（データリンク層）、データ表現の変換は第6層（プレゼンテーション層）の役割です。

</details>

**問2.** 通信機能を階層化して設計する利点として、最も適切なものはどれでしょう？

1. ある層の技術を変更しても、他の層に影響を与えずに済む
2. 階層を増やすほど通信速度が向上する
3. すべての層を同じベンダの製品でそろえられる
4. ヘッダが不要になり通信量を削減できる

<details><summary>答えと解説</summary>

正解: **1**

各層は役割と受け渡しのルール（インタフェース）だけで結ばれているため、たとえば物理層のケーブルを光ファイバに替えてもアプリは修正不要です。階層が増えること自体は速度向上にはつながらず、むしろ各層がヘッダを付けるので通信量はわずかに増えます。ベンダ統一は階層化の目的ではなく、むしろ異なるベンダ同士をつなげることが狙いです。

</details>

**問3.** OSI参照モデルを第1層から第4層まで順に並べたものとして、正しいのはどれでしょう？

1. 物理層→ネットワーク層→データリンク層→トランスポート層
2. 物理層→データリンク層→トランスポート層→ネットワーク層
3. データリンク層→物理層→ネットワーク層→トランスポート層
4. 物理層→データリンク層→ネットワーク層→トランスポート層

<details><summary>答えと解説</summary>

正解: **4**

下から物理層（1）→データリンク層（2）→ネットワーク層（3）→トランスポート層（4）の順です。「物・デ・ネ・ト」のリズムで下から覚えると、他の選択肢のように第2層と第3層が入れ替わった並びに惑わされなくなります。

</details>

**問4.** 送信元と宛先の端末間（エンドツーエンド）で、データを確実に届けるための信頼性確保を担う層はどれでしょう？

1. ネットワーク層
2. トランスポート層
3. セッション層
4. データリンク層

<details><summary>答えと解説</summary>

正解: **2**

トランスポート層（第4層）は、TCPに代表されるように端末同士の間でデータの到達確認や再送を行います。ネットワーク層は経路選択を行うだけで到達の保証まではせず、データリンク層が面倒を見るのは隣接する機器までの一区間だけです。セッション層は会話の開始・終了の管理が役割です。

</details>

## 2. TCP/IP 4階層とOSIの対応

OSI参照モデルは「共通の整理表」ですが、実際のインターネットで動いているのは、より実践的な **TCP/IPモデル（4階層）** です。試験でも実務でも、両モデルの対応を行き来できることが大前提になります。

### 対応表

| TCP/IPモデル | OSI参照モデル | 代表的なプロトコル・技術 |
|---|---|---|
| アプリケーション層 | 第5〜7層 | HTTP、DNS、SMTP |
| トランスポート層 | 第4層 | TCP、UDP |
| インターネット層 | 第3層 | IP、ICMP |
| ネットワークインタフェース層 | 第1〜2層 | イーサネット、無線LAN |

ポイントは2つ。OSIの上位3層（セッション・プレゼンテーション・アプリケーション）がTCP/IPでは**アプリケーション層1つにまとまる**こと、物理層とデータリンク層が**ネットワークインタフェース層にまとまる**ことです。

### 機器も「何層の装置か」で整理できる

| 機器 | 動作する層 |
|---|---|
| リピータハブ | 物理層（第1層） |
| スイッチ（L2） | データリンク層（第2層） |
| ルータ・L3スイッチ | ネットワーク層（第3層） |

> 💡 🔴 「IPは何層？」「スイッチは何層？」と聞かれて即答できるようにしましょう。この先のすべての章で「いま何層の話か」を意識すると、知識が絡まらずに積み上がります。

### 確認問題

**問1.** TCP/IPモデルのインターネット層は、OSI参照モデルのどの層に対応するでしょう？

1. トランスポート層（第4層）
2. ネットワーク層（第3層）
3. データリンク層（第2層）
4. セッション層（第5層）

<details><summary>答えと解説</summary>

正解: **2**

インターネット層はIPが動く層で、OSIのネットワーク層（第3層）に対応します。トランスポート層は両モデルで同じ名前のまま対応し、データリンク層はネットワークインタフェース層の一部、セッション層はTCP/IPではアプリケーション層に含まれます。

</details>

**問2.** OSI参照モデルのセッション層・プレゼンテーション層・アプリケーション層の3つをまとめて担う、TCP/IPモデルの層はどれでしょう？

1. ネットワークインタフェース層
2. インターネット層
3. トランスポート層
4. アプリケーション層

<details><summary>答えと解説</summary>

正解: **4**

TCP/IPモデルではOSIの上位3層（第5〜7層）をアプリケーション層1つに集約しています。ネットワークインタフェース層が束ねるのは下位の物理層とデータリンク層で、インターネット層とトランスポート層はそれぞれOSIの第3層・第4層に1対1で対応します。

</details>

**問3.** プロトコル「IP」が属する層として、正しいものはどれでしょう？

1. インターネット層
2. アプリケーション層
3. トランスポート層
4. ネットワークインタフェース層

<details><summary>答えと解説</summary>

正解: **1**

IPはTCP/IPモデルのインターネット層（OSIのネットワーク層）のプロトコルで、宛先までパケットを届ける役割を持ちます。アプリケーション層に属するのはHTTPやDNS、トランスポート層はTCPやUDP、ネットワークインタフェース層はイーサネットなどです。

</details>

**問4.** L2スイッチが主に動作するOSI参照モデルの層はどれでしょう？

1. 物理層（第1層）
2. ネットワーク層（第3層）
3. データリンク層（第2層）
4. トランスポート層（第4層）

<details><summary>答えと解説</summary>

正解: **3**

L2スイッチはフレームのMACアドレスを見て転送するので、データリンク層（第2層）の機器です。物理層の機器は信号を中継するだけのリピータハブ、ネットワーク層の機器はIPアドレスで経路選択するルータやL3スイッチです。トランスポート層で動作する集線機器は一般のLANにはありません。

</details>

## 3. カプセル化とヘッダ（フレーム・パケット・セグメントの入れ子）

アプリケーションが作ったデータは、そのままケーブルに流れるわけではありません。各層が自分の仕事に必要な管理情報（**ヘッダ**）をデータの先頭に付け足しながら、下の層へ渡していきます。これを**カプセル化**といいます。荷物を箱に入れ、伝票を貼り、さらにコンテナに積み込むイメージです。

### 層ごとのデータの呼び名

| 層 | 付けるもの | できあがる単位 |
|---|---|---|
| トランスポート層 | TCPヘッダ | **セグメント** |
| ネットワーク層 | IPヘッダ | **パケット** |
| データリンク層 | イーサネットヘッダ＋FCS | **フレーム** |

つまりケーブル上を流れるフレームの中身は、外側から「イーサネットヘッダ［IPヘッダ［TCPヘッダ［データ］］］FCS」という**入れ子構造**です。フレームの末尾に付く **FCS** は、伝送中にビット誤りが起きていないかを検出するためのチェック用データ（トレーラ）です。

受信側では逆に、下の層から順にヘッダを外しながら上の層へ渡します（**非カプセル化**）。

> 💡 🔴 機器は「自分の層のヘッダ」しか見ません。スイッチはイーサネットヘッダの宛先MAC、ルータはIPヘッダの宛先IPを見る——この一文が、この先のすべての章の土台になります。

### 確認問題

**問1.** トランスポート層でTCPヘッダが付けられたデータの単位は、何と呼ばれるでしょう？

1. フレーム
2. パケット
3. ビット列
4. セグメント

<details><summary>答えと解説</summary>

正解: **4**

TCPヘッダが付いた単位はセグメントです。そのセグメントにIPヘッダが付くとパケット、さらにイーサネットヘッダとFCSが付くとフレームになります。ビット列は物理層で信号として扱うときの見方で、特定のヘッダが付いた単位の名前ではありません。

</details>

**問2.** ケーブル上を流れるフレームを外側（先頭）から見たとき、ヘッダの並び順として正しいものはどれでしょう？

1. イーサネットヘッダ→IPヘッダ→TCPヘッダ→データ
2. TCPヘッダ→IPヘッダ→イーサネットヘッダ→データ
3. IPヘッダ→イーサネットヘッダ→TCPヘッダ→データ
4. イーサネットヘッダ→TCPヘッダ→IPヘッダ→データ

<details><summary>答えと解説</summary>

正解: **1**

カプセル化は上の層から順に行われ、後から付けたヘッダほど外側に来ます。TCPヘッダ（第4層）が最も内側、次にIPヘッダ（第3層）、最も外側がイーサネットヘッダ（第2層）です。他の選択肢はこの内外の関係が崩れており、受信側が外側から順にヘッダを外していけなくなります。

</details>

**問3.** イーサネットフレームの末尾に付くFCSの役割はどれでしょう？

1. 宛先までの経路を記録する
2. 伝送中に発生したビット誤りを検出する
3. データを暗号化する
4. フレームの優先度を示す

<details><summary>答えと解説</summary>

正解: **2**

FCS（Frame Check Sequence）は送信時に計算したチェック値で、受信側が再計算して一致しなければ「伝送中に壊れた」と判断してフレームを破棄します。経路の記録や暗号化の機能はなく、優先度は802.1Qタグなど別のフィールドで表します。

</details>

**問4.** ルータがパケットの転送先を決めるために参照する情報はどれでしょう？

1. イーサネットヘッダの送信元MACアドレス
2. TCPヘッダのポート番号
3. IPヘッダの宛先IPアドレス
4. FCSの値

<details><summary>答えと解説</summary>

正解: **3**

ルータは第3層の機器なので、IPヘッダの宛先IPアドレスを経路表と照合して転送先を決めます。送信元MACアドレスを学習に使うのはスイッチ、ポート番号を見るのはファイアウォールや負荷分散装置などで、FCSは誤り検出専用の値です。

</details>

## 4. 通信をたどってみる——PCがWebページを開くまで

PCのブラウザで「https://www.example.jp/」を開く——このとき裏側では、ここまで学んだ仕組みが総動員されます。細部は後の章で学ぶので、まず全体の流れを俯瞰しましょう。

### Webページが表示されるまでの5ステップ

1. **名前解決（DNS）**：ホスト名 www.example.jp から、WebサーバのIPアドレスを調べます
2. **宛先の判定**：宛先IPと自分のネットワーク部を比べ、別ネットワークなら「**デフォルトゲートウェイ**（ルータ）に渡す」と判断します
3. **ARP**：デフォルトゲートウェイのMACアドレスを調べ、フレームの宛先MACに設定します
4. **TCP接続**：Webサーバとの間で**3ウェイハンドシェイク**を行い、コネクションを確立します
5. **HTTP**：確立したコネクション上で、ページのデータを要求・受信します

### 旅の途中で変わるもの・変わらないもの

| 項目 | ルータを越えると |
|---|---|
| 宛先IPアドレス | **変わらない**（最後までWebサーバ宛て） |
| 宛先MACアドレス | **区間ごとに変わる**（次のルータ宛てに付け替え） |

> 💡 🔴 「IPは終点までの住所、MACは次の一区間の宛名」。この5ステップは午後問題を読むときの地図になるので、何も見ずに言えるようにしておきましょう。

### 確認問題

**問1.** ブラウザにURLを入力したとき、WebサーバのIPアドレスを知るために利用される仕組みはどれでしょう？

1. ARP
2. DNS
3. DHCP
4. ICMP

<details><summary>答えと解説</summary>

正解: **2**

ホスト名からIPアドレスを調べる名前解決はDNSの役割です。ARPはIPアドレスからMACアドレスを求める仕組み、DHCPは自分のIPアドレスなどを自動取得する仕組み、ICMPはエラー通知や疎通確認（ping）に使われるプロトコルで、いずれも名前解決は行いません。

</details>

**問2.** 別ネットワークにあるWebサーバ宛ての通信で、PCが最初に送出するフレームの宛先MACアドレスはどれでしょう？

1. WebサーバのMACアドレス
2. ブロードキャストアドレス
3. DNSサーバのMACアドレス
4. デフォルトゲートウェイのMACアドレス

<details><summary>答えと解説</summary>

正解: **4**

MACアドレスは同一ネットワーク内の一区間でしか使えない宛名なので、別ネットワーク宛てのフレームはまずデフォルトゲートウェイ（ルータ）のMACアドレス宛てに送ります。WebサーバのMACアドレスは別ネットワークにあるため知りようがなく、ブロードキャスト宛てに送る仕組みでもありません。DNSサーバは名前解決の相手であり、データの中継役ではありません。

</details>

**問3.** ルータを複数経由してWebサーバに届くまでの間、原則として変化しないものはどれでしょう（NATは使わないものとします）？

1. IPヘッダの宛先IPアドレス
2. イーサネットヘッダの宛先MACアドレス
3. イーサネットヘッダの送信元MACアドレス
4. フレーム全体のFCSの値

<details><summary>答えと解説</summary>

正解: **1**

宛先IPアドレスは最終目的地を示すので、途中のルータでは書き換えられません。一方、イーサネットのヘッダはルータを越えるたびに「次の一区間」用に作り直されるため、宛先・送信元MACアドレスは区間ごとに変わり、それに伴いFCSも再計算されます。

</details>

**問4.** HTTPでページのデータを要求する前に、TCPで行われることはどれでしょう？

1. ARPキャッシュの全削除
2. ルーティングテーブルの交換
3. 3ウェイハンドシェイクによるコネクション確立
4. サーバ証明書の発行

<details><summary>答えと解説</summary>

正解: **3**

TCPは通信に先立ち、SYN→SYN/ACK→ACKという3回のやり取り（3ウェイハンドシェイク）でコネクションを確立します（詳細は第14章）。ARPキャッシュは通信のたびに削除するものではなく、ルーティングテーブルの交換はルータ同士が行う処理です。サーバ証明書は認証局が発行するもので、通信開始時に発行されるわけではありません。

</details>
