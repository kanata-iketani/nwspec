# 第4章 OS・ハードウェア・システム構成

コンピュータを動かす OS の仕事と、システム全体の組み立て方（クラサバ・3層構成・仮想化）を学ぶ章です。3層構成はネスペ午後の事例の定番舞台で、仮想化は本編のクラウド・SDN に直結します。

## 1. OS の役割（プロセス・タスク管理・割込み）

### OS はコンピュータの「管理人」

OS（オペレーティングシステム）は、ハードウェアとアプリケーションの間に立つ管理人です。主な仕事は次のとおりです。

- **プロセス管理**：実行中のプログラム（プロセス）に CPU を順番に割り当てる。CPU が1個でも複数のアプリが同時に動いて見えるのは、OS が高速に切り替えているからです（マルチタスク）
- そのほか、メモリ管理・ファイル管理・周辺機器の管理など

### プロセスの3つの状態

| 状態 | 意味 |
|---|---|
| 実行状態 | いま CPU を使っている |
| 実行可能状態 | 準備は完了し、CPU が空くのを待っている |
| 待ち状態 | 入出力の完了など、CPU 以外の何かを待っている |

### 割込み

実行中の処理をいったん中断して、優先すべき処理に切り替える仕組みが**割込み**です。キーボード入力やネットワークからのデータ到着は、割込みによって OS に通知されます。

> 💡 コツ：「入出力待ちになったプロセスからは CPU を取り上げて他に回す」。この切り替えこそが OS の腕の見せどころです。

🟡 プロセスの3状態と割込みの役割を押さえれば、午前Ⅰ対策としては十分です。

### 確認問題

**問1.** 割込みの説明として、適切なものはどれでしょう？

1. プログラムの文法誤りを実行前に検出する仕組み
2. 実行中の処理をいったん中断し、優先すべき処理に切り替える仕組み
3. 電源を切る前にデータを保存する仕組み
4. 複数の CPU に処理を均等に分配する仕組み

<details><summary>答えと解説</summary>

正解: **2**

割込みは、入出力の完了やデータの到着などの出来事を契機に、実行中の処理を中断して必要な処理へ制御を移す仕組みです。文法誤りの検出はコンパイラなどの仕事で、電源断前の保存や複数 CPU への分配は割込みという用語の意味ではありません。

</details>

**問2.** ディスクからの読み込み完了を待っているプロセスは、どの状態にあるでしょう？

1. 実行状態
2. 実行可能状態
3. 終了状態
4. 待ち状態

<details><summary>答えと解説</summary>

正解: **4**

入出力の完了など CPU 以外の何かを待っているのが「待ち状態」です。実行状態は CPU を使用中、実行可能状態は準備が整って CPU の空きだけを待っている状態で、入出力待ちとは区別されます。読み込みが終わると待ち状態から実行可能状態に戻ります。

</details>

**問3.** CPU が1個のコンピュータで複数のアプリケーションが同時に動いているように見えるのはなぜでしょう？

1. OS が CPU 時間を細かく区切り、プロセスを高速に切り替えて実行しているから
2. 各アプリケーションが専用の CPU を内蔵しているから
3. 主記憶が複数の命令を同時に実行しているから
4. 画面表示だけを並べて、実際には1つのアプリしか動いていないから

<details><summary>答えと解説</summary>

正解: **1**

OS のプロセス管理（マルチタスク）により、CPU 時間を細かく区切って各プロセスに順番に割り当てるため、人間には同時に動いて見えます。アプリが CPU を内蔵しているわけではなく、命令を実行するのは CPU であって主記憶ではありません。実際に複数のプロセスが並行して進んでいます。

</details>

**問4.** プロセスの「実行可能状態」の説明として、適切なものはどれでしょう？

1. 入出力の完了を待っている状態
2. いままさに CPU で命令を実行している状態
3. 実行の準備は整っており、CPU が割り当てられるのを待っている状態
4. 異常終了して再起動を待っている状態

<details><summary>答えと解説</summary>

正解: **3**

実行可能状態は「CPU さえもらえればすぐ走れる」状態です。入出力完了を待つのは待ち状態、CPU で実行中なのは実行状態です。異常終了後の扱いはプロセスの3状態（実行・実行可能・待ち）には含まれません。3状態の行き来は午前の定番図なので整理しておきましょう。

</details>

## 2. ファイルシステムと入出力

### ファイルシステム＝保存の住所録

補助記憶の上で「どのファイルがどこにあるか」を管理する仕組みが**ファイルシステム**です。

- **ディレクトリ（フォルダ）**は階層構造で整理されます
- 場所の指定には、根元（ルート）から順に書く**絶対パス**と、いまいる場所（カレントディレクトリ）を起点に書く**相対パス**があります
- 例：/home/user/memo.txt は絶対パス、../memo.txt は相対パス（.. は1つ上のディレクトリ）

### 入出力を速くする工夫

CPU に比べてディスクや周辺機器は桁違いに遅いため、速度差を埋める工夫があります。

| 仕組み | 内容 |
|---|---|
| バッファ | データを一時的にためて、装置間の速度差を吸収する |
| スプーリング | 印刷データなどをいったん補助記憶に書き出し、CPU は次の仕事へ進む |
| DMA | CPU を介さずに、主記憶と装置が直接データをやり取りする方式 |

⚪ この章は細部まで覚える優先度は低めです。「絶対パスと相対パスの違い」「バッファは速度差を吸収する緩衝役」の2点だけ押さえておきましょう。

### 確認問題

**問1.** 絶対パスの説明として、適切なものはどれでしょう？

1. カレントディレクトリを起点としてファイルの場所を示す書き方
2. ファイル名だけでファイルの場所を示す書き方
3. ルートディレクトリを起点として目的のファイルまでの経路をすべて示す書き方
4. ファイルの作成日時でファイルを特定する書き方

<details><summary>答えと解説</summary>

正解: **3**

絶対パスは階層の根元（ルート）からの経路をすべて書く指定方法で、どこから参照しても同じファイルを指します。カレントディレクトリ起点で書くのは相対パスです。ファイル名だけでは同名ファイルを区別できず、作成日時はパスによる場所の指定とは関係ありません。

</details>

**問2.** スプーリングの説明として、適切なものはどれでしょう？

1. 印刷データなどをいったん補助記憶に書き出しておき、低速な装置への出力と CPU の処理を切り離す仕組み
2. ファイルを圧縮してディスクの使用量を減らす仕組み
3. 同じファイルを複数のディスクに複製して故障に備える仕組み
4. ディスクの断片化を解消して読み書きを速くする仕組み

<details><summary>答えと解説</summary>

正解: **1**

スプーリングは、プリンタのような低速装置への出力データを補助記憶に書き出しておき、CPU を待たせずに次の処理へ進ませる仕組みです。圧縮は容量削減、複製は冗長化（ミラーリングなど）、断片化の解消はデフラグの説明であり、いずれもスプーリングではありません。

</details>

**問3.** 入出力におけるバッファの主な目的はどれでしょう？

1. データを暗号化して盗聴を防ぐこと
2. ファイルの誤削除を防ぐこと
3. ディスクの空き容量を増やすこと
4. 処理速度の異なる装置の間で、データを一時的にためて速度差を吸収すること

<details><summary>答えと解説</summary>

正解: **4**

バッファは速度の異なる装置の間に置く一時的なため場で、データをまとめて受け渡すことで速度差を吸収します。本編でもルータなどがパケットを一時的にためるバッファが登場します。暗号化・誤削除防止・空き容量の増加は、いずれもバッファの役割ではありません。

</details>

## 3. システム構成（クラサバ・3層・集中と分散）

### 集中と分散

- **集中処理**：1台の大型コンピュータに仕事を集める。管理は楽だが、その1台が止まると全業務が止まる
- **分散処理**：複数のコンピュータで役割分担する。1台の故障に強いが、管理は複雑になる

### クライアントサーバと3層アーキテクチャ

サービスを**提供する側（サーバ）**と**依頼する側（クライアント）**に分けるのがクライアントサーバ方式です。Web システムでは、仕事を3つの層に分けた**3層アーキテクチャ**が定番です。

| 層 | 役割 | 担当の例 |
|---|---|---|
| プレゼンテーション層 | 画面表示・入力の受付 | ブラウザ・Web サーバ |
| アプリケーション層 | 業務処理（ロジック） | AP サーバ |
| データ層 | データの保存・検索 | DB サーバ |

層を分けると、変更や増強を層ごとに独立して行えるうえ、負荷分散やセキュリティ対策も層単位で設計しやすくなります。

> 💡 コツ：ネスペ午後の事例は「Web サーバ・AP サーバ・DB サーバ」の3層構成が舞台になることが非常に多く、この構成図のイメージが長文読解の土台になります。

🔴 3層それぞれの役割と、層を分けるメリットを自分の言葉で説明できるようにしましょう。

### 確認問題

**問1.** 3層アーキテクチャの Web システムで、業務処理（ロジック）を主に担当する層はどれでしょう？

1. アプリケーション層
2. プレゼンテーション層
3. データ層
4. 物理層

<details><summary>答えと解説</summary>

正解: **1**

業務処理のロジックは AP サーバが担うアプリケーション層の役割です。プレゼンテーション層は画面表示と入力の受付、データ層はデータの保存・検索を担当します。物理層は OSI 参照モデルの用語であり、3層アーキテクチャの層の名前ではありません。

</details>

**問2.** システムを3層アーキテクチャにする主なメリットはどれでしょう？

1. サーバの台数が必ず1台で済む
2. ネットワークを経由しないため通信障害の影響を受けない
3. 変更や増強を層ごとに独立して行いやすい
4. データのバックアップが不要になる

<details><summary>答えと解説</summary>

正解: **3**

層ごとに役割を分けることで、画面の変更・業務ロジックの修正・DB の増強などを互いに影響を抑えて行え、負荷分散やセキュリティ対策も層単位で設計できます。層を分けるとサーバは複数になるのが普通で、層の間は通信でつながるため通信障害と無縁ではなく、バックアップも引き続き必要です。

</details>

**問3.** 集中処理の特徴として、適切なものはどれでしょう？

1. コンピュータが複数あるため1台の故障に強い
2. 管理は1か所で済み容易だが、ホストが停止すると全業務が止まる
3. 各拠点のコンピュータが対等に処理を分担する
4. 障害が起きても他のコンピュータが自動的に処理を引き継ぐ

<details><summary>答えと解説</summary>

正解: **2**

集中処理は1台のホストに仕事を集めるため、管理・セキュリティ対策は1か所で済む半面、ホストの停止が全業務の停止に直結します。複数台で分担する、故障に強い、他が引き継ぐといった性質は分散処理側の特徴です。

</details>

**問4.** クライアントサーバ方式の説明として、適切なものはどれでしょう？

1. すべてのコンピュータが対等な立場で直接やり取りする方式
2. 1台のコンピュータの中ですべての処理を完結させる方式
3. 利用者の端末に一切の処理をさせない方式
4. サービスを提供する側と依頼する側に役割を分けて処理を分担する方式

<details><summary>答えと解説</summary>

正解: **4**

クライアントサーバ方式は、サービスを提供するサーバと依頼するクライアントに役割を分ける構成です。全員が対等にやり取りするのはピアツーピア方式の説明です。1台で完結させる形はスタンドアロンに近く、クライアント側も画面表示などの処理を担うため「一切処理をさせない」も誤りです。

</details>

## 4. 仮想化のきほん（ホスト型・ハイパバイザ型・コンテナ）

### 1台の物理サーバを何台にも見せる

**仮想化**とは、1台の物理マシンの上に、独立して動く複数の「仮想マシン（VM）」を作る技術です。VM を動かす土台のソフトウェアを**ハイパバイザ**と呼びます。方式は大きく3つです。

| 方式 | 構成（下から上へ） | 特徴 |
|---|---|---|
| ホスト型 | ハードウェア → ホスト OS → 仮想化ソフト → VM | 手軽に導入できるが、ホスト OS の分だけオーバヘッドが大きい |
| ハイパバイザ型 | ハードウェア → ハイパバイザ → VM | ホスト OS が不要で効率的。サーバ用途の主流 |
| コンテナ型 | ハードウェア → OS → コンテナエンジン → コンテナ | **ゲスト OS を持たず**カーネルを共有。軽量で起動が速い |

### コンテナは「OS を丸ごと持たない」

VM は1台ごとにゲスト OS を抱えますが、コンテナはホストの OS（カーネル）を共有し、アプリと必要なライブラリだけを隔離して動かします。そのぶん軽く、起動も速いのが利点です。

> 💡 コツ：区別のポイントは2つの質問です。「ホスト OS の上に仮想化ソフトが載っているか（ホスト型）」「ゲスト OS を持つか（VM か、コンテナか）」。

🔴 3方式の構成図の違いは午前でも頻出で、本編のクラウド・SDN（第25章）の前提知識になります。

### 確認問題

**問1.** ハイパバイザ型（ベアメタル型）仮想化の説明として、適切なものはどれでしょう？

1. ホスト OS の上に仮想化ソフトをインストールして VM を動かす
2. ハードウェアの上で直接ハイパバイザが動作し、その上で VM を動かす
3. ゲスト OS を持たず、ホストのカーネルを共有して動かす
4. 物理サーバを増設して処理能力を高める

<details><summary>答えと解説</summary>

正解: **2**

ハイパバイザ型は、ハードウェア上で直接ハイパバイザが動き、ホスト OS が不要なぶん効率的で、サーバ仮想化の主流です。ホスト OS の上に仮想化ソフトを載せるのはホスト型、カーネル共有はコンテナ型の説明です。物理サーバの増設は仮想化ではなくスケールアウトの話です。

</details>

**問2.** コンテナ型仮想化が仮想マシン（VM）方式と比べて軽量で起動が速い主な理由はどれでしょう？

1. ゲスト OS を持たず、ホスト OS のカーネルを共有するから
2. 専用のハードウェアで動作するから
3. アプリケーションを実行しないから
4. すべてのデータを圧縮して保存するから

<details><summary>答えと解説</summary>

正解: **1**

コンテナはゲスト OS を丸ごと抱える代わりに、ホスト OS のカーネルを共有し、アプリと必要なライブラリだけを隔離して動かします。OS の起動が不要なぶん軽量・高速です。専用ハードウェアは不要で、アプリを実行するための仕組みであり、圧縮は軽さの理由ではありません。

</details>

**問3.** ホスト型仮想化の特徴として、適切なものはどれでしょう？

1. ホスト OS が不要で、オーバヘッドが最も小さい
2. VM を一切作らずにアプリケーションを隔離する
3. ハイパバイザがハードウェアを直接制御する
4. 既存の OS に仮想化ソフトを追加するだけで導入できるが、ホスト OS の分のオーバヘッドがある

<details><summary>答えと解説</summary>

正解: **4**

ホスト型は、普段使っている OS の上に仮想化ソフトをインストールして VM を動かす方式で、導入は手軽ですがホスト OS を経由するぶんオーバヘッドが大きくなります。ホスト OS が不要でハードウェアを直接制御するのはハイパバイザ型、VM を作らずに隔離するのはコンテナ型の説明です。

</details>

**問4.** 仮想マシン（VM）とコンテナの違いの説明として、適切なものはどれでしょう？

1. VM は物理サーバ1台につき1つしか作れないが、コンテナは複数作れる
2. コンテナは VM より起動に時間がかかる
3. VM はそれぞれがゲスト OS を持つが、コンテナはゲスト OS を持たない
4. VM と コンテナはどちらもゲスト OS を持ち、違いは名前だけである

<details><summary>答えと解説</summary>

正解: **3**

最大の違いは OS の持ち方です。VM は1台ごとにゲスト OS を抱えるのに対し、コンテナはホストのカーネルを共有してゲスト OS を持ちません。そのためコンテナの方が軽量で起動も速くなります。VM も1台の物理サーバ上に複数作れるので、1つしか作れないという説明は誤りです。

</details>
