# 第21章 VPN（IPsec・TLS-VPN・広域イーサ）

離れた拠点や自宅から、共用のネットワーク越しに安全に社内へつなぐ仕組みが VPN です。IPsec と TLS-VPN の通信の流れを言葉で追い、広域イーサネットなど閉域網サービスとの使い分けまで整理する章です。

## 1. VPN とは・拠点間VPNとリモートアクセスVPN

**VPN（Virtual Private Network）**は、インターネットなどの共用ネットワークの上に、暗号化と認証で守られた「仮想的な専用線」を作る技術です。VPN を支えるのは次の3つの機能です。

| 機能 | 役割 |
|---|---|
| トンネリング | 元のパケットを別のパケットで包んで（カプセル化して）運ぶ |
| 暗号化 | 途中で盗聴されても中身を読めなくする |
| 認証 | 正しい相手か・改ざんされていないかを確認する |

### 2つの利用形態

**拠点間VPN（サイト間VPN）**は、本社と支社のように、拠点のルータや FW **同士**が常時トンネルを張る形態です。トンネルの出入口はゲートウェイ機器なので、社内の PC は VPN を意識する必要がなく、普段どおり宛先に送るだけでゲートウェイが包んで相手拠点まで届けてくれます。

**リモートアクセスVPN**は、外出先や自宅の PC・スマートフォンが、社内に置いた VPN 装置へ個別にトンネルを張る形態です。端末側に VPN クライアント（ソフトウェア）が必要で、接続のたびに利用者本人の認証が行われます。

> 💡 コツ：「誰がトンネルの口になるか」で区別します。拠点間は「機器どうし」、リモートアクセスは「端末と機器」です。

🔴 午後問題では「在宅勤務のためにリモートアクセスVPNを導入する」という設定が頻出です。2つの形態の違いを自分の言葉で説明できるようにしましょう。

### 確認問題

**問1.** VPN における「トンネリング」の説明として、適切なものはどれでしょう？

1. 通信経路上のルータをすべて専用線に置き換えること
2. パケットの宛先 IP アドレスを書き換えて転送すること
3. 元のパケットを別のパケットで包み（カプセル化し）、共用ネットワーク上を運ぶこと
4. パケットを圧縮して帯域を節約すること

<details><summary>答えと解説</summary>

正解: **3**

トンネリングは、元のパケットを新しいヘッダで包んで（カプセル化して）運ぶ技術で、共用網の上に仮想的な専用経路を作ります。専用線への置き換えは物理的な回線契約の話で VPN とは逆の発想です。宛先の書き換えは NAT、圧縮は帯域節約の技術であり、トンネリングの説明ではありません。

</details>

**問2.** 拠点間VPNの特徴として、適切なものはどれでしょう？

1. 拠点のゲートウェイ機器同士がトンネルを張るため、社内の各 PC に VPN クライアントを入れる必要がない
2. 利用者の PC が1台ずつ個別にトンネルを張る
3. 暗号化は行わず、認証のみを行う
4. 通信のたびに利用者本人のパスワード入力が必要になる

<details><summary>答えと解説</summary>

正解: **1**

拠点間VPNではルータや FW などのゲートウェイ同士が常時トンネルを維持するため、配下の PC は VPN を意識せずに通信できます。端末が個別にトンネルを張り利用者認証を行うのはリモートアクセスVPNの特徴です。暗号化は VPN の中心的な機能であり、省略するという説明も誤りです。

</details>

**問3.** リモートアクセスVPNの説明として、適切なものはどれでしょう？

1. 本社と支社のルータ同士が常時トンネルを維持する形態である
2. 物理的な専用線を新たに敷設する形態である
3. 社内 LAN の中だけで暗号化通信を行う形態である
4. 外出先や自宅の端末が、VPN クライアントを使って社内の VPN 装置へトンネルを張る形態である

<details><summary>答えと解説</summary>

正解: **4**

リモートアクセスVPNは、個々の端末が社内の VPN 装置（VPN ゲートウェイ）に接続して社内ネットワークを利用する形態で、端末側のクライアントソフトと利用者認証が特徴です。ルータ同士の常時トンネルは拠点間VPN、専用線の敷設は VPN ではなく物理回線の話です。社内 LAN 内部の暗号化という説明もリモートアクセスの定義とは異なります。

</details>

**問4.** 本社に設置した1台の VPN ルータに、全支社との拠点間VPNと全社員のリモートアクセスVPNを集約した構成があります。この構成の弱点として、最も適切なものはどれでしょう？

1. 支社の数だけトンネルの暗号鍵を用意できない
2. その VPN ルータが故障すると、全支社との通信と在宅勤務者の接続がすべて停止する単一障害点になっている
3. リモートアクセスと拠点間 VPN は同じ機器に共存できない
4. トンネルを集約すると暗号化が無効になる

<details><summary>答えと解説</summary>

正解: **2**

すべてのトンネルが1台に集約されているため、その機器の故障が全社の通信断に直結します。これが単一障害点（SPOF）で、午後問題では機器の冗長化が定番の対策です。トンネルごとに鍵を持つことは通常の動作で問題なく、1台の機器で両形態の VPN を終端することも一般的です。集約によって暗号化が無効になることもありません。

</details>

## 2. IPsec（AH/ESP・トンネル/トランスポート・IKE）

**IPsec** は、IP パケットを暗号化・認証して運ぶためのプロトコル群で、拠点間VPNの定番です。

### 2つのプロトコル：AH と ESP

| プロトコル | 暗号化 | 認証（改ざん検知） |
|---|---|---|
| AH | ✕ しない | ○ する |
| ESP | ○ する | ○ する |

AH は暗号化をしないうえ、IP ヘッダまで認証対象に含めるため、途中で NAT がアドレスを書き換えると検証に失敗します。実務ではほぼ **ESP** が使われます。

### 2つのモード

**トンネルモード**は、元の IP ヘッダごとパケット全体を暗号化し、新しい IP ヘッダを付けて運びます。拠点のゲートウェイ同士で使う拠点間VPN向けです。**トランスポートモード**は、IP ヘッダはそのままにペイロード部分だけを保護します。ホスト同士の通信向けです。

### IKE：トンネルを張る前の交渉

暗号化には「どの方式で・どの鍵で」という合意（**SA**：Security Association）が必要です。この交渉と鍵交換を自動で行うのが **IKE** で、UDP ポート 500 を使います。NAT を越える場合は **NAT トラバーサル**により ESP パケットを UDP ポート 4500 で包んで通します。

> 💡 コツ：流れは「IKE で鍵と方式に合意（SA 確立）→ ESP で実データを暗号化して転送」の2段階です。

🔴 「ESP＋トンネルモード＋IKE」の組み合わせが拠点間 IPsec-VPN の基本形です。試験でも実務でもこの形を軸に考えましょう。

### 確認問題

**問1.** IPsec の ESP が提供し、AH が提供しない機能はどれでしょう？

1. 改ざんの検知
2. ペイロードの暗号化
3. パケットのカプセル化
4. 通信相手の認証

<details><summary>答えと解説</summary>

正解: **2**

AH は認証（改ざん検知・相手の確認）のみで暗号化を行わず、ESP は暗号化と認証の両方を提供します。したがって ESP だけが持つのは暗号化です。改ざん検知と相手の認証は両者が提供し、カプセル化はモード（トンネルモード）の働きであってプロトコルの差ではありません。

</details>

**問2.** IPsec のトンネルモードの説明として、適切なものはどれでしょう？

1. IP ヘッダはそのままにして、ペイロード部分だけを暗号化する
2. 暗号化を行わず、経路情報だけを隠す
3. TCP のポート番号だけを暗号化する
4. 元の IP ヘッダを含むパケット全体を暗号化し、新しい IP ヘッダを付けて転送する

<details><summary>答えと解説</summary>

正解: **4**

トンネルモードは元のパケット全体（IP ヘッダ含む）を保護し、ゲートウェイのアドレスを持つ新しい IP ヘッダを付けて運ぶため、社内のアドレスや通信相手を外から隠せます。ペイロードだけを保護するのはトランスポートモードです。暗号化しない・ポート番号だけ暗号化するという動作は IPsec のモードの説明として誤りです。

</details>

**問3.** IKE の役割として、適切なものはどれでしょう？

1. 暗号方式や鍵を自動で交渉し、SA（Security Association）を確立する
2. 暗号化されたデータそのものを転送する
3. VPN 装置のルーティングテーブルを交換する
4. 利用者のパスワードをサーバに保存する

<details><summary>答えと解説</summary>

正解: **1**

IKE は、実データを暗号化して送る前の「交渉役」で、使う暗号方式や鍵を合意して SA を確立します（UDP 500 番を使用）。実データの転送は ESP の役割です。ルーティング情報の交換は OSPF や BGP などルーティングプロトコルの仕事で、パスワードの保存は認証サーバの機能であり IKE とは関係ありません。

</details>

**問4.** NAT を行うルータを経由する経路で AH を使うと通信が成立しない主な理由はどれでしょう？

1. AH は暗号化が強力すぎて NAT 機器が処理できないから
2. NAT 機器は UDP パケットを通さないから
3. AH は IP ヘッダも認証の対象とするため、NAT がアドレスを書き換えると受信側の検証が失敗するから
4. AH は IPv6 専用のプロトコルだから

<details><summary>答えと解説</summary>

正解: **3**

AH は IP ヘッダを含めて改ざんを検知するため、NAT によるアドレス書き換えが「改ざん」と判定されてしまいます。NAT 環境では暗号化も必要なことが多く、実務では ESP と NAT トラバーサル（UDP 4500 でのカプセル化）を使います。AH はそもそも暗号化を行わないので1つ目は誤り、NAT 機器は UDP を普通に通しますし、AH は IPv4 でも使えます。

</details>

**問5.** 本社と支社のルータ間で IPsec による拠点間VPNを構築する場合の、基本となる構成はどれでしょう？

1. AH＋トランスポートモード
2. AH＋トンネルモード
3. ESP＋トンネルモード
4. ESP＋トランスポートモード

<details><summary>答えと解説</summary>

正解: **3**

拠点間VPNでは、暗号化が必要なので ESP を、ゲートウェイ同士で社内アドレスのパケットを包んで運ぶためにトンネルモードを使うのが基本形です。AH は暗号化をしないため盗聴対策になりません。トランスポートモードは IP ヘッダを書き換えないホスト間通信向けで、拠点のゲートウェイが代理でパケットを運ぶ用途には適しません。

</details>

## 3. TLS-VPN（クライアント証明書・リバースプロキシ型との違い）

**TLS-VPN（SSL-VPN）**は、HTTPS と同じ **TLS** で通信を保護するリモートアクセスVPNです。TCP ポート 443 を使うため、ホテルや外出先の FW・プロキシを**通過しやすい**のが大きな利点です。

### 3つの方式

| 方式 | 端末に必要なもの | 使えるアプリ |
|---|---|---|
| リバースプロキシ型 | ブラウザのみ | Web アプリだけ |
| ポートフォワーディング型 | 小さなモジュール | 事前に決めたアプリ（ポート） |
| L2 フォワーディング型 | 専用クライアント | ほぼすべてのアプリ |

**リバースプロキシ型**は、VPN 装置が社内 Web サーバの「代理の窓口」になる方式です。利用者はブラウザで VPN 装置にアクセスするだけなので導入が最も手軽ですが、使えるのは Web アプリに限られます。ファイル共有や社内システムの専用アプリまで使いたい場合は **L2 フォワーディング型**を選びます。

### クライアント証明書で「端末」を確認する

ID とパスワードだけでは、漏えいすると誰でも私物端末から接続できてしまいます。そこで会社支給の端末にだけ**クライアント証明書**を入れておき、TLS のハンドシェイクで端末側も証明書を提示させます。これにより「正しい利用者が、許可された端末から」接続していることを確認できます。

> 💡 コツ：サーバ証明書は「サーバの本人確認」、クライアント証明書は「端末（利用者）の本人確認」。向きが逆なだけで仕組みは同じです。

🔴 「リバースプロキシ型は Web アプリのみ・ブラウザだけで使える」という対応関係は午前Ⅱ・午後の両方で問われます。

### 確認問題

**問1.** TLS-VPN のリバースプロキシ型の特徴として、適切なものはどれでしょう？

1. 端末はブラウザだけで利用でき、対象は Web アプリケーションに限られる
2. 専用クライアントを導入し、あらゆるアプリケーションを利用できる
3. 物理的な専用線で社内に接続する
4. 暗号化を行わない代わりに高速に通信できる

<details><summary>答えと解説</summary>

正解: **1**

リバースプロキシ型は VPN 装置が社内 Web サーバの代理窓口となる方式で、ブラウザさえあれば使える手軽さと引き換えに、対象が Web アプリに限定されます。専用クライアントで全アプリを使えるのは L2 フォワーディング型です。専用線は VPN ではなく物理回線で、TLS-VPN は TLS による暗号化が前提なので暗号化しないという説明も誤りです。

</details>

**問2.** リモートアクセスで Web 以外の社内システム（ファイル共有や専用クライアントのアプリ）も使いたい場合、TLS-VPN で選ぶべき方式はどれでしょう？

1. リバースプロキシ型
2. DNS ラウンドロビン
3. L2 フォワーディング型
4. URL フィルタリング型

<details><summary>答えと解説</summary>

正解: **3**

L2 フォワーディング型は専用クライアントで端末の通信を丸ごとトンネルに乗せるため、Web 以外のアプリも利用できます。リバースプロキシ型はブラウザで使える Web アプリに限定されます。DNS ラウンドロビンは負荷分散の手法、URL フィルタリングは Web アクセス制限の機能で、どちらも VPN の方式ではありません。

</details>

**問3.** TLS-VPN でクライアント証明書による認証を併用する主な目的はどれでしょう？

1. VPN 装置の処理負荷を減らすため
2. パスワードを平文で送信できるようにするため
3. 通信速度を向上させるため
4. ID・パスワードが漏えいしても、証明書を入れた許可端末以外からは接続できないようにするため

<details><summary>答えと解説</summary>

正解: **4**

クライアント証明書は「所持」の要素による端末の認証で、会社支給端末にだけ証明書を配布しておけば、ID・パスワードが漏れても私物端末や攻撃者の端末からの接続を防げます。認証を追加しても負荷軽減や速度向上にはなりません。また TLS では通信自体が暗号化されるため「平文で送信できるようにする」という目的も成り立ちません。

</details>

**問4.** IPsec による リモートアクセスVPN と比べたときの、TLS-VPN の利点として適切なものはどれでしょう？

1. 暗号化の強度が常に IPsec より高い
2. HTTPS と同じ TCP 443 番ポートを使うため、外出先の FW やプロキシを通過しやすい
3. 認証を一切行わずに接続できるため手間がない
4. トンネリングを行わないため遅延が発生しない

<details><summary>答えと解説</summary>

正解: **2**

多くのネットワークでは HTTPS（TCP 443）が許可されているため、同じポートを使う TLS-VPN は FW やプロキシのある環境からでも接続しやすいのが実務上の大きな利点です。暗号強度は設定する暗号スイート次第で、どちらが常に強いとは言えません。認証を行わないことは利点ではなくセキュリティ上の欠陥であり、TLS-VPN もトンネリング（カプセル化）を行います。

</details>

## 4. 広域イーサネットと IP-VPN・インターネットVPN の比較

拠点間を結ぶ手段は、インターネットVPNだけではありません。通信事業者が契約者専用に提供する**閉域網**のサービスも試験頻出です。

### 3つのサービスの比較

| 項目 | 広域イーサネット | IP-VPN | インターネットVPN |
|---|---|---|---|
| 使う網 | 事業者の閉域網 | 事業者の閉域網 | インターネット |
| 提供レイヤ | レイヤ2 | レイヤ3 | （自前で構築） |
| 品質・帯域保証 | 期待できる | 期待できる | なし（ベストエフォート） |
| コスト | 高い | 中 | 低い |

**広域イーサネット**は、離れた拠点同士を1つの大きな LAN（レイヤ2）としてつなぐサービスです。レイヤ2なので、拠点間で OSPF などのルーティングプロトコルを**利用者が自由に**流せます。

**IP-VPN** は、事業者の閉域網が **MPLS** という技術で契約者ごとに通信を分離し、レイヤ3（IP）で転送するサービスです。網がルーティングに関与するため、利用者の経路設計の自由度は広域イーサより下がります。

**インターネットVPN** は、安価な一方で帯域や遅延の保証がなく、インターネットを通る以上 IPsec などの**暗号化が必須**です。

> 💡 コツ：閉域網の2つは「レイヤ」で区別します。L2 なら広域イーサネット、L3（MPLS）なら IP-VPN です。

🟡 午後問題では「コスト・品質・経路制御の自由度」を根拠にサービスを選ばせる設問が出ます。表の比較軸ごと覚えましょう。

### 確認問題

**問1.** 広域イーサネットの特徴として、適切なものはどれでしょう？

1. インターネット上に IPsec でトンネルを張るサービスである
2. 事業者網がレイヤ3で転送するため、利用者はルーティングプロトコルを選べない
3. 拠点間をレイヤ2で接続するため、利用者が OSPF などのルーティングプロトコルを自由に流せる
4. 通信品質の保証が一切ないベストエフォートのサービスである

<details><summary>答えと解説</summary>

正解: **3**

広域イーサネットは閉域網による レイヤ2 接続サービスで、拠点同士が同じ LAN のようにつながるため、その上で使うルーティングプロトコルを利用者側で自由に設計できます。インターネット上の IPsec トンネルはインターネットVPN、網が L3 で転送するのは IP-VPN の説明です。閉域網サービスなので品質保証が期待できる点もベストエフォートという記述と異なります。

</details>

**問2.** IP-VPN の説明として、適切なものはどれでしょう？

1. 通信事業者の閉域網で、MPLS などにより契約者ごとに分離されたレイヤ3の接続を提供するサービスである
2. 各家庭のブロードバンド回線をそのまま束ねたサービスである
3. 無線 LAN だけで拠点間を接続するサービスである
4. レイヤ2で接続するため拠点間が同一セグメントになるサービスである

<details><summary>答えと解説</summary>

正解: **1**

**問3.** インターネットVPNの弱点として、最も適切なものはどれでしょう？

1. 導入コストが3つのサービスの中で最も高い
2. 暗号化が技術的に不可能である
3. 拠点を2つまでしか接続できない
4. インターネットを経由するため、帯域や遅延などの通信品質が保証されない

<details><summary>答えと解説</summary>

正解: **4**

インターネットはベストエフォートの共用網なので、混雑時の帯域や遅延は保証されません。これがインターネットVPN最大の弱点で、品質が必要な用途では閉域網サービスを選びます。コストはむしろ最も安いのが利点です。IPsec や TLS で暗号化するのが前提なので暗号化が不可能という記述は誤りで、接続拠点数に2つまでという制限もありません。

</details>

**問4.** 「拠点間の通信はすべて社内システムの Web 利用で、コストを最優先したい。多少の遅延は許容するが、盗聴対策は必須」という要件に最も合うサービスはどれでしょう？

1. 広域イーサネット
2. IPsec を使ったインターネットVPN
3. IP-VPN
4. 暗号化なしのインターネット直接通信

<details><summary>答えと解説</summary>

正解: **2**

品質保証が不要でコスト最優先なら、安価なインターネットVPNが適します。盗聴対策は IPsec の暗号化で満たせます。広域イーサネットや IP-VPN は品質が必要な場合の選択肢で、コスト重視の要件には過剰です。暗号化なしの直接通信は「盗聴対策必須」の要件を満たしません。

</details>
