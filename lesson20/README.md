# 第20章 ネットワークセキュリティ（FW・IDS/IPS・DMZ）

ネットワークを守る装置と設計の章です。ファイアウォール・DMZ・IDS/IPS・WAF・UTM の役割の違いを整理し、「どの攻撃をどの装置で防ぐか」を判断できるようにします。

## 1. ファイアウォール（パケットフィルタとステートフルインスペクション)

**ファイアウォール（FW）**は、ネットワークの出入口で通信を**ルール（ポリシー）に従って通す・止める**装置です。建物の受付・検問に例えられます。

### パケットフィルタリング

パケットの**ヘッダ情報**——送信元/宛先 IP アドレス、送信元/宛先ポート番号、プロトコル——を見てルールと照合する、最も基本的な方式です。

例:「社内 → インターネットの宛先ポート 443(HTTPS) は許可、それ以外は拒否」

弱点は、**戻りの通信**のために「外部 → 内部」のルールも開けておく必要があり、静的なルールだけでは管理が煩雑で穴ができやすいことです。

### ステートフルインスペクション

現在の FW の主流方式です。**通信のセッション（状態）を記録**し、「内部から始めた通信の**戻りパケットだけ**を自動で許可」します。

- 内部 → 外部の通信開始を**状態テーブル**に記録
- その応答として整合するパケットだけ通す
- 外部から**いきなり**届くパケットは拒否

これにより、戻り用のルールを静的に開けておく必要がなくなり、安全性と管理性が大きく向上します。

### 設計の大原則: デフォルト拒否

ルールは「**原則すべて拒否し、必要な通信だけを明示的に許可する**」（デフォルトデナイ・ホワイトリスト方式）が鉄則です。

> 💡 コツ: FW が見るのは基本的に「宛先・送信元・ポート」まで。**通信の中身（アプリの内容）までは見ない**——この限界が次章以降の WAF や IPS につながります。

🔴 ステートフル=「戻りを自動許可」とデフォルト拒否の原則は最重要です。

### 確認問題

**問1.** ステートフルインスペクション方式のファイアウォールの特徴として、適切なものはどれでしょう？

1. 通信の内容を解析して SQL インジェクションを検知する
2. セッションの状態を記録し、内部から開始した通信の戻りパケットだけを動的に許可する
3. すべてのパケットを暗号化して転送する
4. ウイルスに感染したファイルを駆除する

<details><summary>答えと解説</summary>

正解: **2**

ステートフルインスペクションは通信の状態（セッション）を状態テーブルで管理し、内部発の通信に対応する戻りだけを自動許可するため、外部からの一方的なパケットを遮断できます。SQL インジェクションのようなアプリケーション層の攻撃検知は WAF の役割です。暗号化は VPN や TLS、ウイルス駆除はマルウェア対策ソフトの機能であり、FW の基本機能ではありません。

</details>

**問2.** パケットフィルタリング型ファイアウォールが通過可否の判断に使う情報として、適切なものはどれでしょう？

1. Web ページに含まれる文字列
2. メール本文の添付ファイルの種類
3. 送信元/宛先の IP アドレスとポート番号などのヘッダ情報
4. 利用者のパスワードの強度

<details><summary>答えと解説</summary>

正解: **3**

パケットフィルタリングは IP ヘッダや TCP/UDP ヘッダの情報（アドレス・ポート・プロトコル）をルールと照合して判断します。Web ページの文字列やメールの添付ファイルといった通信の中身（ペイロード）は見ないため、アプリケーション層の攻撃は防げません。パスワードの強度は認証側の問題で FW の判断材料ではありません。

</details>

**問3.** ファイアウォールのルール設計の原則として、適切なものはどれでしょう？

1. 原則すべて許可し、問題が起きた通信だけを個別に拒否する
2. すべての通信を無条件に許可し、ログだけを取得する
3. ルールは設置時に1回だけ設定し、以後は変更しない
4. 原則すべて拒否し、業務に必要な通信だけを明示的に許可する

<details><summary>答えと解説</summary>

正解: **4**

デフォルト拒否（ホワイトリスト方式）が鉄則です。必要な通信だけを許可すれば、想定外の通信は自動的に遮断されます。「原則許可・個別拒否」は未知の攻撃が素通りします。ログだけでは防御になりません。業務やシステムは変化するため、ルールの定期的な見直し（棚卸し）も運用上重要です。

</details>

**問4.** 一般的なファイアウォール（パケットフィルタ型・ステートフル型）では防ぐことが難しい攻撃はどれでしょう？

1. 許可された 443 番ポートを通る、Web アプリケーションへの SQL インジェクション
2. 外部から内部サーバの閉じているポートへの接続試行
3. 許可していないポート番号への外部からのアクセス
4. 外部からいきなり届く、セッションと無関係なパケット

<details><summary>答えと解説</summary>

正解: **1**

FW はヘッダ情報で判断するため、正規に許可された HTTPS(443) の中を通るアプリケーション層の攻撃（SQL インジェクションなど）は中身を見ないので止められません。これを守るのが WAF です。閉じたポートや未許可ポートへのアクセス、セッションと整合しない外部からのパケットは、FW が得意とする遮断対象です。

</details>

## 2. DMZ と境界設計（公開サーバの置き方）

Web サーバや外部向け DNS のように**インターネットに公開するサーバ**は、どこに置くべきでしょうか。社内 LAN に置くと、そのサーバが乗っ取られた瞬間に**社内全体が危険**にさらされます。

### DMZ（非武装地帯）

そこで、インターネットと社内 LAN の**中間に専用のセグメント**を作り、公開サーバをそこに置きます。これが **DMZ** です。マンションの「エントランスの宅配ボックス」のイメージで、外部の人を部屋（社内LAN）まで入れずに用件を済ませます。

### 3つのゾーン間の通信ルール（基本形）

| 通信の向き | 扱い |
|---|---|
| インターネット → DMZ | 公開サービスのポートのみ許可（例: 443） |
| インターネット → 社内LAN | **全面拒否** |
| 社内LAN → DMZ | 管理・利用に必要な通信のみ許可 |
| DMZ → 社内LAN | **原則拒否**（必要最小限のみ） |

ポイントは「**DMZ → 社内LAN を原則止める**」ことです。これにより、万一 DMZ の公開サーバが乗っ取られても、攻撃者はそこから社内に入りにくくなります（**被害の局所化**）。

### DMZ に置く代表的なサーバ

公開 Web サーバ、外部向け（権威）DNS サーバ、メール中継サーバ、リバースプロキシなど。逆に、顧客データベースや社内ファイルサーバのような**重要データを持つサーバは社内 LAN 側**に置き、DMZ のサーバから必要最小限の通信だけを許します。

🔴 「公開サーバは DMZ」「DMZ→内部は原則拒否＝被害の局所化」は午後の設計問題の必須知識です。

### 確認問題

**問1.** 公開 Web サーバを社内 LAN ではなく DMZ に設置する主な理由はどれでしょう？

1. Web サーバの応答速度が向上するから
2. Web サーバが乗っ取られても、社内 LAN への侵入を直接許さないようにするため
3. IP アドレスを節約できるから
4. DNS の名前解決が不要になるから

<details><summary>答えと解説</summary>

正解: **2**

公開サーバは外部から攻撃を受けやすいため、乗っ取られた場合に備えて社内 LAN と分離した DMZ に置き、DMZ から内部への通信を原則拒否することで被害を局所化します。設置場所を変えても応答速度や IP アドレスの消費が本質的に改善するわけではなく、名前解決が不要になることもありません。

</details>

**問2.** DMZ を含む境界設計で「全面的に拒否すべき」通信の向きはどれでしょう？

1. 社内 LAN からインターネットへの Web アクセス
2. インターネットから DMZ の公開 Web サーバの 443 番ポートへのアクセス
3. インターネットから社内 LAN への直接アクセス
4. 社内 LAN から DMZ のサーバへの管理アクセス

<details><summary>答えと解説</summary>

正解: **3**

インターネットから社内 LAN への直接アクセスは全面拒否が原則で、外部に見せる必要があるものはすべて DMZ 経由にします。インターネットから DMZ への公開ポート、社内から DMZ への管理通信、社内から外部への Web アクセスは、必要なものを絞って許可する通信です。

</details>

**問3.** DMZ に配置するサーバとして最も適切なものはどれでしょう？

1. 社内の人事情報を保存するファイルサーバ
2. 経理部門専用の会計システム
3. 顧客情報を保存するデータベースサーバ
4. インターネットに公開する Web サーバや外部向け DNS サーバ

<details><summary>答えと解説</summary>

正解: **4**

DMZ には外部からアクセスされる前提の公開サーバ（Web、外部向け DNS、メール中継など）を置きます。顧客データベースや人事ファイルサーバ、会計システムのような重要データを持つサーバは、外部から直接届かない社内 LAN 側に置き、DMZ からの通信も必要最小限に絞るのが原則です。

</details>

**問4.** DMZ の Web サーバが社内 LAN のデータベースサーバを利用する構成の場合、ファイアウォールの設定として適切なものはどれでしょう？

1. DMZ から社内 LAN へは、その Web サーバから DB サーバの特定ポートへの通信だけを許可する
2. DMZ から社内 LAN へのすべての通信を許可する
3. インターネットから DB サーバへの直接アクセスを許可する
4. 社内 LAN から DMZ への通信をすべて拒否する

<details><summary>答えと解説</summary>

正解: **1**

DMZ から内部への通信は原則拒否とした上で、業務に必要な「特定の送信元から特定の宛先・ポートへ」だけを例外的に許可するのが最小権限の設計です。すべて許可すると DMZ 侵害時に内部へ広がります。DB サーバへの外部からの直接アクセスは論外で、社内から DMZ への管理通信まで全部拒否すると運用ができなくなります。

</details>

## 3. IDS/IPS・WAF・UTM の違い

ファイアウォールは「アドレスとポート」までしか見ません。その先を守る装置たちを、**何を見て・何をするか**で整理しましょう。

### IDS と IPS: 不正を「検知」か「防御」か

- **IDS（侵入検知システム）**: 通信を監視して攻撃の兆候を**検知し、管理者に通知**する。通信の**コピー**（ミラーポート経由など）を見るため、通信自体は止めない
- **IPS（侵入防止システム）**: 通信経路の**インライン**（通り道上）に設置し、攻撃と判断した通信を**その場で遮断**する

検知方法には、既知の攻撃パターンと照合する**シグネチャ型**と、普段と違う振る舞いを捉える**アノマリ型**があります。

> 💡 コツ: D は Detection（検知）、P は Prevention（防止）。「IDS=警報ベル、IPS=自動ドアロック」のイメージです。

### WAF: Web アプリ専門のガードマン

**WAF（Web Application Firewall）**は、HTTP/HTTPS の**中身（リクエストの内容）**を検査し、**SQL インジェクションやクロスサイトスクリプティング（XSS）**のような Web アプリケーションを狙う攻撃を防ぎます。FW では見えない「正規のポートを通る悪意あるリクエスト」を守る最後の砦です。

### UTM: 全部入りの1台

**UTM（統合脅威管理）**は、FW・IPS・アンチウイルス・URL フィルタリングなどを**1台に統合**した製品です。管理がまとまる反面、処理が集中するため性能面の考慮が必要で、中小規模の拠点で特に使われます。

🔴 「どの攻撃をどの装置で防ぐか」——SQL インジェクションなら WAF、と即答できるようにしましょう。

### 確認問題

**問1.** IDS と IPS の違いとして、適切なものはどれでしょう？

1. IDS は無線専用、IPS は有線専用の装置である
2. IDS は検知と通知までを行い、IPS はインラインに設置して攻撃通信を遮断できる
3. IDS は暗号化を行い、IPS は復号を行う
4. IDS は社外に設置し、IPS は必ず社内 LAN に設置する

<details><summary>答えと解説</summary>

正解: **2**

IDS(Detection) は通信のコピーを監視して検知・通知までを行い、IPS(Prevention) は通信経路上（インライン）に置かれ攻撃をリアルタイムに遮断します。この「検知まで」か「遮断まで」かが本質的な違いです。有線・無線や設置場所の社内外で区別する装置ではなく、暗号化・復号の機能分担も誤りです。

</details>

**問2.** SQL インジェクション攻撃からの防御を主目的とする装置はどれでしょう？

1. パケットフィルタリング型ファイアウォール
2. DHCP サーバ
3. L2 スイッチ
4. WAF

<details><summary>答えと解説</summary>

正解: **4**

SQL インジェクションは正規に許可された HTTP/HTTPS リクエストの中身に悪意ある SQL を仕込む攻撃のため、HTTP の内容を検査する WAF が防御の主役です。パケットフィルタ型 FW はヘッダしか見ないため素通しします。L2 スイッチはフレーム転送、DHCP サーバは IP アドレス配布の装置で、攻撃防御の機能はありません。

</details>

**問3.** UTM（統合脅威管理）の説明として、適切なものはどれでしょう？

1. ファイアウォールや IPS、アンチウイルスなど複数のセキュリティ機能を1台に統合した製品
2. Web アプリケーションの開発専用のフレームワーク
3. 無線LAN の電波を測定する調査ツール
4. 証明書を発行する認証局の運用規程

<details><summary>答えと解説</summary>

正解: **1**

UTM は FW・IPS・アンチウイルス・URL フィルタリングなどを1台に統合し、管理を一元化できる製品で、中小規模拠点に向きます。一方で処理が1台に集中するため性能設計への注意が必要です。開発フレームワークや電波調査ツール、認証局の規程はいずれもセキュリティ装置としての UTM とは別物です。

</details>

**問4.** 「攻撃を検知したら管理者に通知するだけでなく、その通信自体を自動的に遮断したい。ただし Web アプリ専用ではなく、ネットワーク全体の攻撃に対応したい」という要件に合う装置はどれでしょう？

1. ミラーポートに接続した IDS
2. IPS
3. WAF
4. フォワードプロキシ

<details><summary>答えと解説</summary>

正解: **2**

インラインで通信を遮断でき、ネットワーク層からアプリケーション層まで幅広い攻撃シグネチャに対応するのは IPS です。ミラーポートの IDS はコピーを見るだけなので遮断できません。WAF は Web アプリ宛の HTTP/HTTPS に特化しており要件の「Web 専用ではなく」に合いません。フォワードプロキシは社内から外部へのアクセス管理が主目的です。

</details>

**問5.** シグネチャ型の検知方式の特徴として、適切なものはどれでしょう？

1. 通信量の統計だけで判断するため、パターン定義が不要である
2. 正常時の振る舞いを学習し、そこからの逸脱を検知する
3. 暗号化された通信を復号せずに内容を解析できる
4. 既知の攻撃パターンと照合して検知するため、未知の攻撃の検知は苦手である

<details><summary>答えと解説</summary>

正解: **4**

シグネチャ型は既知の攻撃パターン（シグネチャ）との照合で検知するため精度が高い一方、パターンが存在しない未知の攻撃は見逃しやすいのが弱点です。正常時からの逸脱で検知するのはアノマリ型です。パターン定義はシグネチャ型にこそ必要であり、暗号化通信の中身は復号しなければどの方式でも解析できません。

</details>

## 4. 検疫・マルウェア対策・ログの考え方

境界の装置だけでは、**持ち込まれた端末**や**既に侵入された後**には対応できません。内側の守りと「記録」の話です。

### 検疫ネットワーク

出張から戻った PC や私物端末をいきなり社内 LAN につなぐと、パッチ未適用やマルウェア感染が持ち込まれる恐れがあります。**検疫ネットワーク**は、接続してきた端末をまず**隔離用セグメント**に収容し、**セキュリティ状態を検査**（パッチ適用状況・ウイルス対策ソフトの定義ファイルの更新状況など）して、**合格した端末だけ**を業務ネットワークへ通す仕組みです。空港の検疫所と同じ発想です。

### マルウェア対策の基本

- **パターンマッチング**: 既知のマルウェアの特徴（定義ファイル）と照合する。**定義ファイルの更新が生命線**
- **振る舞い検知**: 実行時の不審な挙動で判定する。未知のマルウェアにも対応しやすい
- **EDR**: 端末の操作ログを常時記録し、**侵入された後**の検知・調査・対応を支援する仕組み。「感染を防ぐ」から「感染を前提に素早く気づく」への発想の転換

### ログの考え方

インシデント対応は**ログが頼り**です。押さえるべき原則は3つあります。

1. **時刻同期（NTP）**: 機器ごとに時計がずれていると、複数のログを突き合わせて攻撃の流れを追えない
2. **保全**: 攻撃者はログを消そうとする。別サーバへの転送・改ざん防止が重要
3. **相関分析**: FW・サーバ・端末のログを集約して横断的に分析する基盤が **SIEM**

🟡 「検疫=つなぐ前に検査」「ログは NTP で時刻同期」が頻出ポイントです。

### 確認問題

**問1.** 検疫ネットワークの仕組みとして、適切なものはどれでしょう？

1. 社外から届くメールの添付ファイルをすべて削除する
2. 接続してきた端末をまず隔離セグメントに収容し、セキュリティ状態の検査に合格した端末だけを業務ネットワークに接続させる
3. Web サーバへのアクセスを国別に制限する
4. 通信をすべて暗号化して盗聴を防ぐ

<details><summary>答えと解説</summary>

正解: **2**

検疫ネットワークは、端末を業務 LAN につなぐ前に隔離領域で検査し、パッチや定義ファイルが基準を満たした端末だけを通すことで、感染端末や脆弱な端末の持ち込みを防ぎます。添付ファイルの削除はメールフィルタ、国別制限はアクセス制御、暗号化は盗聴対策であり、端末の持ち込み検査という検疫の目的とは異なります。

</details>

**問2.** 複数の機器のログを突き合わせて攻撃の流れを調査するために、すべての機器で徹底しておくべきことはどれでしょう？

1. ログをテキスト形式ではなく画像形式で保存すること
2. ログの保存期間を1日に統一すること
3. NTP による時刻同期を行い、ログのタイムスタンプを揃えること
4. ログの出力をできるだけ少なくすること

<details><summary>答えと解説</summary>

正解: **3**

機器ごとに時計がずれていると、イベントの前後関係が判断できず、複数ログを突き合わせた調査が成立しません。NTP による時刻同期は調査の大前提です。保存期間はむしろ十分に長く確保すべきで、1日では過去の侵入を追えません。出力を減らすと手がかりが失われ、画像形式での保存は検索・分析を困難にするだけです。

**問3.** EDR の説明として、適切なものはどれでしょう？

1. ネットワークの出入口で IP アドレスとポート番号を基に通信を遮断する装置
2. 電子メールの送信ドメイン認証を行う仕組み
3. 無線LAN の電波干渉を自動で回避する機能
4. 端末の操作や挙動を常時記録し、侵入後の検知・調査・対応を支援する仕組み

<details><summary>答えと解説</summary>

正解: **4**

EDR(Endpoint Detection and Response) は端末上の挙動を記録・監視し、侵入を前提として早期検知と調査・対応を支援します。「防ぐ」だけでなく「入られた後に素早く気づく」ための仕組みです。出入口での遮断はファイアウォール、送信ドメイン認証は SPF/DKIM/DMARC、電波干渉の回避は無線の DFS やチャネル設計の話です。

</details>

**問4.** パターンマッチング方式のマルウェア対策ソフトを有効に保つために、最も重要な運用はどれでしょう？

1. 定義ファイル（シグネチャ）を常に最新へ更新すること
2. スキャン対象をシステムフォルダのみに限定すること
3. 検知時の通知をオフにすること
4. 端末の時刻をあえてずらして攻撃者を混乱させること

<details><summary>答えと解説</summary>

正解: **1**

パターンマッチングは既知マルウェアの定義ファイルとの照合で検知するため、定義が古いと新しいマルウェアを見逃します。更新の徹底が生命線です。スキャン範囲の限定は検知漏れを招き、通知をオフにすると感染に気づけません。時刻をずらす運用はログの突き合わせを自ら壊す行為であり、セキュリティ上むしろ有害です。

</details>
