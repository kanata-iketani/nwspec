# 第19章 セキュリティ基礎（暗号・ハッシュ・PKI）

セキュリティ分野の土台になる章です。共通鍵と公開鍵の使い分け、ハッシュと HMAC、デジタル署名と PKI、代表的な攻撃手法、そしてリスクと多層防御の考え方を身につけます。

## 1. 共通鍵暗号と公開鍵暗号（例え話から）

暗号は「鍵をかける（暗号化）」「鍵を開ける（復号）」の仕組みです。鍵の使い方で2方式に分かれます。

### 共通鍵暗号: 同じ鍵で閉めて開ける

暗号化と復号に**同じ鍵**を使います。金庫の合鍵を2人で持つイメージです。代表は **AES**。

- 長所: **処理が速い**。大量データの暗号化向き
- 短所: **鍵をどうやって安全に相手へ渡すか**（鍵配送問題）。また n 人が互いに通信するには **n(n-1)/2 個**の鍵が必要になり、人数が増えると管理が大変

### 公開鍵暗号: 閉める鍵と開ける鍵が別

**公開鍵**と**秘密鍵**のペアを使います。「誰でも閉められるが、持ち主しか開けられない南京錠」のイメージです。代表は **RSA** や楕円曲線暗号（ECC）。

- 送信者は**受信者の公開鍵**で暗号化 → 受信者だけが自分の**秘密鍵**で復号できる
- 長所: 公開鍵は公開してよいので**鍵配送問題が解決**。鍵の数も1人2個で済む
- 短所: **処理が遅い**

### 実際はハイブリッド

TLS など実際のシステムでは、**公開鍵暗号で共通鍵を安全に共有**し、**本文は共通鍵暗号で高速に**処理する合わせ技（ハイブリッド暗号）が標準です。

> 💡 コツ: 「暗号化は受信者の公開鍵で」。誰に読ませたいかを考えると、使う鍵を間違えません。

🔴 2方式の長所・短所と「誰の・どちらの鍵を使うか」は全セキュリティ分野の土台です。

### 確認問題

**問1.** 共通鍵暗号方式の課題として、適切なものはどれでしょう？

1. 処理速度が公開鍵暗号より大幅に遅い
2. 暗号化はできるが復号ができない
3. 通信相手と鍵を安全に共有する方法（鍵配送）が問題になる
4. 鍵のペアを生成するのに認証局が必要である

<details><summary>答えと解説</summary>

正解: **3**

共通鍵暗号は同じ鍵を双方が持つ必要があるため、その鍵を盗聴されずに相手へ渡す「鍵配送問題」が本質的な課題です。処理速度はむしろ公開鍵暗号より高速です。復号できないのはハッシュ関数の性質であり、認証局が関わるのは公開鍵の正当性を保証する PKI の話です。

</details>

**問2.** A さんが B さんにだけ読める暗号文を公開鍵暗号で送るとき、暗号化に使う鍵はどれでしょう？

1. A さんの秘密鍵
2. B さんの公開鍵
3. A さんと B さんで共有した共通鍵の公開部分
4. B さんの秘密鍵

<details><summary>答えと解説</summary>

正解: **2**

受信者 B の公開鍵で暗号化すれば、対になる秘密鍵を持つ B だけが復号できます。A の秘密鍵で変換するのはデジタル署名の操作で、守秘にはなりません。B の秘密鍵は B 以外が持ってはいけない鍵であり、共通鍵に「公開部分」という概念はありません。

</details>

**問3.** 10人のグループ全員が互いに共通鍵暗号で1対1の秘密通信をする場合、必要な鍵の数はいくつでしょう？

1. 10個
2. 20個
3. 100個
4. 45個

<details><summary>答えと解説</summary>

正解: **4**

共通鍵はペアごとに1個必要なので n(n-1)/2 = 10×9÷2 = 45個です。10個は公開鍵暗号で各自が持つ鍵ペアの片方を数えた場合に近い発想、20個は公開鍵暗号における全員分の鍵ペア（1人2個）の数です。100個は n の2乗であり、自分自身との通信や重複を除いていない計算です。

</details>

**問4.** TLS などで使われるハイブリッド暗号の説明として、適切なものはどれでしょう？

1. 公開鍵暗号で共通鍵を安全に共有し、データ本体は高速な共通鍵暗号で処理する
2. 共通鍵暗号と公開鍵暗号で同じデータを二重に暗号化して強度を上げる
3. データの前半を共通鍵暗号、後半を公開鍵暗号で処理する
4. 暗号化をハッシュ関数で代用して高速化する

<details><summary>答えと解説</summary>

正解: **1**

ハイブリッド暗号は「鍵配送問題に強い公開鍵暗号」と「高速な共通鍵暗号」のいいとこ取りで、鍵の共有だけを公開鍵方式で行い、本文は共通鍵方式で処理します。二重暗号化や前半・後半での使い分けをする方式ではありません。ハッシュ関数は一方向変換で復号できないため、暗号化の代用にはなりません。

</details>

## 2. ハッシュとメッセージ認証（改ざん検知・HMAC）

### ハッシュ関数: データの「指紋」をとる

**ハッシュ関数**は、どんな長さのデータからも**固定長**の値（ハッシュ値）を計算する関数です。代表は **SHA-256**（出力は256ビット）。データの「指紋」のようなものです。

重要な性質は3つあります。

| 性質 | 意味 |
|---|---|
| 一方向性 | ハッシュ値から元データを復元**できない** |
| 衝突への耐性 | 同じハッシュ値になる別データを見つけるのが**極めて困難** |
| わずかな変化で激変 | 1文字でも変わるとハッシュ値は全く別物になる |

ファイル配布時に「ハッシュ値を照合してください」とあるのは、**改ざんや破損の検知**のためです。

### ハッシュだけでは足りない場面

経路の途中に攻撃者がいる場合、**データを書き換えてハッシュ値も計算し直して付け替える**ことができてしまいます。ハッシュ関数は誰でも計算できるからです。

### HMAC: 鍵を混ぜたハッシュ

そこで、送信者と受信者だけが知る**共通鍵（秘密の値）をデータに混ぜてから**ハッシュを計算するのが **HMAC** です。鍵を知らない攻撃者は正しい HMAC 値を計算し直せないため、

- **改ざん検知**（完全性）
- **送信者が鍵を知る本人であることの確認**（メッセージ認証)

の両方が実現します。TLS や IPsec の中でも使われています。

🔴 「ハッシュ単体=改ざん検知のみ(付け替えに弱い)、HMAC=鍵入りで認証もできる」の違いが問われます。

### 確認問題

**問1.** ハッシュ関数の性質として、適切なものはどれでしょう？

1. ハッシュ値と鍵があれば元のデータを復元できる
2. 入力データが長いほどハッシュ値も長くなる
3. 入力が1ビットでも変わると、ハッシュ値は大きく変化する
4. 同じハッシュ値を持つ別のデータは簡単に作成できる

<details><summary>答えと解説</summary>

正解: **3**

ハッシュ関数はわずかな入力の違いでも出力が大きく変わるため、改ざん検知に使えます。一方向性があるため鍵のあるなしに関わらず元データの復元はできず、出力は入力の長さによらず固定長です。同じハッシュ値になる別データを見つけるのが極めて困難であること（衝突への耐性）も重要な性質です。

</details>

**問2.** ハッシュ値を添えてデータを送るだけでは改ざん対策として不十分な理由はどれでしょう？

1. ハッシュ値の計算に数日かかるため実用的でないから
2. ハッシュ値から元データが復元されてしまうから
3. ハッシュ関数は一度しか使えないから
4. 攻撃者がデータを書き換えた上で、ハッシュ値も計算し直して付け替えられるから

<details><summary>答えと解説</summary>

正解: **4**

ハッシュ関数は誰でも計算できるため、経路上の攻撃者はデータ改ざん後に正しいハッシュ値を再計算して差し替えられます。これを防ぐには鍵を混ぜる HMAC や署名が必要です。ハッシュ計算は高速で、一方向性により元データの復元はできず、同じ関数を何度でも使えます。

</details>

**問3.** HMAC によって実現できることの組み合わせとして、適切なものはどれでしょう？

1. 改ざんの検知と、共通鍵を知る送信者からのメッセージであることの確認
2. 通信データの暗号化と圧縮
3. 送信者が後から送信の事実を否認できないようにすること
4. IP アドレスの詐称防止

<details><summary>答えと解説</summary>

正解: **1**

HMAC は共通鍵を混ぜてハッシュを計算するため、鍵を知らない第三者は正しい値を作れず、改ざん検知とメッセージ認証の両方が実現します。暗号化や圧縮の機能はありません。否認防止には本人だけが持つ秘密鍵によるデジタル署名が必要で、共通鍵方式の HMAC では双方が同じ鍵を持つため実現できません。IP 詐称の防止も HMAC の役割ではありません。

</details>

**問4.** SHA-256 の出力に関する説明として、適切なものはどれでしょう？

1. 出力の長さは入力データの半分になる
2. 入力の長さによらず、常に 256 ビットの固定長の値を出力する
3. 出力は常に平文のパスワードを含む
4. 出力から入力を一意に逆算できる

<details><summary>答えと解説</summary>

正解: **2**

SHA-256 はどんな長さの入力からも 256 ビット固定長のハッシュ値を出力します。入力の半分になるわけではありません。一方向性があるため出力からの逆算はできず、出力はビット列であって平文の情報をそのまま含むものではありません。

</details>

## 3. デジタル署名と PKI（証明書・CA・失効）

### デジタル署名: 「本人が書いた」ことの証明

公開鍵暗号の鍵を**逆向き**に使うと署名になります。

1. 送信者は文書のハッシュ値を計算し、それを**自分の秘密鍵**で変換（署名）して文書に添付
2. 受信者は**送信者の公開鍵**で署名を検証し、自分で計算したハッシュ値と一致するか確認

秘密鍵は本人しか持っていないため、検証に成功すれば「**本人が作成した**（認証）」「**改ざんされていない**（完全性）」「**後から『送っていない』と言い逃れできない**（否認防止）」が成立します。

> 💡 コツ: 暗号化は「**相手の公開鍵**で」、署名は「**自分の秘密鍵**で」。向きが逆です。

### PKI: その公開鍵、本物ですか？

署名の検証には送信者の公開鍵が必要ですが、攻撃者が「偽の公開鍵」をすり替えたら台無しです。そこで**信頼できる第三者＝ CA（認証局）**が「この公開鍵は確かにこの人・このサーバのものです」と**デジタル証明書**を発行して保証します。この社会的な仕組み全体を **PKI（公開鍵基盤）**と呼びます。

証明書自体にも CA の署名が付いており、ルート CA を頂点とする**信頼の連鎖**で検証します。

### 失効: 有効期限前に無効にする

秘密鍵の漏えいなどがあれば、証明書は期限前でも**失効**させます。失効の確認方法は、失効リストを配布する **CRL** と、オンラインで1件ずつ問い合わせる **OCSP** の2つです。

🔴 署名に使う鍵の向き・CA の役割・CRL/OCSP は午前Ⅱの超頻出です。

### 確認問題

**問1.** デジタル署名を作成するときと検証するときに使う鍵の組み合わせとして、適切なものはどれでしょう？

1. 作成: 受信者の公開鍵、検証: 受信者の秘密鍵
2. 作成: 送信者の公開鍵、検証: 送信者の秘密鍵
3. 作成: 送信者の秘密鍵、検証: 送信者の公開鍵
4. 作成: 共通鍵、検証: 別の共通鍵

<details><summary>答えと解説</summary>

正解: **3**

署名は本人しか持たない送信者の秘密鍵で作成し、誰でも入手できる送信者の公開鍵で検証します。受信者の鍵ペアを使うのは守秘のための暗号化（受信者の公開鍵で暗号化）の場合です。共通鍵を使う方式は HMAC などであり、否認防止ができない点でデジタル署名と異なります。

</details>

**問2.** PKI における CA（認証局）の役割として、適切なものはどれでしょう？

1. 通信データを代理で暗号化・復号する
2. 公開鍵とその持ち主の対応を保証するデジタル証明書を発行する
3. 利用者の秘密鍵を預かって保管する
4. ネットワークの経路情報を広告する

<details><summary>答えと解説</summary>

正解: **2**

CA は「この公開鍵は確かにこの主体のもの」という対応関係を審査し、自らの署名付きでデジタル証明書を発行する信頼の起点です。通信の暗号化・復号は通信当事者が行います。秘密鍵は本人だけが保持すべきもので CA に預けるものではなく、経路情報の広告は BGP などルーティングプロトコルの話です。

</details>

**問3.** サーバの秘密鍵が漏えいした疑いがある場合、その証明書への対応として適切なものはどれでしょう？

1. 有効期限まではそのまま使い続ける
2. 証明書の公開鍵だけを差し替えて同じ証明書を使う
3. ハッシュ関数を強いものに変更する
4. CA に失効を申請し、CRL や OCSP で失効が確認できるようにした上で新しい鍵ペアと証明書に切り替える

<details><summary>答えと解説</summary>

正解: **4**

秘密鍵の漏えい時は有効期限を待たず失効手続きを行い、CRL(失効リスト) や OCSP(オンライン照会) で第三者が失効を確認できる状態にし、新しい鍵ペアで証明書を再発行します。使い続ければなりすましを許します。証明書は公開鍵と一体で署名されているため公開鍵だけの差し替えはできず、ハッシュ関数の変更は漏えいへの対処になりません。

</details>

**問4.** デジタル署名によって実現できるが、HMAC では実現できないものはどれでしょう？

1. 否認防止（送信者が後から送信の事実を否定できないこと）
2. 改ざんの検知
3. 通信内容の暗号化
4. 通信速度の向上

<details><summary>答えと解説</summary>

正解: **1**

HMAC は送信者と受信者が同じ共通鍵を持つため、「受信者が自分で作った」と言われると区別できず、否認防止になりません。デジタル署名は本人だけが持つ秘密鍵を使うため否認防止が成立します。改ざん検知は両者とも可能です。暗号化はどちらの機能でもなく、速度向上はそもそもセキュリティ機能ではありません。

</details>

## 4. 攻撃手法のきほん（盗聴・なりすまし・DoS/DDoS・中間者)

守り方を学ぶ前に、攻撃の型を知っておきましょう。代表的な4分類です。

### 盗聴（情報を盗み見る）

経路上のパケットを**キャプチャ**して内容を読む攻撃です。平文の通信（HTTP、古い POP3 など）は丸見えになります。基本の対策は**暗号化**（TLS など）です。

### なりすまし（別人のふりをする）

送信元 IP アドレスの詐称、メール差出人の詐称（フィッシング）、ARP 応答を偽る **ARP スプーフィング**などがあります。対策は**認証**（デジタル署名、SPF/DKIM、802.1X など）です。

### DoS / DDoS（サービスを止める）

サーバや回線に処理しきれない負荷をかけ、サービスを**停止・低下**させる攻撃です。

- **SYN フラッド**: TCP の3ウェイハンドシェイクを途中で放置し、サーバの接続待ちリソースを食いつぶす
- **DDoS**: 乗っ取った多数の機器（**ボットネット**）から一斉に攻撃する分散型
- **リフレクション（反射）攻撃**: 送信元 IP を**標的に詐称**して DNS や NTP に問い合わせ、**増幅された応答**を標的に浴びせる

### 中間者攻撃（MITM）

通信の間に割り込み、両者には正常に見せかけながら**盗聴・改ざん・すり替え**を行う攻撃です。偽の無線 AP や ARP スプーフィングが入口になります。対策は TLS と**証明書の検証**です。

🟡 「リフレクション攻撃=送信元 IP を標的に詐称」はよく問われるポイントです。

### 確認問題

**問1.** SYN フラッド攻撃の説明として、適切なものはどれでしょう？

1. Web アプリケーションの入力欄に SQL 文を注入してデータベースを不正操作する
2. 無線LAN のパスフレーズを総当たりで解析する
3. TCP の接続要求を大量に送り、応答を放置してサーバの接続待ちリソースを枯渇させる
4. DNS の応答を偽造して利用者を偽サイトへ誘導する

<details><summary>答えと解説</summary>

正解: **3**

SYN フラッドは 3 ウェイハンドシェイクの最初の SYN だけを大量に送り、最後の ACK を返さないことで、サーバ側の接続待ち（ハーフオープン）の資源を食いつぶす DoS 攻撃です。SQL 文の注入は SQL インジェクション、DNS 応答の偽造は DNS キャッシュポイズニング、パスフレーズの解析はパスワードクラックであり、いずれも別の攻撃です。

</details>

**問2.** DNS や NTP を悪用したリフレクション（反射・増幅）攻撃で、攻撃者が送信元 IP アドレスを詐称して設定するのはどれでしょう？

1. 攻撃者自身の IP アドレス
2. 攻撃対象（標的）の IP アドレス
3. DNS サーバの IP アドレス
4. プライベート IP アドレスの任意の値

<details><summary>答えと解説</summary>

正解: **2**

リフレクション攻撃では、送信元を標的の IP に詐称して問い合わせを送ることで、サーバからの大きな応答が標的へ集中します。攻撃者自身の IP にすると応答が自分に返るだけで攻撃になりません。DNS サーバは応答を返す踏み台側であり、任意のプライベートアドレスでは応答が標的に向かいません。

</details>

**問3.** 中間者攻撃（MITM）への対策として、最も適切なものはどれでしょう？

1. TLS を使い、サーバ証明書の検証を正しく行う
2. パケットのサイズを小さくする
3. 通信回数を減らす
4. SSID を目立たない名前に変更する

<details><summary>答えと解説</summary>

正解: **1**

TLS による暗号化と証明書検証を正しく行えば、割り込んだ攻撃者は正規の証明書を提示できず、なりすましが検知されます。パケットサイズや通信回数は攻撃の成立と無関係です。SSID の名前変更は接続先の偽装（偽 AP）を防ぐ効果がなく、中間者攻撃への対策にはなりません。

</details>

**問4.** DoS 攻撃と DDoS 攻撃の違いとして、適切なものはどれでしょう？

1. DoS は無線限定、DDoS は有線限定の攻撃である
2. DoS はデータの窃取が目的で、DDoS は改ざんが目的である
3. DoS は暗号化通信にのみ有効で、DDoS は平文通信にのみ有効である
4. DDoS はボットネットなど多数の機器から分散して攻撃する点が DoS と異なる

<details><summary>答えと解説</summary>

正解: **4**

DDoS(Distributed DoS) は、マルウェアに感染させた多数の機器（ボットネット）から一斉に攻撃する分散型で、攻撃元が多いため遮断が困難です。どちらもサービス妨害が目的であり、窃取や改ざんが目的の攻撃ではありません。有線・無線や暗号化の有無による区別も誤りです。

</details>

## 5. 脅威と対策の考え方（リスク・多層防御・ゼロトラストの入口)

個別の技術の前に、「守り方の考え方」を整理します。午後問題で対策を記述するときの軸になります。

### リスクは3要素で考える

**リスク**は、守るべき**情報資産**に、**脅威**（攻撃・災害・ミス）が、**脆弱性**（弱点）を突いて損害を与える可能性です。3つが揃って初めてリスクになるため、どれか1つを下げればリスクは減ります。たとえば脆弱性に**パッチを適用する**のは「脆弱性を減らす」対策です。

### 多層防御: 1枚の壁に頼らない

どんな対策も**突破される可能性がゼロにはなりません**。そこで、入口（ファイアウォール）・内部（ネットワーク分割、アクセス制御）・端末（マルウェア対策）・データ（暗号化）・人（教育）と**複数の層**で守り、1層が破られても次の層で食い止める考え方が**多層防御**です。城の「堀・城壁・天守」のイメージです。

### ゼロトラストの入口

従来は「社内ネットワーク＝信頼できる、外＝危険」という**境界型防御**が主流でした。しかしクラウド利用やテレワークで「社内／社外」の境界があいまいになり、内部に侵入された後は素通しという弱点も明らかになりました。そこで「**何も無条件には信頼せず、アクセスのたびに検証する**」という考え方が**ゼロトラスト**です。利用者・端末の認証と権限の最小化（**最小権限の原則**）を、場所を問わず毎回行います。

🟡 「多層防御の考え方」と「境界型防御とゼロトラストの違い」は記述でも使えるよう言葉で説明できるようにしましょう。

### 確認問題

**問1.** 情報セキュリティにおけるリスクを構成する3要素の組み合わせとして、適切なものはどれでしょう？

1. 機密性・完全性・可用性
2. 情報資産・脅威・脆弱性
3. 認証・認可・監査
4. 予防・検知・復旧

<details><summary>答えと解説</summary>

正解: **2**

リスクは「情報資産」に「脅威」が「脆弱性」を突いて損害を与える可能性として捉え、どれか1つを減らせばリスクを低減できます。機密性・完全性・可用性は情報セキュリティの3要素（CIA）、認証・認可・監査はアクセス管理の枠組み、予防・検知・復旧は対策の時間軸による分類であり、リスクの構成要素そのものではありません。

</details>

**問2.** 多層防御の考え方として、適切なものはどれでしょう？

1. 最も高性能なファイアウォールを1台導入すれば他の対策は省略できる
2. すべての対策を入口に集中させるのが最も効率的である
3. 入口・内部・端末・データなど複数の層に対策を重ね、1層が突破されても次で食い止める
4. 暗号化さえしておけば侵入されても問題ない

<details><summary>答えと解説</summary>

正解: **3**

多層防御は「どの対策も突破されうる」前提で、複数の層に対策を重ねて被害を食い止める考え方です。1台の装置や入口だけに頼る構成は、そこを突破されると後が素通しになります。暗号化も重要な1層ですが、鍵の窃取や端末内での窃取には無力な場面があり、単独では十分ではありません。

</details>

**問3.** ゼロトラストの基本的な考え方として、適切なものはどれでしょう？

1. 社内ネットワークからのアクセスはすべて無条件に信頼する
2. すべての通信を禁止して業務を停止する
3. 一度ログインに成功した端末は永久に信頼する
4. 社内外を問わず、アクセスのたびに利用者や端末を検証する

<details><summary>答えと解説</summary>

正解: **4**

ゼロトラストは「ネットワークの場所では信頼を判断せず、アクセスごとに認証・認可を行う」考え方です。社内だからと無条件に信頼するのは従来の境界型防御の発想で、内部侵入後に弱いという課題があります。すべてを禁止するのではなく検証して許可する仕組みであり、一度の成功を永久に信頼する運用はゼロトラストの逆です。

</details>

**問4.** 「利用者には業務に必要な最小限の権限だけを与える」という原則を何と呼ぶでしょう？

1. 最小権限の原則
2. 単一障害点の排除
3. フェールセーフ
4. 負荷分散の原則

<details><summary>答えと解説</summary>

正解: **1**

最小権限の原則は、不正利用や侵害時の被害範囲を小さくするため、必要最小限の権限のみを付与する考え方で、ゼロトラストでも中核になります。単一障害点の排除とフェールセーフは信頼性設計の用語、負荷分散は性能設計の手法であり、権限管理の原則ではありません。

</details>
