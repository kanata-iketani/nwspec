# 第22章 認証技術（802.1X・RADIUS・SSO）

「つないでよい相手か」を入口で見極めるのが認証です。認証の3要素から、社内 LAN の入口を守る IEEE802.1X と RADIUS、複数サービスをまたぐ SSO、端末種別ごとの認証方式の使い分けまでを学ぶ章です。

## 1. 認証の3要素と多要素認証

**認証**とは「あなたは本当に本人ですか？」を確かめる手続きです。確かめる材料は、次の3つの要素に分類されます。

| 要素 | 意味 | 例 |
|---|---|---|
| 知識（Something you know） | 本人だけが知っている | パスワード、PIN、秘密の質問 |
| 所持（Something you have） | 本人だけが持っている | スマートフォン、IC カード、ハードウェアトークン、クライアント証明書 |
| 生体（Something you are） | 本人の身体の特徴 | 指紋、顔、虹彩 |

### 多要素認証（MFA）

**異なる要素を2つ以上**組み合わせる認証を多要素認証と呼びます。たとえば「パスワード（知識）＋スマートフォンアプリのワンタイムパスワード（所持）」は多要素です。

注意したいのは、**同じ要素を2回使っても多要素にはならない**ことです。「パスワード＋秘密の質問」はどちらも知識なので、2段階ではあっても多要素認証ではありません。

### 各要素の弱点

知識は漏えい・推測に弱く、所持は紛失・盗難のリスクがあります。生体は漏えいしても**本人が変更できない**という固有の注意点があります。だからこそ、性質の異なる要素を重ねて互いの弱点を補うのが多要素認証の狙いです。

> 💡 コツ：「知っている・持っている・その人自身である」の3語で覚え、問題文の認証手段をこの3つに仕分けしましょう。

🔴 「この組み合わせは多要素認証か？」という判定問題は午前Ⅱの定番です。要素の仕分けを即答できるようにしましょう。

### 確認問題

**問1.** 認証の3要素の組み合わせとして、正しいものはどれでしょう？

1. 知識・所持・年齢
2. 知識・所持・生体
3. パスワード・暗号化・署名
4. ID・パスワード・メールアドレス

<details><summary>答えと解説</summary>

正解: **2**

認証の3要素は「知識（知っている）・所持（持っている）・生体（その人自身の特徴）」です。年齢は本人確認の要素として使われません。暗号化や署名はデータ保護・改ざん検知の技術で認証要素の分類ではなく、ID やメールアドレスは利用者の識別子であって本人性を証明する要素そのものではありません。

</details>

**問2.** 多要素認証に該当するものはどれでしょう？

1. パスワードと秘密の質問
2. 2種類の異なるパスワード
3. 指紋と顔の両方による認証
4. パスワードと、スマートフォンアプリに表示されるワンタイムパスワード

<details><summary>答えと解説</summary>

正解: **4**

パスワードは知識、スマートフォンに表示されるワンタイムパスワードは端末の所持を証明するため、異なる2要素の組み合わせで多要素認証に該当します。パスワードと秘密の質問、2種類のパスワードはいずれも知識のみの重ね掛けです。指紋と顔もどちらも生体で、同一要素の組み合わせは多要素とは呼びません。

</details>

**問3.** 「パスワードに加えて秘密の質問にも答えさせる」方式が多要素認証と言えない理由はどれでしょう？

1. どちらも「知識」の要素であり、異なる要素を組み合わせていないから
2. 認証を2回行うとサーバの負荷が高くなるから
3. 秘密の質問は法律で禁止されているから
4. パスワードは認証の要素に含まれないから

<details><summary>答えと解説</summary>

正解: **1**

多要素認証の条件は「異なる要素を2つ以上」であり、知識＋知識は段階が増えても1要素のままです。片方が漏れる状況（本人周辺の情報収集など）ではもう片方も漏れやすく、安全性の向上が限定的です。サーバ負荷は多要素かどうかの定義と無関係で、秘密の質問を禁止する法律もなく、パスワードは代表的な知識要素です。

</details>

**問4.** 生体認証について、他の要素にはない注意点はどれでしょう？

1. 総当たり攻撃で簡単に突破されてしまう
2. 利用者が覚えておく負担が大きい
3. 認証情報が漏えいしても、パスワードのように本人が変更することができない
4. ハードウェアが一切不要である

<details><summary>答えと解説</summary>

正解: **3**

指紋や顔などの生体情報は本人の身体そのものなので、一度漏えいしても「変更して無効化する」ことができません。これが生体認証固有のリスクです。総当たり攻撃はパスワードなど知識要素への典型的な攻撃です。生体は覚える負担がないのが利点であり、読み取りにはセンサーなどのハードウェアがむしろ必要です。

</details>

## 2. IEEE802.1X と RADIUS（サプリカント・オーセンティケータの流れ）

**IEEE802.1X** は、LAN の「入口」で端末を認証する仕組みです。認証に通るまで、スイッチのポートや無線 AP は業務通信を通しません。

### 登場する3者

| 役割 | 実体 | 仕事 |
|---|---|---|
| サプリカント | 端末（の認証ソフト） | 認証情報を提示する |
| オーセンティケータ | LAN スイッチ・無線 AP | 端末と認証サーバの仲介役。自分では合否を判定しない |
| 認証サーバ | RADIUS サーバ | 認証情報を検証し、合否を返す |

### 認証の流れ

1. 端末がスイッチに接続すると、端末〜スイッチ間で **EAPOL** というフレームで認証のやり取りが始まります
2. スイッチは受け取った認証情報（EAP メッセージ）を **RADIUS プロトコル**（UDP）に載せ替えて認証サーバへ中継します
3. サーバが合格を返すと、スイッチはポートを開放します。あわせて所属 VLAN を指示する**ダイナミック VLAN** も実現できます

認証方式（EAP の種類）としては、クライアント証明書で端末を認証する **EAP-TLS**、ID・パスワードを使う **PEAP** が代表的です。

> 💡 コツ：オーセンティケータは「門番だが判定はしない中継役」。合否を決めるのはあくまで RADIUS サーバです。

🔴 「サプリカント＝端末、オーセンティケータ＝スイッチ/AP、認証サーバ＝RADIUS」の3点セットと、EAPOL→RADIUS の載せ替えの流れは必ず押さえましょう。

### 確認問題

**問1.** IEEE802.1X において、オーセンティケータに該当する機器はどれでしょう？

1. 利用者の PC
2. RADIUS サーバ
3. LAN スイッチや無線アクセスポイント
4. DNS サーバ

<details><summary>答えと解説</summary>

正解: **3**

オーセンティケータは端末と認証サーバの間に立つ中継役で、実体は LAN スイッチや無線 AP です。利用者の PC（の認証ソフト）はサプリカント、RADIUS サーバは合否を判定する認証サーバに当たります。DNS サーバは名前解決の装置で 802.1X の構成要素ではありません。

</details>

**問2.** IEEE802.1X を導入したスイッチのポートに端末を接続した直後（認証成功前）の状態として、適切なものはどれでしょう？

1. 認証に関する通信（EAP）以外は遮断され、業務通信はできない
2. すべての通信が即座に許可される
3. Web サイトの閲覧だけが許可される
4. 物理的にリンクアップしない

<details><summary>答えと解説</summary>

正解: **1**

802.1X では認証に合格するまでポートは認証のやり取り（EAPOL）しか通さず、業務通信は遮断されます。これにより未許可端末の LAN 接続を入口で防ぎます。すべて許可では認証の意味がなく、Web だけ許可するのは検疫や Web 認証など別の仕組みです。リンク自体（物理層）は確立したうえで、その上の通信を制限します。

</details>

**問3.** IEEE802.1X の認証の流れとして、オーセンティケータの動作を正しく説明したものはどれでしょう？

1. 端末のパスワードを自分のデータベースと照合して合否を判定する
2. 認証サーバの代わりに証明書を発行する
3. 端末の MAC アドレスを書き換えて転送する
4. 端末との間は EAPOL でやり取りし、認証情報は RADIUS プロトコルで認証サーバへ中継する

<details><summary>答えと解説</summary>

正解: **4**

オーセンティケータは、端末側とは EAPOL、サーバ側とは RADIUS という2つのプロトコルを使い分けて認証メッセージを中継します。合否の判定やアカウント情報の保持は認証サーバの役割で、スイッチ自身は判定しません。証明書の発行は認証局（CA）の仕事であり、MAC アドレスの書き換えも行いません。

</details>

**問4.** EAP-TLS の特徴として、適切なものはどれでしょう？

1. 暗号化せずに ID とパスワードを平文で送る方式である
2. クライアント証明書を使って端末（利用者）を認証する方式である
3. MAC アドレスの一覧表だけで認証する方式である
4. ワンタイムパスワードを郵送で通知する方式である

<details><summary>答えと解説</summary>

正解: **2**

EAP-TLS はサーバとクライアントの双方が証明書を提示して認証する方式で、パスワードを使わないため漏えいに強く、802.1X の認証方式の中でも強固とされます。平文でパスワードを送る方式ではありません。MAC アドレスの一覧による認証は MAC アドレス認証という別の仕組みで、ワンタイムパスワードの郵送という方式でもありません。

</details>

**問5.** 全社の有線 LAN と無線 LAN の 802.1X 認証を、1台の RADIUS サーバだけで運用している構成があります。この構成の弱点として、最も適切なものはどれでしょう？

1. RADIUS サーバが増えるほど認証が遅くなる
2. スイッチと RADIUS サーバは1対1でしか接続できない
3. RADIUS サーバが停止すると、全社で新規の認証ができず LAN に接続できなくなる
4. 有線と無線で RADIUS サーバを共用することはできない

<details><summary>答えと解説</summary>

正解: **3**

認証の合否を判定できるのは RADIUS サーバだけなので、1台構成ではそのサーバの障害が「誰も新たに LAN へ入れない」という全社影響に直結します。対策はサーバの冗長化（スイッチに複数サーバを登録）です。サーバを増やすこと自体で認証が遅くなるわけではなく、1台のサーバで多数のスイッチや有線・無線の認証をまとめて受けるのはごく一般的な構成です。

</details>

## 3. SSO（SAML・OIDC ざっくり）とディレクトリ（LDAP/AD）

**SSO（シングルサインオン）**は、1回の認証で複数のサービスを利用できる仕組みです。パスワードの使い回しを減らし、利用者の手間と管理者の負担を下げられます。

### SAML：社内システムやクラウドサービスの定番

**SAML** では、認証を担当する **IdP（Identity Provider）**と、サービスを提供する **SP（Service Provider）**が役割分担します。利用者が SP にアクセスすると IdP へ誘導され、IdP での認証に成功すると「この人は本人です」という**アサーション**（XML の証明書き）が発行され、SP はそれを検証してログインさせます。SP はパスワードを預からずに済むのがポイントです。

### OIDC：OAuth 2.0 ベースの新しめの方式

**OIDC（OpenID Connect）**は、認可の仕組みである OAuth 2.0 を拡張して「認証」もできるようにしたもので、**ID トークン**で本人であることを伝えます。Web やスマートフォンアプリのログイン連携で広く使われます。

### 土台になるディレクトリ

利用者 ID や所属などを一元管理するデータベースが**ディレクトリサービス**で、そこへアクセスするための標準プロトコルが **LDAP** です。**Active Directory（AD）**は Microsoft のディレクトリサービスで、多くの企業で認証の土台になっています。

> 💡 コツ：SAML は「IdP・SP・アサーション」、OIDC は「OAuth 2.0 ベース・ID トークン」とキーワードで対にして覚えましょう。

🟡 SSO は便利な反面、IdP が止まる・乗っ取られると全サービスに波及します。利点とリスクをセットで説明できるようにしましょう。

### 確認問題

**問1.** SAML による SSO で、IdP（Identity Provider）の役割はどれでしょう？

1. 利用者にアプリケーションの機能を提供する
2. 利用者を認証し、本人であることを示すアサーションを発行する
3. パケットを暗号化して転送する
4. ドメイン名を IP アドレスに変換する

<details><summary>答えと解説</summary>

正解: **2**

IdP は認証の専門役で、認証に成功した利用者についてアサーション（本人であることの証明書き）を発行し、SP はそれを検証してログインを許可します。アプリ機能を提供するのは SP の役割です。暗号化転送は VPN など通信保護の仕組み、名前解決は DNS の仕事であり、IdP の役割ではありません。

</details>

**問2.** OIDC（OpenID Connect）の説明として、適切なものはどれでしょう？

1. XML 形式のアサーションを使う、SAML より古い規格である
2. ディレクトリサービスにアクセスするためのプロトコルである
3. OAuth 2.0 を拡張し、ID トークンで利用者の認証を行えるようにした仕組みである
4. LAN スイッチのポート単位で端末を認証する規格である

<details><summary>答えと解説</summary>

正解: **3**

OIDC は認可の枠組みである OAuth 2.0 の上に認証機能を載せた規格で、ID トークンによって「誰がログインしたか」を伝えます。XML のアサーションを使うのは SAML で、OIDC のほうが後発です。ディレクトリへのアクセスは LDAP、ポート単位の端末認証は IEEE802.1X の説明です。

</details>

**問3.** LDAP の説明として、適切なものはどれでしょう？

1. 利用者情報などを管理するディレクトリサービスへアクセスするためのプロトコルである
2. ファイルを暗号化して保存するためのファイルシステムである
3. 無線 LAN の電波干渉を避けるためのチャネル設計手法である
4. Web サーバの負荷を分散するための装置である

<details><summary>答えと解説</summary>

正解: **1**

LDAP は、利用者 ID・所属・連絡先などを木構造で一元管理するディレクトリサービスに対して、検索や更新を行うための標準プロトコルです。Active Directory も LDAP でアクセスできます。ファイルの暗号化保存、無線のチャネル設計、負荷分散装置はいずれもディレクトリアクセスとは別の分野の話です。

</details>

**問4.** SSO を全社に導入した場合のリスクとして、最も適切なものはどれでしょう？

1. サービスごとに異なるパスワードを覚える負担が増える
2. 各サービスが個別に利用者のパスワードを保存しなければならなくなる
3. IdP が停止したり乗っ取られたりすると、連携するすべてのサービスの利用や安全性に影響が及ぶ
4. 利用者の認証回数が増えて利便性が下がる

<details><summary>答えと解説</summary>

正解: **3**

SSO では認証が IdP に集中するため、IdP の障害や侵害は連携する全サービスに波及します。導入時は IdP の冗長化と多要素認証による保護が重要です。パスワードを覚える負担や認証回数はむしろ減るのが SSO の利点で、SP がパスワードを預からずに済む点も SAML などの利点なので、残りの選択肢は利点と逆の説明になっています。

</details>

## 4. MAC アドレス認証・Web 認証・証明書認証の使い分け

LAN の入口認証には 802.1X 以外の方式もあり、午後問題では「端末の種類ごとの使い分け」がよく問われます。

### 3つの方式の比較

| 方式 | 仕組み | 向いている対象 | 弱点 |
|---|---|---|---|
| MAC アドレス認証 | 端末の MAC アドレスを登録済みリストや RADIUS で照合 | 802.1X に対応できないプリンタ・IoT 機器 | MAC アドレスは**偽装できる** |
| Web 認証 | 接続後にブラウザへ認証ページを表示し ID・パスワードを入力 | 来訪者（ゲスト）の一時利用 | 端末にソフトは不要だが、毎回の入力が必要 |
| 証明書認証（EAP-TLS） | 端末に入れたクライアント証明書で認証 | 社員の業務端末 | 証明書の配布・更新・失効の管理に手間がかかる |

### 使い分けの考え方

業務 PC のように管理が行き届く端末は、最も強固な**証明書認証**で守ります。認証ソフト（サプリカント）を持たないプリンタなどは **MAC アドレス認証**で救済しますが、偽装に弱いので「登録端末しかつながらないから安全」と**過信しない**ことが重要です。来訪者には **Web 認証**でゲスト用 VLAN に収容し、社内ネットワークと分離するのが定石です。

> 💡 コツ：問題文に「プリンタ」「複合機」が出てきたら MAC アドレス認証、「来訪者」が出てきたら Web 認証＋ゲスト VLAN を疑いましょう。

🟡 「MAC アドレス認証の弱点を述べよ」は午後の定番です。「MAC アドレスは偽装可能だから」と書けるようにしておきましょう。

### 確認問題

**問1.** MAC アドレス認証が採用される典型的な場面はどれでしょう？

1. 来訪者に一時的なインターネット接続を提供する場合
2. 経営層の端末だけ特別に強固に認証したい場合
3. すべての社員の業務 PC を最も強固に認証したい場合
4. 802.1X のサプリカントを導入できないプリンタや IoT 機器を LAN に接続する場合

<details><summary>答えと解説</summary>

正解: **4**

MAC アドレス認証は端末側に認証ソフトが不要なため、802.1X に対応できないプリンタや IoT 機器の救済策として使われます。来訪者向けには Web 認証が定石です。強固さが必要な業務端末や重要端末には、偽装に弱い MAC アドレス認証ではなく証明書認証（EAP-TLS）が適します。

</details>

**問2.** MAC アドレス認証の弱点として、最も適切なものはどれでしょう？

1. 端末ごとに専用の認証ソフトを導入する必要がある
2. MAC アドレスは攻撃者が自由に偽装できるため、登録端末へのなりすましを防げない
3. 認証のたびに利用者がパスワードを入力する必要がある
4. IPv6 環境では一切使用できない

<details><summary>答えと解説</summary>

正解: **2**

MAC アドレスはソフトウェア設定で容易に書き換えられるため、正規端末の MAC アドレスを知られるとなりすまされます。これが MAC アドレス認証の本質的な弱点です。認証ソフトが不要なこと、利用者の入力なしで認証できることはむしろこの方式の利点です。MAC アドレスはレイヤ2の識別子なので IPv6 かどうかには依存しません。

</details>

**問3.** 来訪者（ゲスト）用の無線 LAN を提供する際の設計として、最も適切なものはどれでしょう？

1. Web 認証で受け入れ、ゲスト専用 VLAN に収容して社内ネットワークから分離する
2. 来訪者の端末すべてにクライアント証明書を発行する
3. 認証なしで社内 LAN と同じ VLAN に接続させる
4. 来訪者の端末の MAC アドレスを恒久的に社内の業務用リストへ登録する

<details><summary>答えと解説</summary>

正解: **1**

ゲストには端末にソフトを入れずに済む Web 認証が手軽で、ゲスト用 VLAN への収容により社内資源へのアクセスを遮断するのが定石です。一時利用者への証明書発行は配布・失効の手間が現実的でありません。認証なしで社内と同じ VLAN に入れるのは論外で、ゲスト端末を業務用リストに恒久登録するのも管理と安全性の両面で不適切です。

</details>

**問4.** 3つの認証方式のうち、最も強固とされる証明書認証（EAP-TLS）の運用上の課題はどれでしょう？

1. パスワードの定期変更を利用者に強制する必要がある
2. ブラウザを起動しないと認証が始まらない
3. 証明書の配布・更新・失効といったライフサイクル管理に手間がかかる
4. MAC アドレスの偽装に対して無力である

<details><summary>答えと解説</summary>

正解: **3**

証明書認証は端末への証明書の配布、有効期限切れ前の更新、退職・紛失時の失効といった管理の仕組みづくりが課題で、その手間と引き換えに高い安全性を得ます。パスワードを使わないのでパスワード変更の運用は不要です。ブラウザが必要なのは Web 認証で、MAC アドレスの偽装が弱点になるのは MAC アドレス認証です。

</details>
