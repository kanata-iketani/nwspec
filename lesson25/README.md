# 第25章 仮想化・クラウド・SDN

物理の配線から一歩離れ、仮想スイッチ・クラウドの仮想ネットワーク・VXLAN・SDN といった「ソフトウェアでつくるネットワーク」を学ぶ章です。近年の試験で出題が増えている分野です。

## 1. サーバ仮想化とネットワーク（仮想スイッチ・NICチーミング）

**サーバ仮想化**では、1台の物理サーバ上で**ハイパーバイザ**というソフトウェアが複数の**仮想マシン（VM）**を動かします。各VMには仮想的なNICがあり、それらをつなぐのが**仮想スイッチ（vSwitch）**です。

### 仮想スイッチの重要な性質

仮想スイッチはハイパーバイザ内で動くソフトウェアのL2スイッチです。ここで試験頻出のポイントがあります。

**同じ物理サーバ上のVM同士の通信は、仮想スイッチ内で折り返され、物理NICや外部のスイッチを通りません。**

つまり、外部に置いたファイアウォールやIDSでは**VM間の通信を監視・制御できない**場合があります。午後試験では「VM間通信をどう可視化・制御するか」が設計上の論点になります。

### NICチーミング

物理サーバの複数の物理NICを束ねて使う技術が**NICチーミング**です。目的は2つです。

| 目的 | 内容 |
|---|---|
| 冗長化 | 1枚のNICやケーブルが故障しても通信を継続できる |
| 帯域の有効活用 | 複数NICにトラフィックを分散できる（方式による） |

構成にはアクティブ/スタンバイ型や負荷分散型があり、接続先スイッチ側の設定（LAGなど）との整合も必要です。

> 💡 コツ: 🟡 「VM間通信は物理ネットワークに出ないことがある」——この一文が仮想化ネットワーク問題の核心です。

### 確認問題

**問1.** 同一の物理サーバ上で動作するVM同士が、同じ仮想スイッチに接続されて通信する場合の経路として、適切なものはどれか。

1. 必ず物理NICから外部スイッチへ出て折り返してくる
2. 通信のたびにインターネットを経由する
3. 仮想スイッチ内で転送され、物理NICを通らない
4. VM同士はネットワークを介した通信ができない

<details><summary>答えと解説</summary>

正解: **3**

同一ホスト上の同一仮想スイッチに接続されたVM同士の通信は、ハイパーバイザ内の仮想スイッチで折り返され、物理NICや外部スイッチを通りません。そのため外部の監視機器からは見えない点が設計上の注意点です。必ず外部へ出るわけではなく、もちろんインターネット経由でも通信不可でもありません。

</details>

**問2.** NICチーミングの目的として、最も適切なものはどれか。

1. 複数の物理NICを束ね、冗長化やトラフィックの分散を図る
2. NICのMACアドレスを暗号化して盗聴を防ぐ
3. 1枚のNICを複数のIPアドレスで時分割利用する
4. NICのファームウェアを自動更新する

<details><summary>答えと解説</summary>

正解: **1**

NICチーミングは複数の物理NICを論理的に束ねる技術で、片方の故障時にも通信を継続できる冗長化と、トラフィック分散による帯域の有効活用が目的です。MACアドレスの暗号化やファームウェア更新の機能ではなく、1枚のNICに複数IPを割り当てる話（IPエイリアス）とも別物です。

</details>

**問3.** 仮想化環境で、同一ホスト上のVM間の通信が外部に設置したIDSで検知できなかった。原因として最も適切なものはどれか。

1. VM間の通信はすべて暗号化されるため
2. VM間の通信が仮想スイッチ内で完結し、IDSが接続された物理ネットワークを通らないため
3. IDSは仮想マシンのトラフィックを原理的に解析できないため
4. ハイパーバイザがIDS宛ての通信だけを破棄するため

<details><summary>答えと解説</summary>

正解: **2**

同一ホスト・同一仮想スイッチ上のVM間通信は物理ネットワークに出ないため、外部のIDSには届きません。対策には仮想環境側での監視や、通信をいったん外部に出す設計などがあります。VM間通信が自動的に暗号化されるわけではなく、IDSが仮想マシン由来のトラフィックを解析できないという原理的制約もありません。

</details>

**問4.** ハイパーバイザの説明として、適切なものはどれか。

1. VMのディスクイメージを圧縮するユーティリティ
2. 仮想マシン間で負荷分散を行う専用ロードバランサ
3. 物理ネットワークとVLANを対応付ける物理スイッチの機能
4. 物理サーバ上で複数の仮想マシンを動作させるための基盤ソフトウェア

<details><summary>答えと解説</summary>

正解: **4**

ハイパーバイザは物理サーバのCPU・メモリなどの資源を分割し、複数のVMを同時に動かすための基盤ソフトウェアです。仮想スイッチもこの上で動作します。ディスク圧縮ツールやロードバランサではなく、物理スイッチの機能でもありません。

</details>

## 2. クラウドのネットワーク（仮想ネットワーク・閉域接続・責任共有）

**IaaS**（Infrastructure as a Service）では、サーバだけでなくネットワークも仮想化されたものを利用します。ただし「クラウドだから設計不要」ではありません。

### 利用者が設計するもの

IaaSの**仮想ネットワーク**では、利用者自身が次を設計・設定します。

- アドレス空間と**サブネット**の分割（公開用・内部用など）
- ルーティング（ルートテーブル）
- **セキュリティグループ**: 仮想サーバ単位で通信の可否を制御する仮想ファイアウォール機能

### オンプレミスとの接続

| 接続方式 | 特徴 |
|---|---|
| インターネットVPN | 安価で早く構築できるが、品質はインターネット次第 |
| **閉域接続**（専用線・閉域網） | インターネットを経由せず、帯域や遅延が安定し、セキュリティ面でも有利。コストは高い |

### 責任共有モデル

クラウドのセキュリティは事業者と利用者で分担します。IaaSの場合、**物理設備や仮想化基盤までは事業者**の責任、**ゲストOSのパッチ適用、ミドルウェア、セキュリティグループなどの設定は利用者**の責任です。「クラウドに置いたから安全」ではなく、設定ミスによる情報漏えいは利用者側の責任範囲で起きます。

> 💡 コツ: 🔴 「どこまでが事業者で、どこからが利用者か」を層で答えさせる問題が頻出です。IaaSは「仮想化基盤まで事業者、OSから上は利用者」と覚えましょう。

### 確認問題

**問1.** IaaSにおける責任共有モデルで、一般に利用者側の責任となるものはどれか。

1. データセンターの入退室管理
2. ゲストOSへのセキュリティパッチの適用
3. 物理サーバのハードウェア保守
4. 仮想化基盤（ハイパーバイザ）の脆弱性対応

<details><summary>答えと解説</summary>

正解: **2**

IaaSでは物理設備・ハードウェア・仮想化基盤までがクラウド事業者の責任で、ゲストOSから上（OSのパッチ、ミドルウェア、アプリ、各種設定）は利用者の責任です。入退室管理・物理サーバ保守・ハイパーバイザの対応はいずれも事業者側の範囲です。

</details>

**問2.** オンプレミスとクラウドを専用線などの閉域網で接続する方式の、インターネットVPNと比べた利点はどれか。

1. 構築費用と月額費用が必ず安くなる
2. 物理的な配線工事が一切不要になる
3. クラウド側のセキュリティグループ設定が不要になる
4. インターネットを経由しないため、帯域や遅延が安定し、盗聴などのリスクも低減できる

<details><summary>答えと解説</summary>

正解: **4**

閉域接続はインターネットを経由しないため通信品質（帯域・遅延）が安定し、経路上の脅威にさらされにくい点が利点です。一方でコストはインターネットVPNより高くなるのが一般的で、物理回線の敷設も必要です。また、接続方式にかかわらずセキュリティグループなどのアクセス制御設定は必要です。

</details>

**問3.** IaaSのセキュリティグループの説明として、適切なものはどれか。

1. 仮想サーバ単位で送受信の通信可否を制御する仮想ファイアウォール機能
2. クラウド利用料金をプロジェクト単位で集計する機能
3. 仮想サーバのCPU使用率を監視して自動で台数を増減する機能
4. 利用者アカウントをグループ化して権限を一括付与する機能

<details><summary>答えと解説</summary>

正解: **1**

セキュリティグループは、仮想サーバ（インスタンス）に適用し、プロトコル・ポート・送信元などの条件で通信の可否を制御する仮想ファイアウォール機能です。料金集計の機能でも、オートスケーリング（自動増減）でも、ID管理の権限グループでもありません。

</details>

**問4.** オンプレミスのシステムをIaaSへ移行する際のネットワーク設計に関する記述のうち、適切なものはどれか。

1. クラウドではIPアドレスの概念がないため、アドレス設計は不要である
2. 仮想ネットワークはすべて事業者が設定するため、利用者の設計作業はない
3. クラウド上でもサブネット分割やルーティング、通信制御の設計は利用者が行う必要がある
4. クラウドに移行すればファイアウォール相当の通信制御は不要になる

<details><summary>答えと解説</summary>

正解: **3**

IaaSの仮想ネットワークでは、アドレス空間・サブネット・ルートテーブル・セキュリティグループなどの設計と設定は利用者の仕事です。クラウドでもIPアドレスやルーティングの概念はそのまま使われ、通信制御も引き続き必要です。「クラウドだから設計不要・制御不要」はいずれも誤りです。

</details>

## 3. オーバーレイ技術（VXLANとトンネリング）

データセンターや拠点間で「離れた場所に同じL2ネットワークを広げたい」という要望に応えるのが**オーバーレイ**技術です。物理ネットワーク（**アンダーレイ**）の上に、カプセル化を使って論理ネットワーク（オーバーレイ）をかぶせます。

### トンネリングの考え方

元のパケットやフレームを別のヘッダで包んで（**カプセル化**して）運び、出口で元に戻す仕組みを**トンネリング**といいます。途中の機器は外側のヘッダしか見ないため、中身のネットワーク構成を気にせず運べます。

### VXLAN

**VXLAN**は代表的なオーバーレイ技術で、**L2のイーサネットフレームをUDP/IPでカプセル化**し、L3ネットワーク越しにL2ネットワークを延伸します。

| 項目 | VLAN | VXLAN |
|---|---|---|
| 識別子 | VLAN ID（12ビット） | **VNI（24ビット）** |
| セグメント数 | 最大4,094 | **約1,677万** |
| 延伸範囲 | L2の範囲 | L3網を越えられる |

カプセル化と解除（元に戻す処理）を行う端点を**VTEP**（VXLAN Tunnel End Point）と呼びます。

> 💡 コツ: 🟡 「VXLAN＝L2 over L3」「VNIは24ビットでVLANの4,094制限を解決」。この2点を押さえれば午前Ⅱは対応できます。アンダーレイ（物理）とオーバーレイ(論理)の2階建て構造をイメージしましょう。

### 確認問題

**問1.** VXLANの説明として、適切なものはどれか。

1. 光ファイバを波長ごとに分割して複数の通信を多重化する技術
2. 無線LANのチャネルを束ねて帯域を拡大する技術
3. L2のイーサネットフレームをUDP/IPでカプセル化し、L3ネットワーク越しにL2ネットワークを延伸する技術
4. IPパケットを暗号化して拠点間を安全に接続する技術

<details><summary>答えと解説</summary>

正解: **3**

VXLANはイーサネットフレームをUDP/IPで包んで運ぶオーバーレイ技術で、ルータを越えた先にも同じL2セグメントを広げられます。1番目は波長分割多重（WDM）、2番目は無線LANのチャネルボンディング、4番目はIPsec VPNなどの説明で、VXLAN自体に暗号化機能はありません。

</details>

**問2.** VLANと比較したVXLANの特徴として、適切なものはどれか。

1. 識別子が24ビットのVNIであり、約1,677万のセグメントを扱える
2. 識別子が12ビットに縮小され、省メモリになっている
3. セグメントの識別子を使わず、MACアドレスだけで分離する
4. セグメント数の上限はVLANと同じ4,094である

<details><summary>答えと解説</summary>

正解: **1**

VXLANの識別子VNIは24ビットで、約1,677万（2の24乗−予約分）のセグメントを識別できます。これは12ビット（最大4,094）しかないVLAN IDの不足を解決するための設計です。識別子が縮小されたり、識別子なしでMACアドレスだけで分離したりするわけではありません。

</details>

**問3.** VXLANにおいてフレームのカプセル化と解除（カプセル化を解く処理）を行う端点はどれか。

1. DHCPリレーエージェント
2. VTEP
3. デフォルトゲートウェイ
4. ルートブリッジ

<details><summary>答えと解説</summary>

正解: **2**

VTEP（VXLAN Tunnel End Point）はVXLANトンネルの端点で、送信側で元のフレームをUDP/IPでカプセル化し、受信側で解除して元のフレームに戻します。DHCPリレーはDHCP要求の中継、デフォルトゲートウェイは他ネットワーク宛て通信の出口、ルートブリッジはSTPの基準スイッチで、いずれもVXLANの端点ではありません。

</details>

**問4.** オーバーレイネットワークとアンダーレイネットワークの関係として、適切なものはどれか。

1. オーバーレイは物理配線、アンダーレイは論理構成を指す
2. 両者は同じものを指す別名である
3. アンダーレイが停止してもオーバーレイの通信は影響を受けない
4. 物理ネットワーク（アンダーレイ）の上に、カプセル化で論理ネットワーク（オーバーレイ）を構築する関係である

<details><summary>答えと解説</summary>

正解: **4**

アンダーレイは実際にパケットを運ぶ物理ネットワーク、オーバーレイはその上にトンネリングで作る論理ネットワークです。1番目は両者が逆ですし、別名でもありません。オーバーレイのパケットは実際にはアンダーレイ上を流れるため、アンダーレイが止まればオーバーレイの通信も止まります。

</details>

## 4. SDNとゼロトラスト・SASE

この章の3つのキーワードは、いずれも「ネットワークの作り方・守り方の発想転換」です。考え方レベルで押さえましょう。

### SDN（Software Defined Networking）

従来の機器は、経路を決める**制御プレーン**とパケットを転送する**データプレーン**を1台の中に持っていました。SDNはこの2つを**分離**し、制御を**SDNコントローラ**に集中させます。管理者はコントローラにポリシーを与えるだけで、多数の機器の動作をソフトウェアで一括制御できます（コントローラと機器の間のプロトコルとしてOpenFlowが知られています）。

### ゼロトラスト

従来の**境界型防御**は「社内＝安全、社外＝危険」と考え、境界のファイアウォールで守る発想でした。しかしクラウド利用やテレワークで「内と外」の境界はあいまいになりました。**ゼロトラスト**は「**暗黙に信頼できる場所はない**」を前提に、社内外を問わず**すべてのアクセスを毎回検証**（利用者認証・端末の状態確認など）してから許可する考え方です。

### SASE（Secure Access Service Edge）

**ネットワーク機能**（SD-WANなど）と**セキュリティ機能**（Webフィルタリング、CASBなど）を**クラウドサービスとして統合提供**する考え方です。どこから働いても、一度クラウド上のSASEを経由して同じポリシーで守られます。

> 💡 コツ: 🟡 SDN＝「制御と転送の分離」、ゼロトラスト＝「毎回検証」、SASE＝「NWとセキュリティをクラウドで統合」。一言定義で覚えましょう。

### 確認問題

**問1.** SDNの特徴として、最も適切なものはどれか。

1. 各ネットワーク機器が自律的に経路を決め、管理者は介入しない
2. 制御プレーンとデータプレーンを分離し、コントローラで集中制御する
3. すべての通信を物理的な専用線に置き換える
4. ネットワーク機器のOSを手作業で1台ずつ設定する

<details><summary>答えと解説</summary>

正解: **2**

SDNは経路決定などの制御プレーンを機器から分離してSDNコントローラに集中させ、機器側は転送（データプレーン）に専念させる構成です。ソフトウェアから多数の機器を一括制御できる点が利点です。各機器の自律制御や1台ずつの手作業設定は従来型の運用で、専用線化はSDNとは関係ありません。

</details>

**問2.** ゼロトラストの考え方として、適切なものはどれか。

1. 社内ネットワークからのアクセスは信頼し、認証を省略する
2. 境界のファイアウォールを強化すれば内部の対策は不要とする
3. 社内外を問わず、すべてのアクセスを毎回検証してから許可する
4. 一度認証した端末は以後すべての操作を無条件に許可する

<details><summary>答えと解説</summary>

正解: **3**

ゼロトラストは「暗黙に信頼できる場所はない」を前提に、アクセス元が社内でも社外でも、利用者認証や端末の状態確認などの検証を毎回行う考え方です。「社内だから信頼」「境界だけ守る」「一度認証すれば以後は無条件」は、いずれもゼロトラストが見直しの対象とする従来型の発想です。

</details>

**問3.** SASEの説明として、適切なものはどれか。

1. ネットワーク機能とセキュリティ機能をクラウドサービスとして統合提供する考え方
2. 社内に物理アプライアンスを集約して境界防御を強化する構成
3. 無線LANのアクセスポイントを集中管理するコントローラ製品
4. サーバの仮想マシンを別のホストへ無停止で移動させる技術

<details><summary>答えと解説</summary>

正解: **1**

SASEはSD-WANなどのネットワーク機能と、WebフィルタリングやCASBなどのセキュリティ機能をクラウド上で統合提供するモデルで、利用者がどこにいても同じポリシーを適用できます。社内アプライアンス集約はむしろ従来型の発想で、無線LANコントローラやVMのライブマイグレーションとは別の概念です。

</details>

**問4.** 境界型防御の限界が指摘されるようになった背景として、最も適切なものはどれか。

1. ファイアウォール製品の製造が終了したため
2. IPアドレスが世界的に枯渇したため
3. 境界の内側では通信速度が出なくなったため
4. クラウド利用やテレワークの普及で、守るべき資産や利用者が境界の外に広がったため
