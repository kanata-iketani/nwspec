# 第13章 ルーティング（OSPF・BGP・VRRP）

パケットが宛先ネットワークまで届く道順を決める「ルーティング」の章です。ルーティングテーブルの読み方から、OSPF・BGP・VRRP まで、午前Ⅱと午後の両方で問われる最重要分野を学びます。

## 1. ルーティングのきほん（ルーティングテーブル・ロンゲストマッチ）

ルータは、届いたパケットの**宛先 IP アドレス**を見て「次にどこへ渡すか」を決めます。その判断材料が**ルーティングテーブル（経路表）**です。

### ルーティングテーブルの例

| 宛先ネットワーク | ネクストホップ |
|---|---|
| 10.1.0.0/16 | ルータA |
| 10.1.2.0/24 | ルータB |
| 0.0.0.0/0 | ルータC |

PC が 10.1.2.5 宛のパケットを送ると、ルータはテーブルを上から照合します。10.1.0.0/16 と 10.1.2.0/24 の**両方に一致**しますが、このとき選ばれるのはプレフィックス長が長い（= 範囲が狭く、より具体的な）10.1.2.0/24 のほうです。これを**ロンゲストマッチ（最長一致）**の原則といいます。

### デフォルトルート

どの経路にも一致しなかったパケットの「最後の受け皿」が **0.0.0.0/0（デフォルトルート）**です。プレフィックス長が 0 なのですべての宛先に一致しますが、最も短い一致なので、他に一致する経路がないときだけ使われます。デフォルトルートすらなければ、ルータはパケットを**破棄**します。

> 💡 コツ：午後試験では経路表が図中に示され、「このパケットはどこへ転送されるか」を問われます。**「一致する行をすべて挙げる → いちばん /が大きい行を選ぶ」**の2段階で機械的に読みましょう。

🔴 ロンゲストマッチとデフォルトルートは、ルーティングのすべての土台です。

### 確認問題

**問1.** ルータの経路表に「192.168.0.0/16 → ルータA」「192.168.1.0/24 → ルータB」「0.0.0.0/0 → ルータC」の3行があります。宛先 192.168.1.10 のパケットはどこへ転送されるでしょう？

1. ルータA。テーブルの上の行が優先されるから
2. ルータB。一致した経路のうちプレフィックス長が最も長いから
3. ルータC。デフォルトルートが常に優先されるから
4. 3つに一致するため転送先を決められず破棄される

<details><summary>答えと解説</summary>

正解: **2**

192.168.1.10 は3行すべてに一致しますが、ロンゲストマッチの原則により、プレフィックス長が最も長い /24 の経路（ルータB）が選ばれます。経路選択は記載順ではなくプレフィックス長で決まり、デフォルトルート（/0）は最も短い一致なので優先度は最低です。複数一致はエラーではなく、最長の1つを選ぶのがルールです。

</details>

**問2.** デフォルトルートの表記として正しいものはどれでしょう？

1. 255.255.255.255/32
2. 127.0.0.1/8
3. 0.0.0.0/0
4. 192.168.0.0/16

<details><summary>答えと解説</summary>

正解: **3**

デフォルトルートはプレフィックス長 0 の 0.0.0.0/0 で、すべての宛先アドレスに一致します。255.255.255.255 はブロードキャスト、127.0.0.1 はループバック（自分自身）、192.168.0.0/16 はプライベートアドレスの一範囲であり、いずれも「最後の受け皿」の意味を持ちません。

</details>

**問3.** 経路選択で「ロンゲストマッチ（最長一致）」が採用されているのはなぜでしょう？

1. プレフィックスが長い経路ほど宛先の範囲が狭く、より具体的な指定だと考えられるから
2. プレフィックスが長い経路ほど通信速度が速いから
3. テーブルの検索時間を最短にできるから
4. プレフィックスが長い経路ほど新しく登録されたものだから

<details><summary>答えと解説</summary>

正解: **1**

/24 は /16 より範囲が狭く、「その宛先についてより詳しく知っている」経路といえるため、具体的な経路を優先するのが合理的です。プレフィックス長は回線速度や登録順とは無関係で、むしろ最長一致の検索はテーブル検索を複雑にする（速くはしない）仕組みです。

</details>

**問4.** ルータに届いたパケットの宛先が経路表のどの行にも一致せず、デフォルトルートも設定されていない場合、ルータはどう動作するでしょう？

1. 全ポートにフラッディングして宛先を探す
2. 送信元に送り返して再送を促す
3. 一時的に保持し、経路が登録されるまで待つ
4. パケットを破棄し、送信元に ICMP で宛先到達不能を通知する

<details><summary>答えと解説</summary>

正解: **4**

転送先が分からないパケットは破棄され、ICMP の宛先到達不能（Destination Unreachable）メッセージが送信元に返されます。フラッディングはルータではなく L2 スイッチが未学習の MAC アドレス宛フレームに対して行う動作で、ルータはパケットを保持して待つことも、そのまま送り返すこともしません。

</details>

## 2. 静的ルーティングと動的ルーティングの使い分け

経路表に行を登録する方法は2つあります。管理者が手で書く**静的ルーティング**と、ルータ同士がプロトコル（OSPF・BGP など）で経路情報を交換して自動登録する**動的ルーティング**です。

### 比較表

| 観点 | 静的 | 動的 |
|---|---|---|
| 設定 | 1行ずつ手入力 | プロトコルを有効化 |
| 障害時 | 自動では切り替わらない | 代替経路へ自動で収束 |
| 負荷 | 帯域・CPU を消費しない | 経路情報の交換で消費 |
| 向く規模 | 小規模・経路が少ない | 中〜大規模・経路が多い |

### 使い分けの定石

出口がインターネット側の1本しかない拠点（**スタブネットワーク**）なら、細かい経路を覚える必要はなく、**デフォルトルートを静的に1行**書けば十分です。一方、拠点が多くて経路網が複雑なネットワークや、回線障害時に自動で迂回させたいネットワークでは動的ルーティングを使います。

実務では両者の併用が普通です。🟡 たとえば「社内の経路は OSPF で自動交換し、インターネット向けはデフォルトルートを静的に設定」という構成は午後試験の題材ネットワークでも頻出です。

> 💡 コツ：「経路が増えたり変わったりするか？」「障害時に自動で迂回したいか？」の2つが YES なら動的、NO なら静的と覚えましょう。

### 確認問題

**問1.** 動的ルーティングではなく静的ルーティングを選ぶ利点として、最も適切なものはどれでしょう？

1. 回線障害時に代替経路へ自動で切り替わる
2. ネットワークの規模が大きくなっても設定の手間が増えない
3. 経路情報の交換が発生せず、動作が単純で予測しやすい
4. 経路の追加や変更が自動で経路表に反映される

<details><summary>答えと解説</summary>

正解: **3**

静的ルーティングは管理者が書いた経路だけを使うため、経路交換のトラフィックや CPU 負荷がなく、挙動が単純で予測しやすいのが利点です。自動切替・自動反映はいずれも動的ルーティングの特長であり、静的では経路が増えるほど手入力の手間が増えるため、大規模化に強いともいえません。

</details>

**問2.** 動的ルーティングの採用が適している状況はどれでしょう？

1. 拠点間の経路が多数あり、回線障害時には自動で迂回経路に切り替えたい
2. ルータの CPU やメモリの消費を極力抑えたい
3. 経路が今後も増えない小規模ネットワークで、設定を最小限にしたい
4. ルータ間で一切の制御用トラフィックを流したくない

<details><summary>答えと解説</summary>

正解: **1**

経路が多く、障害時の自動迂回（収束）が求められる環境こそ動的ルーティングの出番です。動的ルーティングは経路情報の交換に帯域や CPU を使うため、残り3つのような「負荷や制御トラフィックを抑えたい」「経路が固定の小規模環境」という条件には静的ルーティングのほうが適します。

</details>

**問3.** インターネットへの出口が1本しかないスタブネットワークの拠点ルータに対する、最も定石的な経路設定はどれでしょう？

1. BGP を有効にしてインターネットの全経路を受信する
2. 出口へ向けたデフォルトルートを静的に1行設定する
3. インターネット上の宛先ごとに静的経路を列挙する
4. OSPF をインターネット側の ISP ルータとの間で動作させる

<details><summary>答えと解説</summary>

正解: **2**

出口が1つなら、どの宛先でも転送先は同じなので、デフォルトルート1行で足ります。インターネットの全経路（数十万件）を受信・列挙するのは小規模拠点のルータには過剰で、ISP との間で OSPF を動かす構成も一般的ではありません。「出口が1本ならデフォルトルート」は設計の定石です。

</details>

## 3. OSPF（エリア・LSA・コスト・DR/BDR）

**OSPF** は社内ネットワークで最も使われる動的ルーティングプロトコルで、**リンクステート型**に分類されます。動作の流れを追ってみましょう。

1. 各ルータは Hello パケットで隣のルータを見つけ、ネイバー関係を結ぶ
2. 自分のリンク情報を **LSA（リンクステート広告）**として全ルータに配布（フラッディング）する
3. 全ルータが同じ **LSDB（リンクステートデータベース）**＝ネットワークの地図を持つ
4. 各ルータが地図上で**最短経路を自分で計算**（ダイクストラ法）して経路表を作る

### コスト

経路の良し悪しは**コスト**（小さいほど良い）で比較します。コストは**基準帯域 ÷ インタフェースの帯域**で求めるため、**帯域が大きい回線ほどコストが小さく**なり、経路のコストは出力インタフェースの合計で比べます。

### エリアと DR/BDR

ネットワークが大きくなると LSDB が肥大化するため、**エリア**に分割します。中心には必ず**エリア0（バックボーンエリア）**を置き、他のエリアはエリア0に接続します。また、スイッチに多数のルータがつながるセグメントでは、全ルータ同士が総当たりで LSA を交換すると非効率なので、代表の **DR（指定ルータ）**と予備の **BDR** を選出し、各ルータは DR/BDR とだけ情報交換します。

> 💡 コツ：🔴「全員が同じ地図を持ち、各自で最短経路を計算する」がリンクステート型の本質です。午後ではコスト値の調整で経路を制御する問題が頻出です。

### 確認問題

**問1.** OSPF のコストについて、正しい説明はどれでしょう？

1. ホップ数（経由するルータの台数）がそのままコストになる
2. 管理者は値を変更できず、常に自動計算される
3. 値が大きい経路ほど優先される
4. 基準帯域をインタフェースの帯域で割って求め、帯域が大きいほど小さくなる

<details><summary>答えと解説</summary>

正解: **4**

OSPF のコストは「基準帯域 ÷ インタフェース帯域」で求めるため、高速な回線ほどコストが小さく、コストの合計が最小の経路が選ばれます。ホップ数をメトリックにするのは RIP です。またコストは管理者が手動で設定でき、午後試験では経路制御の手段としてよく登場します。

</details>

**問2.** OSPF のエリア0（バックボーンエリア）について、正しいものはどれでしょう？

1. 最も規模の小さいエリアに割り当てる番号である
2. すべてのエリアはエリア0に接続する必要があり、エリア間の通信はエリア0を経由する
3. エリア0は予備用で、通常のトラフィックは流れない
4. エリアは最大2つまでしか作成できない

<details><summary>答えと解説</summary>

正解: **2**

OSPF はエリア0をバックボーン（背骨）とする階層設計を採り、他のエリアはエリア0に接続し、エリア間の経路情報はエリア0を介して伝わります。エリア0は規模ではなく役割で決まる中心エリアで、予備ではなく通信の中継の要です。エリア数に2つまでという制限もありません。

</details>

**問3.** マルチアクセスネットワーク（1つのスイッチに複数の OSPF ルータが接続された構成）で DR/BDR を選出する目的はどれでしょう？

1. LSA の交換相手を DR/BDR に集約し、ルータ間の隣接関係の数を減らすため
2. 障害時にパケットの転送先を DR に一本化するため
3. セグメント内のルータに IP アドレスを自動配布するため
4. DR がセグメント全体の経路計算を代行し、他のルータの計算を不要にするため

<details><summary>答えと解説</summary>

正解: **1**

全ルータが総当たりで LSA を交換すると隣接関係が組合せ的に増えるため、代表の DR（と予備の BDR）に交換相手を集約して効率化します。DR はあくまで LSA 交換の代表であり、パケット転送の一本化や IP アドレス配布はしません。経路計算は OSPF の原則どおり各ルータが自分で行います。

</details>

**問4.** リンクステート型である OSPF の経路決定のしかたとして、正しいものはどれでしょう？

1. 隣のルータから経路表そのものを受け取り、ホップ数を加算して採用する
2. 管理者が全ルータの経路表を手動で同期する
3. 各ルータが LSA の交換で同一の LSDB（ネットワークの地図）を持ち、自分を起点とする最短経路を各自で計算する
4. DR が計算した最短経路ツリーを全ルータが受け取って使う

<details><summary>答えと解説</summary>

正解: **3**

リンクステート型は「全員が同じ地図（LSDB）を持ち、各自がダイクストラ法で最短経路を計算する」方式です。隣から経路表を受け取ってホップ数を足すのは RIP などのディスタンスベクタ型の動作です。手動同期は動的ルーティングの意味がなく、DR の役割は LSA 交換の集約であって経路計算の代行ではありません。

</details>

## 4. BGP（AS・eBGP/iBGP・パス属性の初歩）

インターネットは、ISP や大企業など**ひとつの管理主体が運用するネットワークのまとまり = AS（自律システム）**が相互接続してできています。各 AS には AS 番号が割り当てられ、**AS 同士の経路交換に使うのが BGP** です。OSPF が「社内の道案内」なら、BGP は「世界地図の道案内」です。

### eBGP と iBGP

| 種類 | 接続相手 | 主な用途 |
|---|---|---|
| **eBGP** | 異なる AS のルータ | ISP との接続・AS 間の経路交換 |
| **iBGP** | 同じ AS 内のルータ | eBGP で学んだ経路を AS 内に伝える |

BGP は TCP（ポート 179）でピア（相手）とコネクションを張り、経路を交換します。

### パス属性で経路を選ぶ

BGP は帯域ではなく、経路に付く**パス属性**で最適経路を選びます。代表は次の2つです。

- **AS_PATH**：その経路が経由してきた AS 番号の並び。**短いほうが優先**。また、受け取った経路の AS_PATH に自分の AS 番号があれば破棄するので、**経路のループを防げます**
- **LOCAL_PREF**：AS 内で共有する優先度で、**大きいほうが優先**。複数の出口（ISP）のどちらから出るかの制御に使います

> 💡 コツ：🟡 まずは「AS 間 = eBGP、AS 内への伝搬 = iBGP」「AS_PATH は短い勝ち・ループ防止」「LOCAL_PREF は大きい勝ち・出口選択」の3点を押さえれば、午前Ⅱの BGP 問題の多くに対応できます。

### 確認問題

**問1.** eBGP と iBGP の説明として、正しいものはどれでしょう？

1. eBGP は暗号化あり、iBGP は暗号化なしという違いである
2. eBGP は異なる AS 間で、iBGP は同一 AS 内で経路を交換する
3. eBGP は IPv6 用、iBGP は IPv4 用のプロトコルである
4. eBGP は動的、iBGP は静的に経路を設定する方式である

<details><summary>答えと解説</summary>

正解: **2**

e は external（AS の外）、i は internal（AS の中）を意味し、eBGP は ISP との接続など異なる AS 間で、iBGP は eBGP で学んだ経路を同じ AS 内の他のルータに伝えるために使います。両者は同じ BGP で、暗号化の有無・IP バージョン・静的か動的かの違いではありません。

</details>

**問2.** BGP はどの場面で使われるプロトコルでしょう？

1. 1台の PC に IP アドレスを自動設定する場面
2. 同一セグメント内で MAC アドレスを解決する場面
3. ISP 同士の相互接続など、AS 間で経路情報を交換する場面
4. 小規模オフィス内のフロア間ルーティング

<details><summary>答えと解説</summary>

正解: **3**

BGP はインターネットを構成する AS 同士が経路を交換するためのプロトコルで、ISP 間や企業とISP のマルチホーム接続で使われます。IP アドレスの自動設定は DHCP、MAC アドレス解決は ARP の仕事で、小規模な社内ルーティングには OSPF や静的ルーティングを使うのが一般的です。

</details>

**問3.** BGP の AS_PATH 属性の役割として、正しいものはどれでしょう？

1. 経路の帯域幅を表し、大きいほど優先される
2. 経路の暗号鍵を格納する
3. ピアとの TCP コネクションの状態を表す
4. 経由した AS 番号の並びを保持し、自 AS 番号を含む経路を破棄することでループを防ぐ

<details><summary>答えと解説</summary>

正解: **4**

AS_PATH には経路が通ってきた AS 番号が順に記録され、短いほうが優先されます。さらに、受信した経路の AS_PATH に自分の AS 番号が含まれていれば「一周して戻ってきた経路」と分かるので破棄し、ループを防止します。帯域・暗号鍵・TCP の状態を表す属性ではありません。

</details>

**問4.** 2つの ISP に接続した AS が「外向きの通信はどちらの ISP から出すか」を AS 内部の方針として制御したいとき、主に使うパス属性はどれでしょう？

1. LOCAL_PREF（値が大きい経路を優先）
2. TTL（値が小さい経路を優先）
3. OSPF コスト（値が小さい経路を優先）
4. MAC アドレス（値が小さい経路を優先）

<details><summary>答えと解説</summary>

正解: **1**

LOCAL_PREF は AS 内で共有される優先度で、値が大きい経路が優先されるため、優先したい ISP 経由の経路に大きい値を付ければ出口を制御できます。TTL はパケットの生存時間、OSPF コストは OSPF の内部メトリック、MAC アドレスは L2 の識別子であり、いずれも BGP のパス属性ではありません。

</details>

## 5. VRRP（仮想ルータ・マスタ/バックアップ・切替）

PC のデフォルトゲートウェイに設定したルータが故障すると、その PC は外部と通信できなくなります。そこでルータを2台用意し、**1つの「仮想ルータ」に見せかける**のが **VRRP** です。

### しくみ

- 2台のルータは共通の**仮想 IP アドレス**と**仮想 MAC アドレス**を持つ仮想ルータを構成します。PC のデフォルトゲートウェイには、実機のアドレスではなく**仮想 IP アドレス**を設定します
- **プライオリティ値が大きい**ほうが**マスタ**になり、実際のパケット転送を担当します。もう1台は**バックアップ**として待機します
- マスタは「生きている」ことを知らせる **VRRP 広告（advertisement）**を定期的（既定で1秒間隔）にマルチキャストで送り続けます

### 切替（フェールオーバー）の流れ

1. マスタが故障し、広告が止まる
2. バックアップは「一定時間広告が来ない」ことで故障を検知し、自分がマスタに昇格する
3. 新マスタが**同じ仮想 IP・仮想 MAC** を引き継いで転送を開始する

PC から見るとゲートウェイの IP も MAC も変わらないため、**PC 側は設定変更も ARP テーブルの更新も不要**のまま通信が続きます。

> 💡 コツ：🔴 午後では「切替に何秒かかるか」「なぜ PC は無変更でよいか」が頻出です。「広告が途絶える → バックアップが昇格 → 仮想 MAC ごと引き継ぐ」の流れを言葉で説明できるようにしましょう。

### 確認問題

**問1.** VRRP を使う構成で、PC のデフォルトゲートウェイに設定すべきアドレスはどれでしょう？

1. マスタルータの実 IP アドレス
2. バックアップルータの実 IP アドレス
3. 仮想ルータの仮想 IP アドレス
4. DNS サーバの IP アドレス

<details><summary>答えと解説</summary>

正解: **3**

PC には2台のルータが共有する仮想 IP アドレスを設定します。こうすれば、どちらのルータがマスタになっても PC の設定変更は不要です。マスタの実 IP を設定するとそのルータの故障時に通信が止まり、冗長化の意味がなくなります。バックアップの実 IP や DNS サーバはゲートウェイの役割を果たしません。

</details>

**問2.** バックアップルータは、マスタルータの障害をどのように検知するでしょう？

1. マスタが定期送信する VRRP 広告が一定時間届かなくなったことで検知する
2. PC からの障害報告パケットを受信して検知する
3. マスタが故障直前に送る停止通知を受信して検知する
4. 管理者が手動でバックアップに切替コマンドを入力する

<details><summary>答えと解説</summary>

正解: **1**

マスタは既定で1秒間隔の VRRP 広告を送り続け、バックアップはそれが一定時間途絶えたことで障害と判断して自動昇格します。突然の電源断では故障通知を送る余裕がないため「通知が来たら切替」ではなく「来なくなったら切替」という設計になっています。PC は VRRP に関与せず、手動切替では自動冗長化になりません。

</details>

**問3.** VRRP が実 MAC アドレスではなく仮想 MAC アドレスを使う利点はどれでしょう？

1. MAC アドレスを暗号化して盗聴を防げる
2. 切替後も PC の ARP テーブルの書き換えが不要で、通信が途切れにくい
3. フレームサイズを小さくして帯域を節約できる
4. スイッチの MAC アドレス学習を不要にできる

<details><summary>答えと解説</summary>

正解: **2**

PC の ARP テーブルには「仮想 IP → 仮想 MAC」の対応が記録されており、新マスタが同じ仮想 MAC を引き継ぐため、切替後も PC は何も更新せずに同じ宛先 MAC へ送り続けられます。もし実 MAC を使うと、切替のたびに全端末の ARP テーブル更新を待つ必要が生じます。暗号化・フレーム縮小・MAC 学習の省略といった効果はありません。

</details>

**問4.** VRRP のプライオリティについて、正しいものはどれでしょう？

1. 値が小さいルータがマスタになる
2. 全ルータで同じ値に設定しなければならない
3. プライオリティはルータが毎回ランダムに決める
4. 値が大きいルータがマスタになる

<details><summary>答えと解説</summary>

正解: **4**

VRRP ではプライオリティ値の大きいルータがマスタに選ばれます。どちらをマスタにしたいかに応じて管理者が異なる値を設定するのが基本で、ランダムに決まるものではありません。同じ値にする決まりはなく、同値の場合は IP アドレスの大小などで決まるため、意図したマスタを選ぶには値に差を付けます。

</details>
