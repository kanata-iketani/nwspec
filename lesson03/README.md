# 第3章 アルゴリズムとプログラミングのきほん

プログラムの考え方（アルゴリズム）とデータの持ち方（データ構造）を学ぶ章です。午前Ⅰの定番分野であると同時に、計算量やキューの考え方はネットワーク機器の動作理解にもつながります。

## 1. アルゴリズムとは・流れ図と擬似言語の読み方

### アルゴリズム＝解き方の手順書

**アルゴリズム**とは、問題を解くための手順を、誰が実行しても同じ結果になるように明確に書いたものです。料理のレシピにたとえると、「材料（入力）」から「完成品（出力）」までの手順を、迷いなく実行できる粒度で書いたものにあたります。

### 流れ図（フローチャート）の記号

| 記号 | 意味 |
|---|---|
| 長方形 | 処理 |
| ひし形 | 条件分岐（判断） |
| 平行四辺形 | データの入出力 |
| 角の丸い長方形 | 開始・終了 |

### 擬似言語の読み方

IPA の試験では、特定のプログラミング言語に依存しない**擬似言語**でアルゴリズムが示されます。読むときの軸は3つの基本制御構造です。

- **順次**：上から順に実行する
- **選択**：if（もし〜なら）で枝分かれする
- **繰返し**：while や for で同じ処理を繰り返す

> 💡 コツ：擬似言語は眺めるだけでは身につきません。変数の値を紙に書き出しながら1行ずつ実行をなぞる「トレース」が最短の上達法です。

🟡 どんな複雑なプログラムも「順次・選択・繰返し」の3つの組み合わせでできています。

### 確認問題

**問1.** 流れ図（フローチャート）でひし形の記号が表すものはどれでしょう？

1. 処理
2. 条件分岐（判断）
3. 開始・終了
4. データの入出力

<details><summary>答えと解説</summary>

正解: **2**

ひし形は条件によって処理の流れが枝分かれする「判断」を表します。処理は長方形、開始・終了は角の丸い長方形、データの入出力は平行四辺形です。流れ図の読み取り問題では、まずひし形で分岐条件を確認するのが定石です。

</details>

**問2.** プログラムの3つの基本制御構造の組み合わせとして、正しいものはどれでしょう？

1. 入力・計算・出力
2. 宣言・代入・参照
3. 順次・選択・繰返し
4. コンパイル・実行・デバッグ

<details><summary>答えと解説</summary>

正解: **3**

どんなプログラムも、上から順に実行する「順次」、条件で枝分かれする「選択」、同じ処理を繰り返す「繰返し」の3つで構成できます。入力・計算・出力は処理の内容の分類、宣言・代入・参照は変数の操作、コンパイル以降は開発作業の工程であり、制御構造の名前ではありません。

</details>

**問3.** 擬似言語の問題を解くときの「トレース」とは、どのような作業でしょう？

1. 変数の値の変化を書き出しながら、プログラムを1行ずつ順になぞること
2. プログラムの全行を暗記すること
3. プログラムを実際のプログラミング言語に書き換えること
4. プログラムの行数を数えて複雑さを見積もること

<details><summary>答えと解説</summary>

正解: **1**

トレースは、紙などに変数の値を書き出しながら実行の流れを1行ずつ追う作業で、擬似言語問題の基本の解き方です。暗記や別言語への書き換えは試験では求められず、行数を数えても動作は分かりません。繰返しのたびに値がどう変わるかを表にするのがコツです。

</details>

**問4.** アルゴリズムの説明として、最も適切なものはどれでしょう？

1. コンピュータの機種ごとに異なる電気信号の仕様
2. プログラムの実行結果を予測できなくする仕組み
3. 特定のプログラミング言語でしか書けない命令の集まり
4. 問題を解くための手順を、実行する人や機械によらず同じ結果になるように明確化したもの

<details><summary>答えと解説</summary>

正解: **4**

アルゴリズムは「解き方の手順書」であり、誰が実行しても同じ入力からは同じ結果が得られるよう明確に書かれている必要があります。特定の言語に依存せず、流れ図や擬似言語でも表現できます。電気信号の仕様や、結果を予測不能にする仕組みという説明は誤りです。

</details>

## 2. 探索と整列・計算量（O記法）

### 探索：目的のデータを見つける

- **線形探索**：先頭から1件ずつ順に調べる。どんな並びでも使えるが、件数に比例して遅くなる
- **二分探索**：**整列済み**のデータ限定。真ん中の値と比べて探す範囲を半分に絞る、を繰り返す。1,000件でも約10回の比較で見つかる

### 整列：データを並べ替える

- **バブルソート**：隣どうしを比較して入れ替える。単純だが遅い
- **クイックソート**：基準値より小さいグループと大きいグループに分割する、を繰り返す。実用上高速で広く使われる

### O記法（オーダー）

データ件数 n が増えたとき、処理時間がどんな勢いで増えるかを表す記法です。

| 記法 | 勢い | 代表例 |
|---|---|---|
| O(log n) | ほとんど増えない | 二分探索 |
| O(n) | 件数に比例 | 線形探索 |
| O(n log n) | 比例よりやや上 | クイックソートの平均 |
| O(n²) | 件数の2乗 | バブルソート |

> 💡 コツ：二分探索が O(log n) なのは「1回比べるたびに候補が半分になる」から。「2を何回掛けると n になるか」の回数が log₂n です。

🔴 「二分探索は整列済みが前提」という条件と、各アルゴリズムのオーダーは午前の超定番です。

### 確認問題

**問1.** 二分探索を使うための前提条件はどれでしょう？

1. データがあらかじめ整列されていること
2. データの件数が奇数であること
3. データがすべて整数であること
4. データに重複がないこと

<details><summary>答えと解説</summary>

正解: **1**

二分探索は「真ん中と比べて、目的の値が左右どちらの半分にあるか」を判断するため、データが整列済みであることが必須です。件数の偶奇やデータ型は関係なく、大小比較ができれば整数以外でも使えます。重複があっても探索自体は可能です。

</details>

**問2.** n 件のデータに対する線形探索の計算量を O 記法で表すとどれでしょう？

1. O(1)
2. O(log n)
3. O(n)
4. O(n²)

<details><summary>答えと解説</summary>

正解: **3**

線形探索は先頭から順に調べるため、比較回数は最悪で n 回、平均でも件数に比例します。よって O(n) です。O(1) は件数によらず一定時間、O(log n) は二分探索、O(n²) はバブルソートなどの計算量です。

</details>

**問3.** 整列済みの 1,024 件のデータから二分探索で目的の値を探すとき、最大の比較回数に最も近いものはどれでしょう？

1. 32回
2. 100回
3. 512回
4. 10回

<details><summary>答えと解説</summary>

正解: **4**

二分探索は1回の比較で候補が半分になります。1,024 → 512 → 256 → 128 → 64 → 32 → 16 → 8 → 4 → 2 → 1 と、10回の半減で1件に絞れます（2の10乗 = 1,024）。つまり log₂1024 = 10 です。512回は半減1回分、32回は 2 の5乗との混同で、100回に根拠はありません。

</details>

**問4.** バブルソートの平均的な計算量を O 記法で表すとどれでしょう？

1. O(log n)
2. O(n²)
3. O(n)
4. O(n log n)

<details><summary>答えと解説</summary>

正解: **2**

バブルソートは隣どうしの比較・交換を全体にわたって繰り返すため、比較回数はおよそ n×n に比例し O(n²) です。O(n log n) はクイックソートの平均などより高速な整列の計算量、O(n) は線形探索、O(log n) は二分探索の計算量です。

</details>

## 3. データ構造（配列・リスト・スタック・キュー・木）

### データの「入れ物」を使い分ける

| 構造 | 特徴 | たとえ |
|---|---|---|
| 配列 | 番号（添字）で一発アクセスできるが、途中への挿入・削除が苦手 | 番号付きロッカー |
| リスト | 各要素が次の要素の場所を指す。挿入・削除は得意だが、n 番目を見るには先頭からたどる | 数珠つなぎ |
| スタック | **後入れ先出し（LIFO）**。push で積み、pop で上から取り出す | 積み上げた皿 |
| キュー | **先入れ先出し（FIFO）**。入れた順に取り出される | レジの行列 |
| 木（ツリー） | 階層構造。2分探索木では「左の子 < 親 < 右の子」 | 組織図 |

### スタックとキューはネスペでも現役

ブラウザの「戻る」ボタンはスタック、ルータやスイッチがパケットを一時的にためるバッファはキューの考え方そのものです。データ構造は本編のネットワーク機器の動作理解にもつながります。

> 💡 コツ：LIFO と FIFO は混同しがちです。「スタック＝皿の山（最後に置いた皿を上から取る）」「キュー＝行列（先に並んだ人から出る）」のイメージで固定しましょう。

🔴 スタック（LIFO）とキュー（FIFO）の区別は午前の最頻出テーマのひとつです。

### 確認問題

**問1.** 空のスタックに A、B、C の順に push し、その後 pop を2回行いました。取り出された順序はどれでしょう？

1. A、B
2. A、C
3. B、C
4. C、B

<details><summary>答えと解説</summary>

正解: **4**

スタックは後入れ先出し（LIFO）なので、最後に積んだものから取り出されます。積んだ状態は下から A、B、C で、1回目の pop で C、2回目で B が出ます。A、B の順になるのは先入れ先出しのキューの動作です。

</details>

**問2.** キューの特徴として、適切なものはどれでしょう？

1. 最後に入れたデータが最初に取り出される
2. 最初に入れたデータが最初に取り出される
3. 添字を指定して任意の位置のデータを直接取り出せる
4. データが自動的に昇順に整列される

<details><summary>答えと解説</summary>

正解: **2**

キューは先入れ先出し（FIFO）で、レジの行列のように入れた順に取り出されます。最後に入れたものが先に出るのはスタック（LIFO）です。添字による直接アクセスは配列の特徴で、キューに自動整列の機能はありません。

</details>

**問3.** 配列の特徴として、適切なものはどれでしょう？

1. 添字を指定すれば要素に直接アクセスできるが、途中への要素の挿入には後続要素の移動が必要
2. 要素の挿入・削除はつなぎ替えだけで済むが、n 番目の要素へは先頭からたどる必要がある
3. 後入れ先出しでデータを管理する
4. 親子関係のある階層構造でデータを管理する

<details><summary>答えと解説</summary>

正解: **1**

配列は要素がメモリ上に連続して並ぶため添字で直接アクセスできますが、途中に挿入するには後ろの要素を1つずつずらす必要があります。つなぎ替えで挿入・削除できるのは連結リスト、後入れ先出しはスタック、階層構造は木の特徴です。

</details>

**問4.** 連結リストが配列より有利な点はどれでしょう？

1. n 番目の要素に添字で直接アクセスできる
2. 要素が必ずメモリ上に連続して配置される
3. 要素の挿入・削除が、前後のつなぎ替えだけで行える
4. 使用するメモリ量が常に配列より少ない

<details><summary>答えと解説</summary>

正解: **3**

連結リストは各要素が次の要素の場所（ポインタ）を持つため、挿入・削除はつなぎ替えだけで済み、要素の大移動が不要です。一方、直接アクセスや連続配置は配列の特徴です。リストはポインタの分だけ余分な領域を使うので、メモリ量で常に有利というのも誤りです。

</details>

## 4. 文字コードとデータ表現（ASCII・UTF-8・浮動小数点）

### 文字も結局は 0 と 1

コンピュータは文字をそのまま持てないので、文字ごとに番号を割り当てて扱います。この対応の決まりが**文字コード**です。

| 文字コード | 特徴 |
|---|---|
| ASCII | 英数字と記号を7ビット（128種類）で表す最古参の体系 |
| UTF-8 | Unicode（世界中の文字に番号を付けた体系）の代表的な符号化方式。英数字は1バイト、日本語の文字はおおむね3バイトの**可変長**。ASCII と互換性があり、Web で最も広く使われる |

**文字化け**は、書いた側と読む側で文字コードの解釈が食い違うことで起きます。

### 浮動小数点ざっくり

コンピュータは小数を「仮数 × 基数の指数乗」という形（例：1.25 × 2³）で表します。これが**浮動小数点数**です。有限のビット数に丸めて格納するため**誤差**が出ることがあり、0.1 のような10進で切りのよい数でも、2進数では無限に続く小数になります。「浮動小数点には誤差がつきもの」と覚えておけば十分です。

> 💡 コツ：UTF-8 は HTTP や国際化ドメイン名など本編でも顔を出します。「ASCII 互換・可変長」の2点をセットで覚えましょう。

🟡 「ASCII は英数字を7ビットで」「UTF-8 は可変長で ASCII 互換」を押さえれば午前Ⅰは十分です。

### 確認問題

**問1.** UTF-8 の説明として、適切なものはどれでしょう？

1. ASCII と互換性があり、文字によってバイト数が変わる可変長の符号化方式である
2. すべての文字を固定の2バイトで表す方式である
3. 日本語専用に設計され、英数字は表現できない
4. 7ビットで128種類の文字だけを表す方式である

<details><summary>答えと解説</summary>

正解: **1**

UTF-8 は Unicode の符号化方式のひとつで、英数字は1バイト（ASCII と同じ値）、日本語はおおむね3バイトという可変長です。固定2バイトではなく、日本語専用でもありません。7ビット128種類は ASCII の説明です。

</details>

**問2.** ASCII の説明として、適切なものはどれでしょう？

1. 世界中のあらゆる文字に番号を割り当てた体系である
2. 画像データを文字に変換する方式である
3. 日本語の漢字を表すために作られた文字コードである
4. 英数字や記号を7ビットで表す文字コードである

<details><summary>答えと解説</summary>

正解: **4**

ASCII は英数字・記号・制御文字を7ビット（128種類）で表す、最も基本的な文字コードです。世界中の文字を集めた体系は Unicode の説明で、ASCII に漢字は含まれません。画像を文字に変換する方式という説明も誤りです。

</details>

**問3.** いわゆる「文字化け」が起きる主な原因はどれでしょう？

1. 文字数が多すぎてメモリが不足した
2. 文字データを書いた側と読む側で、文字コードの解釈が食い違っている
3. 通信回線の速度が遅すぎる
4. 文字データが暗号化されている

<details><summary>答えと解説</summary>

正解: **2**

文字はコード（番号）として保存・送信されるため、書いた側と読む側が異なる文字コードで解釈すると別の文字に見えてしまいます。これが文字化けです。メモリ不足や回線速度は化けの原因ではなく、暗号化されたデータはそもそも復号しなければ読めないので文字化けとは区別されます。

</details>

**問4.** 浮動小数点数の性質として、適切なものはどれでしょう？

1. 整数の計算よりも常に高速である
2. 10進数の小数はすべて誤差なく表現できる
3. 有限のビット数に丸めて格納するため、誤差が生じることがある
4. 負の数は表現できない

<details><summary>答えと解説</summary>

正解: **3**

浮動小数点数は仮数と指数の形で有限のビット数に丸めて格納するため、誤差が生じることがあります。例えば10進の 0.1 は2進数では無限に続く小数になり、正確には格納できません。速度が常に速いとは言えず、符号を持つので負の数も表現できます。

</details>
