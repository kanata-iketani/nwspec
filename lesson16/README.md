# 第16章 DHCP・NAT・NAPT

IP アドレスを自動配布する DHCP と、プライベートアドレスをグローバルアドレスに変換する NAT・NAPT の章です。DORA の4ステップ、リレーエージェント、変換テーブルの読み方、NAT 越えの問題まで、午後の構成図読解に欠かせない知識を学びます。

## 1. DHCP のしくみ（DORA の4ステップ・リース）

PC をネットワークにつなぐと自動で IP アドレスが使えるのは、**DHCP** のおかげです。起動直後の PC はまだ IP アドレスを持たず、DHCP サーバの場所も知りません。そこで**ブロードキャスト**から始まる4ステップ（頭文字で **DORA**）でアドレスを借ります。

### DORA の4ステップ

| # | メッセージ | 向き | 意味 |
|---|---|---|---|
| 1 | **D**iscover | PC → 全体（ブロードキャスト） | 「DHCP サーバはいませんか」 |
| 2 | **O**ffer | サーバ → PC | 「この IP アドレスはどうですか」 |
| 3 | **R**equest | PC → 全体（ブロードキャスト） | 「その IP アドレスをください」 |
| 4 | **A**ck | サーバ → PC | 「確定です。使ってよいです」 |

Request もブロードキャストなのは、複数のサーバから Offer をもらった場合に「どの提案を選んだか」を**全サーバに知らせる**ためです。DHCP は UDP（サーバ 67 番・クライアント 68 番）を使います。

### リース（貸与）

配布されたアドレスは**リース期間**つきの「貸与」です。PC はリース期間の**半分が過ぎた時点**で、サーバに**延長（更新）を要求**します。更新できずに期限が切れると、そのアドレスは使えません。また DHCP は IP アドレスのほか、**サブネットマスク・デフォルトゲートウェイ・DNS サーバ**などの設定もまとめて配布します。

> 💡 コツ：🔴 D と R がブロードキャストである理由（まだ相手を特定できない/選択結果を全員に伝える）は、次チャプターのリレーエージェントの伏線です。

### 確認問題

**問1.** DHCP でアドレスを取得するときの4つのメッセージの正しい順序はどれでしょう？

1. Offer → Discover → Ack → Request
2. Discover → Offer → Request → Ack
3. Request → Ack → Discover → Offer
4. Discover → Request → Offer → Ack

<details><summary>答えと解説</summary>

正解: **2**

クライアントの Discover（サーバ探し）、サーバの Offer（アドレス提案）、クライアントの Request（提案の受諾要求）、サーバの Ack（確定）の順で、頭文字から DORA と覚えます。提案（Offer）は探索（Discover）の後、確定(Ack)は要求（Request）の後という会話の流れを押さえれば、他の並びはあり得ないと分かります。

</details>

**問2.** DHCP Discover がブロードキャストで送信されるのはなぜでしょう？

1. ブロードキャストのほうがユニキャストより高速に届くから
2. セグメント内の全 PC に新しい端末の参加を通知するため
3. クライアントはまだ自分の IP アドレスを持たず、DHCP サーバの IP アドレスも知らないため
4. DHCP サーバが複数あるとエラーになることを検出するため

<details><summary>答えと解説</summary>

正解: **3**

起動直後のクライアントは自分のアドレスも相手（サーバ）のアドレスも知らないため、宛先を特定するユニキャストは使えず、セグメント全体に届くブロードキャストで呼びかけるしかありません。ブロードキャストが速いわけではなく、他の PC への参加通知が目的でもありません。サーバが複数あるのは正常な冗長構成で、エラーではありません。

</details>

**問3.** リース期間の半分が経過した時点で、DHCP クライアントが行う動作はどれでしょう？

1. 使用中のアドレスのリース延長（更新）を、割り当て元のサーバに要求する
2. 使用中のアドレスを直ちに返却して Discover からやり直す
3. 何もせず、期限が切れてから新しいアドレスを探す
4. 自分でランダムなアドレスを生成して切り替える

<details><summary>答えと解説</summary>

正解: **1**

クライアントは期限切れを待たず、リース期間の半分の時点で割り当て元サーバに更新を要求し、同じアドレスを使い続けられるようにします。早めに更新を始めるのは、サーバが一時的に応答できなくても期限までに再試行の猶予を持たせるためです。即返却してやり直す動作や、期限切れまで放置する動作は通信断を招き、クライアントが勝手にアドレスを作ることもありません。

</details>

**問4.** DHCP がクライアントに配布する情報として、適切な組合せはどれでしょう？

1. IP アドレスのみで、他の設定は常に手動で行う
2. MAC アドレスとホスト名
3. Web サーバの URL とメールアドレス
4. IP アドレスに加えて、サブネットマスク・デフォルトゲートウェイ・DNS サーバなど

<details><summary>答えと解説</summary>

正解: **4**

DHCP は IP アドレスだけでなく、通信に必要なサブネットマスク・デフォルトゲートウェイ・DNS サーバのアドレスなどを一括配布でき、だからこそ PC をつなぐだけで通信できるようになります。MAC アドレスは機器固有でサーバが配るものではありません。URL やメールアドレスの配布は DHCP の役割ではなく、IP アドレスのみという理解も不十分です。

</details>

## 2. DHCP リレーエージェント

前チャプターの DORA は、Discover と Request が**ブロードキャスト**でした。ここで問題が起きます。**ブロードキャストはルータを越えられない**ため、DHCP サーバと PC が別のセグメントにいると、Discover がサーバに届かないのです。

かといって、全セグメントに DHCP サーバを1台ずつ置くのは管理が大変です。そこで登場するのが **DHCP リレーエージェント**（多くはルータや L3 スイッチの機能）です。

### リレーエージェントの動き

1. PC がブロードキャストで Discover を送る
2. 同じセグメントにいるリレーエージェントがそれを受け取り、**宛先を DHCP サーバに指定したユニキャストに変換して転送**する（ユニキャストならルータを越えられます）
3. このときリレーエージェントは、**自分が Discover を受け取ったインタフェースの IP アドレス**（中継元情報、giaddr）をメッセージに記録する
4. DHCP サーバはこの中継元情報を見て、**「どのセグメント用のアドレス範囲（プール）から払い出すべきか」を判断**し、応答をリレーエージェント経由で PC に返す

つまりリレーエージェントは「ブロードキャストの声をユニキャストの手紙にして、差出人のセグメントを書き添えて届ける郵便屋さん」です。これにより、**1台の DHCP サーバで複数セグメントのアドレスを集中管理**できます。

> 💡 コツ：🟡 午後の構成図で「DHCP サーバがサーバ室に1台だけ」なら、各セグメントのルータにリレーエージェントがいるはず、と読み取れるようにしましょう。

### 確認問題

**問1.** DHCP リレーエージェントが必要になる根本的な理由はどれでしょう？

1. DHCP サーバはユニキャストを受信できないから
2. リース期間はセグメントをまたぐと無効になるから
3. DHCP の Discover などのブロードキャストは、ルータを越えて別セグメントへ届かないから
4. PC は同じセグメントのサーバからしかアドレスを受け取れない仕様だから

<details><summary>答えと解説</summary>

正解: **3**

ブロードキャストの到達範囲は同一セグメント内に限られ、ルータは中継しません。そのため DHCP サーバが別セグメントにあると Discover が届かず、代わりに受け取ってユニキャストで転送するリレーエージェントが必要になります。サーバはユニキャストを問題なく受信でき、リースがセグメント境界で無効になる仕様もありません。リレーを使えば別セグメントのサーバからの取得は可能です。

</details>

**問2.** PC からのブロードキャストの Discover を受け取った DHCP リレーエージェントが行う処理はどれでしょう？

1. 中継元の情報を付加したうえで、DHCP サーバ宛のユニキャストに変換して転送する
2. 自分が DHCP サーバの代わりになってアドレスを払い出す
3. ブロードキャストのまま全セグメントに転送する
4. Discover を破棄して PC にエラーを返す

<details><summary>答えと解説</summary>

正解: **1**

リレーエージェントは、受け取ったブロードキャストを DHCP サーバ宛のユニキャストに変換し、受信インタフェースの IP アドレス（中継元情報）を付けて転送します。ユニキャストならルータを越えられるため、遠隔のサーバに届きます。自分でアドレスを払い出すのはリレーではなく DHCP サーバの機能です。ブロードキャストのまま全セグメントに流すとネットワークを圧迫するうえ仕様にもなく、破棄してしまっては自動設定が成り立ちません。

</details>

**問3.** リレーエージェント経由で Discover を受け取った DHCP サーバは、複数のアドレスプールのうちどれから払い出すかをどうやって決めるでしょう？

1. プールの番号が小さい順に使う
2. リレーエージェントが記録した中継元（受信インタフェース）の IP アドレスから、クライアントのいるセグメントを判断する
3. クライアントの MAC アドレスのベンダーコードで決める
4. 応答が最も速かったプールを使う

<details><summary>答えと解説</summary>

正解: **2**

リレーエージェントが付加する中継元情報（giaddr）には、クライアントのいるセグメントのインタフェースアドレスが入っており、サーバはこれと一致するネットワークのプールを選びます。これが、1台のサーバで複数セグメントを集中管理できる鍵です。番号順や応答速度でプールを選ぶ仕組みはなく、MAC アドレスのベンダーコードはセグメントの所在を示しません。

</details>

## 3. NAT と NAPT（アドレス変換の流れを表で追う）

プライベート IP アドレスのままではインターネットと通信できないため、出口のルータが**アドレス変換**を行います。

- **NAT**：プライベート IP とグローバル IP を **1対1** で変換
- **NAPT**（IP マスカレード）：**ポート番号も合わせて変換**することで、**多数の PC が1つのグローバル IP を共有**

### NAPT のパケットを追いかける

PC（192.168.1.10）が Web サーバ（203.0.113.80:443）へアクセスします（ルータのグローバルアドレスは 198.51.100.1）。

| 区間 | 送信元 | 宛先 |
|---|---|---|
| PC → ルータ | **192.168.1.10:50000** | 203.0.113.80:443 |
| ルータ → サーバ | **198.51.100.1:60001** | 203.0.113.80:443 |

ルータは**送信元の IP とポートを書き換え**、対応を**変換テーブル**に記録します。

| 内側（変換前） | 外側（変換後） |
|---|---|
| 192.168.1.10:50000 | 198.51.100.1:60001 |
| 192.168.1.20:50000 | 198.51.100.1:60002 |

応答は 198.51.100.1:60001 宛に届き、ルータはテーブルを逆引きして 192.168.1.10:50000 へ戻します。2台の PC が同じポート 50000 を使っても、**外側のポートを変える**ことで区別できます。

> 💡 コツ：🔴 午後では各区間の送信元/宛先を埋める表の穴埋めが定番です。**行き：送信元だけ変わる。帰り：宛先だけ変わる**と覚えましょう。

### 確認問題

**問1.** NAPT で多数の PC が1つのグローバル IP アドレスを共有できるのはなぜでしょう？

1. PC ごとに別々のグローバル IP アドレスを時間帯で貸し出しているから
2. IP アドレスに加えてポート番号も変換し、外側のポート番号の違いで各 PC の通信を区別できるから
3. 全 PC の通信データを1つにまとめて圧縮して送るから
4. グローバル側では MAC アドレスで PC を区別しているから

<details><summary>答えと解説</summary>

正解: **2**

NAPT は送信元 IP アドレスとポート番号の組を変換し、PC ごと・通信ごとに外側のポート番号を変えるため、1つのグローバル IP でも応答を取り違えずに返せます。時間帯での貸し出しや通信の圧縮といった仕組みではなく、MAC アドレスはルータを越えた先では参照できないので区別には使えません。

</details>

**問2.** NAT と NAPT の違いの説明として、正しいものはどれでしょう？

1. NAT は IP アドレスを1対1で変換し、NAPT はポート番号も使って多数のプライベートアドレスを1つのグローバルアドレスに対応づける
2. NAT は IPv6 専用で、NAPT は IPv4 専用である
3. NAT はルータ、NAPT はスイッチングハブの機能である
4. NAT は宛先アドレスのみ、NAPT は送信元アドレスのみを変換する

<details><summary>答えと解説</summary>

正解: **1**

NAT は IP アドレス同士の1対1変換なので同時に通信できる台数はグローバルアドレスの数までですが、NAPT はポート番号も変換に使うことで多対1を実現します。家庭やオフィスのインターネット接続で使われるのは主に NAPT です。IP バージョンで分かれる用語ではなく、どちらも主に L3 の出口装置（ルータなど）の機能で、変換の向きの違いで区別されるものでもありません。

</details>

**問3.** NAPT を行うルータが、インターネット側から届いた応答パケットを内側の正しい PC に届けられるのはなぜでしょう？

1. 応答パケットの中に PC のプライベートアドレスが書かれているから
2. 内側の全 PC に応答をブロードキャストして該当 PC だけが受け取るから
3. 応答は常に最後に通信した PC へ届ける決まりだから
4. 変換時に「内側の IP・ポート」と「外側の IP・ポート」の対応を変換テーブルに記録してあり、応答の宛先ポートから逆引きできるから

<details><summary>答えと解説</summary>

正解: **4**

ルータは変換のたびに対応関係をテーブルへ記録しており、応答パケットの宛先（外側の IP とポート）をキーに逆引きして、元の PC のプライベートアドレスとポートに書き戻します。応答パケット自体には変換後のグローバルアドレスしか載っていません。全 PC へのブロードキャストや「最後に通信した PC へ届ける」といった動作では複数の同時通信を正しくさばけません。

</details>

**問4.** NAPT 環境で PC からインターネット上のサーバへ向かうパケットについて、ルータが書き換えるフィールドの組合せはどれでしょう？

1. 宛先 IP アドレスと宛先ポート番号
2. 送信元 IP アドレスと宛先 IP アドレスの両方
3. 送信元 IP アドレスと送信元ポート番号
4. 宛先 IP アドレスと送信元ポート番号

<details><summary>答えと解説</summary>

正解: **3**

内から外へ向かうパケットで書き換わるのは送信元側（プライベート IP とポート → グローバル IP とポート）だけで、宛先のサーバのアドレスとポートはそのまま運ばれます。逆に、外から戻る応答では宛先側だけが書き戻されます。「行きは送信元、帰りは宛先」という対応を押さえると、午後の表の穴埋めで迷いません。

</details>

## 4. NAT 越えの問題と静的NAT・ポートフォワーディング

NAPT は便利ですが、大きな弱点があります。変換テーブルのエントリは**内側から外側への通信をきっかけに作られる**ため、**外側（インターネット側）から始まる通信は、対応するエントリがなく内側に届けられない**のです。社内にあるサーバを公開したい場合や、外部からの着信を受けるアプリ（IP 電話など）で問題になります。これが **NAT 越え（NAT トラバーサル）**の問題です。

### 解決策1：静的 NAT

グローバル IP アドレスとサーバのプライベート IP アドレスを**あらかじめ固定の1対1**で対応づけておく方法です。エントリが常に存在するので、外部から始まる通信も届きます。ただし公開サーバ1台につきグローバル IP アドレスが1つ必要です。

### 解決策2：ポートフォワーディング（静的 NAPT）

グローバル IP が1つしかない場合は、**「このポート宛に来た通信は、内側のこのホストのこのポートへ転送する」**という静的な変換を登録します。

| 外側（受け口） | 内側（転送先） |
|---|---|
| 198.51.100.1:443 | 192.168.1.100:443（Web サーバ） |
| 198.51.100.1:2222 | 192.168.1.200:22（保守用 SSH） |

1つのグローバル IP を、ポート番号で複数の公開サーバに振り分けられます。

なお、FTP や IP 電話の SIP のように**アプリケーションのデータ部分に IP アドレスを書き込むプロトコル**は、ヘッダしか書き換えない NAT とは相性が悪く、別途の対応（ALG など）が必要になることも知っておきましょう。

> 💡 コツ：🟡「NAPT のテーブルは内→外の通信でしか作られない」という一文が、この章の記述問題の答えの核になります。

### 確認問題

**問1.** NAPT だけを設定したルータの内側にある社内サーバへ、インターネット側から新規に接続できないのはなぜでしょう？

1. 変換テーブルのエントリは内側から外側への通信を契機に作られるため、外部から始まる通信には対応するエントリが存在しないから
2. NAPT がすべての通信を暗号化してしまうから
3. プライベートアドレスのサーバは TCP を使えないから
4. インターネット側からのパケットはルータの処理速度を超えてしまうから

<details><summary>答えと解説</summary>

正解: **1**

NAPT の変換テーブルは内→外の通信をきっかけに動的に作られるため、外部から突然届いたパケットは逆引きするエントリがなく、どの内側ホスト宛か判断できずに破棄されます。これが NAT 越え問題の本質です。NAPT に暗号化の機能はなく、プライベートアドレスでも TCP は普通に使えます。処理速度の問題でもありません。

</details>

**問2.** 静的 NAT と NAPT の動的な変換の違いとして、正しいものはどれでしょう？

1. 静的 NAT はポート番号だけを変換し、IP アドレスは変換しない
2. 静的 NAT はグローバルとプライベートを固定の1対1で対応づけるため、外部から始まる通信も内側へ届けられる
3. 静的 NAT は通信のたびに対応関係がランダムに変わる
4. 静的 NAT は UDP の通信には使えない

<details><summary>答えと解説</summary>

正解: **2**

静的 NAT はあらかじめ固定の1対1対応を登録しておく方式で、エントリが常に存在するため、サーバ公開のように外部から始まる通信も通せます。動的に（通信のたびに）エントリが作られる NAPT との本質的な違いはこの「固定で常在」という点です。変換対象はIP アドレスであり、ランダムに変わるのはむしろ動的変換の性質で、TCP/UDP のどちらでも機能します。

</details>

**問3.** グローバル IP アドレスが1つしかない環境で、内側の Web サーバ（192.168.1.100 の 443 番）を公開するための設定はどれでしょう？

1. Web サーバのデフォルトゲートウェイを削除する
2. Web サーバにグローバル IP アドレスを直接設定する
3. ルータに「グローバル IP の 443 番宛の通信を 192.168.1.100 の 443 番へ転送する」ポートフォワーディングを設定する
4. DHCP のリース期間を無制限にする

<details><summary>答えと解説</summary>

正解: **3**

ポートフォワーディング（静的 NAPT）は「この受け口ポート宛は内側のこのホストへ」という固定の変換で、グローバル IP が1つでも外部からの接続をサーバへ導けます。グローバル IP が1つしかない以上それをサーバ専用に直接設定するとルータや他の通信が成り立たず、ゲートウェイの削除は逆に応答を返せなくする設定です。リース期間はアドレス公開とは関係ありません。

</details>

**問4.** FTP や SIP（IP 電話）が NAT 環境で問題を起こしやすい理由はどれでしょう？

1. どちらも暗号化が必須のプロトコルだから
2. ウェルノウンポートを使用しないプロトコルだから
3. パケットサイズが MTU を常に超えるから
4. アプリケーションのデータ部分に IP アドレスを書き込むため、ヘッダしか書き換えない NAT では内部のアドレスが相手にそのまま伝わってしまうから

<details><summary>答えと解説</summary>

正解: **4**

NAT が書き換えるのは IP や TCP/UDP のヘッダだけです。FTP や SIP はデータ部分に自分の IP アドレスを記載して相手に通知するため、そこにプライベートアドレスが残ったまま届き、相手がそのアドレスに接続できず失敗します。対策としてデータ部分まで書き換える ALG などが使われます。暗号化の必須性やポート番号の種別、パケットサイズはこの問題の原因ではありません。

</details>
