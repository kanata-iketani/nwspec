# 第27章 午後試験の読解法と記述の書き方

午後試験は知識の試験ではなく「長文読解と記述」の試験です。この章では、問題文の構造・記述解答の型・部分点と時間配分という3つの武器を身につけ、手持ちの過去問演習に入る準備を整えます。

## 1. 午後問題の構造 ― 設問から先に読む

午後Ⅰは **90分で3問中2問選択**、午後Ⅱは **120分で2問中1問選択** の記述式です。1問が数ページの長文事例なので、やみくもに頭から読むと時間が足りません。まずは「問題文がどう作られているか」を知りましょう。

### 問題文の定番の作り

午後問題は、ほぼ必ず次の順番で書かれています。

| 部位 | 中身 |
|---|---|
| ① 会社紹介 | 「A社は従業員300名の製造業である」など、業種と規模 |
| ② 現行構成 | ネットワーク構成図 + 機器・IPアドレスの表 |
| ③ きっかけ | 拠点追加・老朽化・セキュリティ指摘など、変更の動機 |
| ④ 検討の経緯 | 担当者どうしの会話。**下線や空欄はここに集中** |
| ⑤ 新構成・移行 | 新しい設計と、残った課題 |

設問は本文中の **下線部** や **空欄** に対応しています。つまり「本文のどこを読めば答えられるか」は最初から決まっているのです。

### 図表と注記の読み方

- **構成図**は本文より先に全体像をくれます。FW・L3SW・サーバの位置関係と、セグメントのIPアドレスを図に書き込みながら読みます。
- 表の**注記**（「注1」「※」）や「**ただし、〜とする**」という一文は、出題者が置いた**制約条件 = 解答を絞り込むヒント**です。読み飛ばすと別解に迷い込みます。

### 🔴 設問から先に読むテクニック

おすすめの手順は次のとおりです。

1. 設問をすべて読み、「何が問われるか」「指定字数」をメモする
2. 構成図と表をながめて全体像をつかむ
3. 本文を読み進め、下線・空欄に当たるたびに対応する設問を解く

答えの材料は、多くの場合 **下線部の直前・直後の段落と構成図**にあります。「探し物を決めてから読む」だけで、読む速さと精度が大きく変わります。

### 確認問題

**問1.** 午後問題を解き始めるとき、最初にやるべきこととして最も適切なのはどれでしょう？

1. 本文を1行目から精読し、全体を理解してから設問を読む
2. 設問に先に目を通し、何が問われるか・指定字数を把握してから本文を読む
3. 構成図は複雑なので最後まで見ずに本文だけで解く
4. 指定字数の長い設問から順に解答を書き始める

<details><summary>答えと解説</summary>

正解: **2**

設問を先に読めば「探し物」が決まり、本文を目的を持って読めます。頭からの精読は時間切れのもとで、構成図はむしろ最初に見るべき全体像です。字数の長い設問から書き始めるのも、本文の根拠を確認しないままでは的外れになります。本番の記述でも「設問で問われた内容に対応する本文中の根拠を探して答える」姿勢が部分点につながります。

</details>

**問2.** 本文中の「ただし、FWはOSPFに参加しないものとする」のような一文の正しい扱いはどれでしょう？

1. 単なる補足なので読み飛ばしてよい
2. 出題者のミスなので無視して一般論で答える
3. 解答を絞り込む制約条件として、設問を解くときに必ず参照する
4. 午後Ⅱにだけ登場する形式である

<details><summary>答えと解説</summary>

正解: **3**

「ただし〜とする」は出題者が意図的に置いた制約条件で、これを使わないと解けない設問が多くあります。読み飛ばすと「一般論では正しいが、この事例では成り立たない」別解に迷い込みます。午後Ⅰ・Ⅱ共通の形式です。本番の記述なら「FWがOSPFに参加しないため、静的経路を併用する必要があるから」のように制約を根拠に組み込みます。

</details>

**問3.** 「下線①について、その目的を答えよ」という設問の答えの材料は、どこにあることが多いでしょう？

1. 下線部の直前・直後の段落と、構成図・表
2. 問題文の末尾にあるおまけの注釈のみ
3. 本文には材料がなく、すべて自分の知識だけで書く
4. ほかの問題（選択しなかった問）の本文

<details><summary>答えと解説</summary>

正解: **1**

下線や空欄は「この近くを読め」という出題者の目印で、直前直後の会話や段落、対応する構成図に材料が置かれています。知識だけで書くと事例と無関係な一般論になり減点されます。別の問題の本文はもちろん無関係です。本番の記述なら「下線直後に示された課題を解消するため」という形で、本文の言葉を使って書きます。

</details>

**問4.** 構成図を読むときの着眼点として最も適切なのはどれでしょう？

1. 機器のメーカー名を推測する
2. FW・L3SW・サーバの位置関係と各セグメントのIPアドレスを本文・表と突き合わせる
3. 図は本文の飾りなので、本文と矛盾したら本文を無視する
4. 線の本数だけ数えれば十分である

<details><summary>答えと解説</summary>

正解: **2**

設問の多くは「どの機器のどのインタフェースをどんな通信が通るか」を問うため、位置関係とIPアドレスの対応づけが読解の土台です。メーカー名は出題されず、図と本文・表は一体の情報なのでどちらかを無視してはいけません。線の本数だけでは経路も冗長構成も判断できません。本番でも「構成図のFW1を経由するため」のように図を根拠に記述します。

</details>

**問5.** 午後Ⅰで「3問中2問」を選ぶときの進め方として最も適切なのはどれでしょう？

1. 問1から順に解くと決めておき、中身は見ない
2. 最も文章量が少ない問題を機械的に選ぶ
3. 各問の構成図と設問をざっと見て、自分の知っている分野・用語が多い問題を選ぶ
4. 開始30分は選択に使い、じっくり全文を読み比べる

<details><summary>答えと解説</summary>

正解: **3**

選択の判断材料は構成図と設問に凝縮されています。数分で図と設問を見て、学習済みの分野（ルーティング、無線、セキュリティなど）かどうかで選ぶのが堅実です。問番号や文章量は難易度と関係がなく、選択に30分かけると解答時間がなくなります。本番のメモとしては「設問の用語が既知か」を基準に2〜3分で決める、と覚えてください。

</details>

## 2. 記述解答の書き方 ― 問い方別の型と字数の収め方

午後の記述は「知っているのに点にならない」が一番もったいない失点です。原因の多くは**問いに正面から答えていない文**にあります。設問の問い方には型があり、型どおりに書けば採点者に伝わります。

### 🔴 問い方別の解答の型

| 問い方 | 文末の型 | ポイント |
|---|---|---|
| **理由**を述べよ | 「〜だから」「〜ため」 | 原因 → 結果の**因果を一文で閉じる** |
| **目的**を述べよ | 「〜するため」 | これから得たい効果を書く（過去の原因ではない） |
| **問題点**を述べよ | 「〜という問題」「〜できない」 | 困る事象を具体的に。「危険」だけでは不十分 |
| **対策**を述べよ | 「〜する」 | 誰が・何に・何をするか、動作で終える |

たとえば「理由」を聞かれて「〜を導入する」と対策を書くと、内容が正しくても0点になり得ます。**文末が設問の問い方と一致しているか**を必ず確認しましょう。

### 指定字数への収め方

- **30字前後**: 伝える要素は1つ。「AだからBできないため」のような最小の因果。
- **50〜60字**: 要素2つ。「原因 + 影響」や「対策 + 得られる効果」。
- 削るのは**修飾語と重複表現**。残すのは**技術用語と因果のつながり**です。
- 指定字数の**8割以上**は埋めます。短すぎる解答は要素が足りていないサインです。

### 本文の言葉を借りる

記述は作文コンテストではありません。本文に「全社共通の事前共有鍵」と書いてあれば、解答でもその言葉をそのまま使います。自己流に言い換えるほど、採点基準のキーワードから遠ざかります。因果が一文で閉じているか、声に出して読んで確認するのがおすすめです。

### 確認問題

**問1.** 「〜の理由を35字以内で述べよ」という設問への解答として、最も適切な文末はどれでしょう？

1. 「〜を導入する。」
2. 「〜ため。」
3. 「〜と思われる。」
4. 「〜という問題。」

<details><summary>答えと解説</summary>

正解: **2**

理由を問われたら「〜ため」「〜だから」で因果を閉じるのが型です。「〜を導入する」は対策の文末、「〜という問題」は問題点の文末で、問いとかみ合いません。「〜と思われる」は根拠があいまいな印象を与えます。本番の記述なら「共有鍵が全端末で共通であり、漏えい時に全端末の設定変更が必要になるため」のように書きます。

</details>

**問2.** 解答が指定字数を超えてしまったとき、最初に削るべきものはどれでしょう？

1. 因果関係を示す「〜ため」などのつなぎ
2. 本文から借りた技術用語
3. 修飾語や同じ意味の重複表現
4. 主語にあたる機器名

<details><summary>答えと解説</summary>

正解: **3**

削ってよいのは「大幅に」「〜などの」といった修飾語や重複表現です。技術用語は採点基準のキーワード、因果のつなぎは理由の設問の生命線、機器名は「何の話か」を特定する要素なので削ると減点リスクが大きくなります。本番の記述なら、例えば「非常に大きな負荷が掛かるおそれがあるため」を「負荷が増大するため」と圧縮します。

</details>

**問3.** 「目的を述べよ」と「理由を述べよ」の違いの説明として、最も適切なのはどれでしょう？

1. 目的はこれから得たい効果、理由はそうする根拠・原因を答える
2. 両者はまったく同じで、どちらも対策を書けばよい
3. 目的は過去の障害を、理由は未来の計画を書く
4. 目的は箇条書き、理由は表で答える決まりがある

<details><summary>答えと解説</summary>

正解: **1**

目的は「〜するため」と、行為によってこれから得たい効果を書きます。理由は「〜だから」と、判断の根拠や原因を書きます。向きが未来か（目的）、根拠か（理由）の違いで、どちらも対策そのものを書くのは誤りです。解答形式の決まりもありません。本番の記述なら、目的は「障害時も通信を継続させるため」、理由は「単一障害点となっているため」のように書き分けます。

</details>

**問4.** 「対策を述べよ」への解答として最も適切な書き方はどれでしょう？

1. 「危険なので注意する。」のように心構えを書く
2. 「セキュリティを強化すべきだ。」のように方針だけ書く
3. 「〜という問題があるため。」と問題点を書く
4. 「FWで外部からDMZ宛てはTCP443のみ許可する。」のように具体的な動作で書く

<details><summary>答えと解説</summary>

正解: **4**

対策は「どの機器に・何を・どうする」という具体的な動作で書きます。「注意する」「強化すべき」は採点できる中身がなく、問題点の文末で終えるのは問いとかみ合いません。本番の記述なら「FWで外部からWebサーバ宛ての通信をTCP443のみに制限する」（30字前後）のように、機器名・対象・動作をそろえます。

</details>

**問5.** 記述解答で本文中の用語の扱いとして最も適切なのはどれでしょう？

1. 自分の言葉に言い換えるほど高評価になる
2. 本文の用語（機器名・方式名）をそのまま使って書く
3. 用語は使わず、ひらがなで平易に書く
4. 英語の略語はすべて正式名称に展開しなければならない

<details><summary>答えと解説</summary>

正解: **2**

採点基準は本文の用語をもとに作られるため、本文が「L3SW1」「事前共有鍵」と呼ぶものはそのまま使うのが安全です。言い換えはキーワード一致から遠ざかるだけで加点されません。平易さより正確さが優先で、本文がVRRPと略すならVRRPのままで問題ありません。本番の記述なら「L3SW2がVRRPのマスタに切り替わり通信を引き継ぐため」のように本文の表記で書きます。

</details>

## 3. 部分点の取り方と時間配分 ― 90分の設計図

午後試験は満点を取る試験ではありません。**60点を確実に超える**ための時間とリスクの管理が合否を分けます。

### 午後Ⅰ: 90分で2問の設計図

- **最初の約5分**: 3問の構成図と設問をざっと見て、解く2問を決める
- **1問あたり約40分**: 得意な方から着手する
- **残り約5分**: 空欄・書きかけの見直し

午後Ⅱは120分で1問です。本文が長いぶん、**最初の25〜30分を読解とメモに使ってよい**と考えると落ち着いて取り組めます。

### わからない設問の扱い

1問の中に必ず1〜2個、手が止まる設問があります。そこで止まるのが最大の事故です。**2分考えて方向が見えなければ印をつけて次へ**進み、最後に戻ります。後の設問が前の設問のヒントになっていることも珍しくありません。

### 🔴 部分点の取り方

記述式は**白紙が最大の敵**です。採点は要素ごとの加点方式と考えられるため、完璧な文でなくても、

- 方向性が合っている（問いの型に沿っている）
- 本文のキーワードや機器名が入っている
- 指定字数の8割以上埋まっている

であれば部分点が期待できます。「自信がないから書かない」は0点を自分で選ぶ行為です。1問を完答して1問白紙にするより、**2問とも7割を狙う**のが60点への近道です。

### 記述練習のやり方

このアプリの **🎤口頭試問モード**を使うと、学習済みチャプターの内容から別角度の記述問題を出題し、あなたの答案を採点してもらえます。「この章の内容で、理由を問う記述問題を30〜50字指定で出して」のように頼み、**型どおりの文末・字数感覚**を体に覚え込ませてください。仕上げは手持ちの過去問で、必ず時間を計って本番どおりに演習します。

### 確認問題

**問1.** 午後Ⅰ（90分・2問選択）の時間配分として最も適切なのはどれでしょう？

1. 選択に5分、1問約40分ずつ、最後に5分の見直し
2. 1問目に70分かけて完璧にし、2問目は20分で解く
3. 2問を同時に1設問ずつ交互に解く
4. 最初の30分は何も書かず全文を暗記する

<details><summary>答えと解説</summary>

正解: **1**

2問にほぼ均等に時間を配り、冒頭の選択と最後の見直しを確保するのが基本形です。1問に70分かけると2問目が壊滅し、交互に解くと事例の文脈が頭から抜けて読み直しが発生します。暗記は不要で、必要箇所を探し直せるようメモを取れば十分です。本番の方針メモなら「1問40分、超えたら途中でも次へ移る」と決めておきます。

</details>

**問2.** 解いている途中で答えが浮かばない設問に出会ったときの行動として、最も適切なのはどれでしょう？

1. 浮かぶまでその設問に時間を使い続ける
2. その問題全体をあきらめて、もう1問を解き直す
3. 2分ほど考えて方向が見えなければ印をつけて次の設問へ進み、最後に戻る
4. 白紙のまま提出し、次の区分に備える

<details><summary>答えと解説</summary>

正解: **3**

1つの設問での停滞が時間切れの最大原因です。印をつけて先へ進めば、後の設問や本文の続きがヒントになることもあります。粘り続けるのも問題ごと乗り換えるのも時間を失うだけで、白紙提出は取れたはずの部分点を捨てる行為です。本番の記述でも、戻ってきたら方向性と本文のキーワードだけでも書いて提出します。

</details>

**問3.** 部分点の観点から正しい行動はどれでしょう？

1. 完璧な文が書けないなら空欄のほうが印象がよい
2. 方向性が合う内容を、本文のキーワードを入れて指定字数の8割以上で書く
3. 指定字数を無視して長く書くほど加点される
4. 設問と関係なくても覚えている用語を羅列する

<details><summary>答えと解説</summary>

正解: **2**

採点は要素ごとの加点方式と考えられるため、問いの型に沿い、本文の機器名・用語を含む答案には部分点の余地があります。空欄は確実に0点、字数超過は解答用紙に収まらず、無関係な用語の羅列は加点要素を含みません。本番の記述なら、確信がなくても「L3SW1が単一障害点となっているため」のように方向性とキーワードを押さえた一文を書きます。

</details>

**問4.** 午後Ⅱ（120分・1問）の進め方として最も適切なのはどれでしょう？

1. 午後Ⅰと同じペースで30分以内に読み終えないと不合格になる
2. 最初の25〜30分を読解と構成図へのメモに使い、残りで設問を解く
3. 本文は読まず、設問と図だけで解答する
4. 最初の60分で答案をすべて下書きし、残り60分で清書する

<details><summary>答えと解説</summary>

正解: **2**

午後Ⅱは本文が長いぶん、序盤にじっくり読解とメモの時間を取るのが定石で、時間的な余裕もあります。本文を読まない解答は事例固有の条件を外して失点し、全答案の下書き+清書は時間が足りません。読むペースに固定のノルマはなく、設問から先に読む手順は午後Ⅱでも同じです。本番のメモなら「30分読む・80分解く・10分見直す」が目安です。

</details>

**問5.** 本番前の記述力トレーニングとして、この講座が推奨する方法はどれでしょう？

1. 4択問題だけを繰り返せば記述力も自然に身につく
2. 模範解答を丸暗記して同じ文を書く
3. 🎤口頭試問モードで別角度の記述問題に字数を決めて答えて採点を受け、仕上げに過去問を時間を計って解く
4. 本文を読まずに解答例だけを読む

<details><summary>答えと解説</summary>

正解: **3**

記述力は「自分で書いて直される」ことでしか伸びません。口頭試問モードは学習済み内容から別角度の記述問題を出し答案を採点してくれるので、型と字数感覚の練習に最適です。仕上げは必ず手持ちの過去問を本番と同じ制限時間で解きます。4択や丸暗記だけでは初見の事例に対応できず、解答例を読むだけでは書く訓練になりません。練習でも「〜ため」で閉じる30〜50字の答案を自分の手で作ることが重要です。

</details>
