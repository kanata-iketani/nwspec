# 第12章 IPアドレッシング（IPv4・サブネット・IPv6）

ネスペの計算問題の主戦場、IPアドレスの章です。IPv4アドレスの構造からサブネットマスク・CIDRの計算、必要ホスト数からのサブネット設計、特別なアドレス、IPv6の基本まで、手を動かして身につけます。

## 1. IPv4アドレスの構造——ネットワーク部とホスト部

**IPv4アドレス**は **32ビット** の数値です。人間が読みやすいよう、8ビットずつ4つの塊（**オクテット**）に区切り、それぞれを10進数にして「192.168.1.10」のように表記します（各オクテットは0〜255）。

### ネットワーク部とホスト部

IPアドレスは2つの部分からできています。

| 部分 | 意味 | 住所でいうと |
|---|---|---|
| **ネットワーク部** | どのネットワークに属するか | 「〇〇市〇〇町」 |
| **ホスト部** | そのネットワーク内のどの機器か | 「〇番地」 |

区切り位置は「192.168.1.10**/24**」のように**プレフィックス長**で表し、この例では先頭24ビットがネットワーク部です。

### 同じネットワークかどうかが、すべての分かれ道

- ネットワーク部が**同じ** → 同じLANの仲間。ARPでMACアドレスを調べて**直接通信**
- ネットワーク部が**違う** → **デフォルトゲートウェイ（ルータ）経由**で通信

歴史的には、先頭のビットパターンで区切りが自動的に決まる**クラスA/B/C**（/8・/16・/24固定）が使われていましたが、現在は区切りを1ビット単位で自由に決められる **CIDR**（次チャプター）が標準です。

> 💡 🔴 ネスペの計算問題はすべて「32ビットのどこまでがネットワーク部か」の一点から始まります。/24なら第3オクテットまで、と反射で変換できるようにしましょう。

### 確認問題

**問1.** IPv4アドレスの説明として、正しいものはどれでしょう？

1. 32ビットを8ビットずつ4つに区切り、10進数で表記する
2. 48ビットを16進数12桁で表記する
3. 128ビットをコロン区切りの16進数で表記する
4. 長さの決まっていない文字列で表記する

<details><summary>答えと解説</summary>

正解: **1**

IPv4アドレスは32ビットで、オクテットごとに10進数にしたドット区切り表記を使います。48ビット・16進12桁はMACアドレス、128ビット・コロン区切りはIPv6アドレスの表記です。長さは32ビットに固定されており、自由な文字列ではありません。

</details>

**問2.** IPアドレスのネットワーク部が表すものはどれでしょう？

1. 機器を製造したベンダ
2. 通信の優先度
3. そのアドレスがどのネットワークに属するか
4. 機器のOSの種類

<details><summary>答えと解説</summary>

正解: **3**

ネットワーク部は所属ネットワークを示す、住所でいう「市町村」にあたる部分です。これが同じ相手とは直接通信でき、違う相手とはルータ経由になります。製造ベンダを示すのはMACアドレスのOUIで、優先度やOSの種類はIPアドレスからは分かりません。

</details>

**問3.** 「192.168.1.10/24」の「/24」が意味するものはどれでしょう？

1. ホスト部が24ビットであること
2. 先頭の24ビットがネットワーク部であること
3. このネットワークに24台まで接続できること
4. 第24番のVLANに属していること

<details><summary>答えと解説</summary>

正解: **2**

/24はプレフィックス長で、先頭24ビット（第3オクテットまで）がネットワーク部だと示します。ホスト部は残りの32−24＝8ビットです。接続可能台数は2の8乗−2＝254台で24台ではなく、VLAN番号とは無関係です。

</details>

**問4.** PC（192.168.1.10/24）がルータを介さずに直接通信できる相手はどれでしょう？

1. 10.0.0.5
2. 192.168.2.10
3. 172.16.1.10
4. 192.168.1.200

<details><summary>答えと解説</summary>

正解: **4**

/24なので第3オクテットまでのネットワーク部「192.168.1」が一致する相手とだけ直接通信でき、192.168.1.200が該当します。192.168.2.10は第3オクテットが異なる別ネットワークで、10.0.0.5や172.16.1.10もネットワーク部が一致しないため、いずれもルータ経由になります。

</details>

## 2. サブネットマスクとCIDR——計算の基本形

ネットワーク部の長さを示すもう1つの表記が**サブネットマスク**です。ネットワーク部を1、ホスト部を0にした32ビットの値で、/24なら255.255.255.0です。

### プレフィックス長 ⇔ マスクの変換

第4オクテットの変換は暗記必須です（1が左から詰まっていきます）。

| プレフィックス | 第4オクテットの2進数 | マスク |
|---|---|---|
| /25 | 10000000 | 255.255.255.128 |
| /26 | 11000000 | 255.255.255.192 |
| /27 | 11100000 | 255.255.255.224 |
| /28 | 11110000 | 255.255.255.240 |
| /30 | 11111100 | 255.255.255.252 |

### ネットワークアドレスの求め方

IPアドレスとマスクを2進数で**AND演算**（両方1のビットだけ1）すると、ホスト部がすべて0になった**ネットワークアドレス**が得られます。

例：172.16.10.70/26
- 70 → 01000110
- マスク → 11000000
- AND → 01000000 ＝ 64 → ネットワークアドレスは **172.16.10.64**

ホスト部が h ビットなら、割り当てられるホスト数は **2のh乗 − 2**（ネットワークアドレスとブロードキャストアドレスの2つを除く）です。

> 💡 🔴 128・192・224・240・248・252 の並びは、電話番号のように暗唱できるまで繰り返しましょう。計算のスピードが午前Ⅱ・午後の得点に直結します。

### 確認問題

**問1.** プレフィックス長 /26 をサブネットマスク表記にしたものはどれでしょう？

1. 255.255.255.128
2. 255.255.255.224
3. 255.255.255.192
4. 255.255.255.240

<details><summary>答えと解説</summary>

正解: **3**

/26は1が26個並ぶマスクです。24個で第3オクテットまで（255.255.255）が埋まり、残り2個が第4オクテットの先頭に入って2進数で11000000、つまり128＋64＝192になります。128は/25（1が1個）、224は/27（1が3個）、240は/28（1が4個）に対応します。

</details>

**問2.** 192.168.5.200/27 のネットワークアドレスはどれでしょう？

1. 192.168.5.192
2. 192.168.5.200
3. 192.168.5.128
4. 192.168.5.224

<details><summary>答えと解説</summary>

正解: **1**

第4オクテットで計算します。200を2進数にすると11001000、/27のマスクの第4オクテットは11100000。AND演算すると11000000＝192なので、ネットワークアドレスは192.168.5.192です。/27は32刻み（0, 32, 64, …, 192, 224）で、200は192以上224未満の範囲に入ります。200はホストアドレス自身、224は次のサブネットの先頭です。

</details>

**問3.** /28 のサブネットでホストに割り当て可能なアドレス数はどれでしょう？

1. 16
2. 14
3. 30
4. 8

<details><summary>答えと解説</summary>

正解: **2**

/28のホスト部は32−28＝4ビットで、2の4乗＝16個のアドレスがあります。そこからホスト部が全0のネットワークアドレスと全1のブロードキャストアドレスの2個を除いた14台に割り当てられます。16は総アドレス数、30は/27の場合の答えです。

</details>

**問4.** 10.1.1.130/25 のネットワークアドレスはどれでしょう？

1. 10.1.1.0
2. 10.1.1.64
3. 10.1.1.130
4. 10.1.1.128

<details><summary>答えと解説</summary>

正解: **4**

130を2進数にすると10000010、/25のマスクの第4オクテットは10000000。AND演算すると10000000＝128なので、ネットワークアドレスは10.1.1.128です。/25は第4オクテットを0〜127と128〜255の2つに分け、130は後半に属します。10.1.1.0は前半のサブネットのネットワークアドレスで、130はホストアドレス自身です。

</details>

**問5.** サブネットマスク 255.255.255.224 をプレフィックス長で表したものはどれでしょう？

1. /26
2. /27
3. /28
4. /25

<details><summary>答えと解説</summary>

正解: **2**

224を2進数にすると11100000で、1が3個です。第3オクテットまでの24個と合わせて24＋3＝27、つまり/27になります。/26なら第4オクテットは192（1が2個）、/28なら240（1が4個）、/25なら128（1が1個）です。

</details>

## 3. サブネット分割の計算——必要ホスト数から設計する

「60台のPCを収容するサブネットを切り出したい」——午後試験にそのまま出る設計手順を身につけましょう。

### 手順：必要ホスト数 → プレフィックス長

1. 必要ホスト数に **＋2**（ネットワークアドレスとブロードキャストアドレスの分）
2. それ以上になる最小の **2のh乗** を探す（hがホスト部のビット数）
3. プレフィックス長 ＝ **32 − h**

例：60台 → 60＋2＝62 → 2の6乗＝64で足りる（2の5乗＝32では不足）→ h＝6 → **/26**

### 分割の例：192.168.1.0/24 を /26 で4分割

ホスト部から2ビット借りると2の2乗＝4個のサブネットができ、第4オクテットが64刻みで区切られます。

| サブネット | ホストの範囲 | ブロードキャスト |
|---|---|---|
| 192.168.1.0/26 | .1〜.62 | .63 |
| 192.168.1.64/26 | .65〜.126 | .127 |
| 192.168.1.128/26 | .129〜.190 | .191 |
| 192.168.1.192/26 | .193〜.254 | .255 |

ブロードキャストアドレスは**ホスト部をすべて1**にしたアドレス、つまり「次のサブネットの先頭 − 1」です。

> 💡 🔴 「256 − マスクの第4オクテット ＝ サブネットの幅」（255.255.255.192なら256−192＝64刻み）と覚えると、区切りを一瞬で書き出せます。

### 確認問題

**問1.** 60台のホストを収容できる最小のサブネットのプレフィックス長はどれでしょう？

1. /27
2. /26
3. /25
4. /24

<details><summary>答えと解説</summary>

正解: **2**

必要なアドレス数は60＋2＝62個です。2の5乗＝32では不足し、2の6乗＝64で初めて足りるので、ホスト部は6ビット、プレフィックス長は32−6＝/26（収容可能62台）です。/27は2の5乗−2＝30台で不足、/25（126台）や/24（254台）は収容できますが「最小」ではありません。

</details>

**問2.** 192.168.1.0/24 を4つの等しい大きさのサブネットに分割するとき、各サブネットのプレフィックス長はどれでしょう？

1. /28
2. /30
3. /25
4. /26

<details><summary>答えと解説</summary>

正解: **4**

4分割するにはホスト部から2ビット借ります（2の2乗＝4）。24＋2＝26なので各サブネットは/26となり、第4オクテットが0・64・128・192から始まる64アドレスずつの塊になります。/25では2分割、/28では16分割、/30では64分割になってしまいます。

</details>

**問3.** 192.168.1.64/26 のブロードキャストアドレスはどれでしょう？

1. 192.168.1.127
2. 192.168.1.126
3. 192.168.1.64
4. 192.168.1.255

<details><summary>答えと解説</summary>

正解: **1**

64を2進数にすると01000000で、/26のホスト部は下位6ビットです。これをすべて1にすると01111111＝127なので、ブロードキャストアドレスは192.168.1.127です。126は割り当て可能な最後のホストアドレス、64はネットワークアドレス自身、255は/24全体でのブロードキャストアドレスです。

</details>

**問4.** 172.16.0.0/22 のサブネットでホストに割り当て可能なアドレス数はどれでしょう？

1. 510
2. 2046
3. 1022
4. 4094

<details><summary>答えと解説</summary>

正解: **3**

ホスト部は32−22＝10ビットで、2の10乗＝1024個のアドレスがあります。ネットワークアドレスとブロードキャストアドレスの2個を除いた1022台に割り当て可能です。510は/23（2の9乗−2）、2046は/21（2の11乗−2）、4094は/20（2の12乗−2）の場合です。

</details>

## 4. 特別なアドレス——プライベート・ブロードキャスト・ループバック

IPv4には、ホストに自由に割り当ててはいけない「予約席」のアドレスがあります。試験でも実務の障害切り分けでも必須の知識です。

### プライベートアドレス

組織内で自由に使ってよい範囲で、**インターネット上にはルーティングされません**。外に出るにはNAT（第16章）による変換が必要です。

| クラス | 範囲 |
|---|---|
| A | 10.0.0.0 〜 10.255.255.255（10.0.0.0/8） |
| B | 172.16.0.0 〜 172.31.255.255（172.16.0.0/12） |
| C | 192.168.0.0 〜 192.168.255.255（192.168.0.0/16） |

### そのほかの特別なアドレス

| アドレス | 意味 |
|---|---|
| ホスト部が全0 | **ネットワークアドレス**（ネットワーク自体を指す） |
| ホスト部が全1 | **ブロードキャストアドレス**（そのネットワークの全員宛て） |
| 127.0.0.1 | **ループバックアドレス**（自分自身。通信機能のテストに使う） |
| 169.254.0.0/16 | **リンクローカルアドレス**（APIPA）。**DHCPでアドレスを取得できなかった**ときにOSが自動設定する |

> 💡 🔴 「172.16〜172.31」の範囲は特に間違えやすい要注意ポイント。また、PCに169.254.x.xが付いていたら「DHCPサーバと通信できていない」と切り分けられます——午後で問われる実戦知識です。

### 確認問題

**問1.** プライベートアドレスに該当するものはどれでしょう？

1. 172.32.10.1
2. 172.20.10.1
3. 192.169.1.1
4. 11.1.1.1

<details><summary>答えと解説</summary>

正解: **2**

クラスBのプライベートアドレスは172.16.0.0〜172.31.255.255で、172.20.10.1はこの範囲内です。172.32.10.1は上限の172.31を1つ超えており、192.169.1.1は192.168.0.0/16の外、11.1.1.1は10.0.0.0/8の外で、いずれもグローバルアドレスです。

</details>

**問2.** 127.0.0.1 の説明として、正しいものはどれでしょう？

1. DHCPでの取得に失敗したときに自動設定されるアドレス
2. ネットワーク全体へのブロードキャストアドレス
3. デフォルトゲートウェイ用に予約されたアドレス
4. 自分自身を指すループバックアドレス

<details><summary>答えと解説</summary>

正解: **4**

127.0.0.1はループバックアドレスで、宛先にすると自ホスト内で折り返され、ネットワーク機能のテストなどに使われます。DHCP失敗時に付くのは169.254.0.0/16のリンクローカルアドレスです。ブロードキャストはホスト部全1のアドレスで、デフォルトゲートウェイ用の予約アドレスという規定はありません。

</details>

**問3.** 192.168.10.0/24 のネットワークで、ホストに割り当てられないアドレスの組合せはどれでしょう？

1. 192.168.10.0 と 192.168.10.255
2. 192.168.10.1 と 192.168.10.254
3. 192.168.10.100 と 192.168.10.200
4. 192.168.10.127 と 192.168.10.128

<details><summary>答えと解説</summary>

正解: **1**

/24ではホスト部（第4オクテット）が全0の192.168.10.0がネットワークアドレス、全1の192.168.10.255がブロードキャストアドレスで、どちらもホストには割り当てられません。残りの.1〜.254はすべて割り当て可能で、.127と.128も/24では普通のホストアドレスです。

</details>

**問4.** PCのIPアドレスを確認したところ 169.254.23.5 でした。推測できる状況はどれでしょう？

1. インターネットに正常に接続できている
2. 管理者がこの固定アドレスを推奨設定として割り当てた
3. DHCPサーバからアドレスを取得できなかった
4. このPCがルータとして動作している

<details><summary>答えと解説</summary>

正解: **3**

169.254.0.0/16はリンクローカルアドレス（APIPA）で、DHCPサーバと通信できなかったときにOSが自動設定します。つまりDHCPまわりの障害を疑うサインです。この状態では同一リンクの外とは通信できず、インターネット接続は正常ではありません。手動の推奨設定に使う範囲ではなく、ルータとして動作している証拠にもなりません。

</details>

## 5. IPv6のきほん——表記・アドレス種別・IPv4との違い

IPv4のアドレス（約43億個）が足りなくなったため作られたのが **IPv6** です。アドレスは **128ビット** で、事実上無尽蔵の数を使えます。

### 表記ルール

16ビットずつ8グループに分け、16進数で表してコロンで区切ります。

`2001:0db8:0000:0000:0000:0000:0000:0001`

省略規則は2つです。

1. 各グループの**先頭の0は省略**できる（0db8 → db8）
2. **全0のグループが連続する部分は「::」に短縮**できる。ただし**1か所だけ**（2か所に使うと元の長さが復元できなくなるため）

→ `2001:db8::1`

### アドレスの種類

| 種類 | 範囲・特徴 |
|---|---|
| グローバルユニキャスト | 2000::/3。インターネットで使う |
| **リンクローカルユニキャスト** | **fe80::/10**。同一リンク内だけで有効。全インタフェースが自動生成する |
| マルチキャスト | ff00::/8。特定グループ宛て |

IPv6では**ブロードキャストが廃止**され、マルチキャストで代替します。ARPもなくなり、**ICMPv6による近隣探索（NDP）**でMACアドレスを解決します。さらに、ルータの広告する情報から端末が自分でアドレスを作る **SLAAC** という自動設定の仕組みもあります。

> 💡 🟡 まずは「128ビット・::は1か所だけ・fe80はリンクローカル・ブロードキャストなし」の4点をおさえましょう。詳しい運用は後の章で扱います。

### 確認問題

**問1.** IPv6アドレスの長さはどれでしょう？

1. 32ビット
2. 64ビット
3. 128ビット
4. 256ビット

<details><summary>答えと解説</summary>

正解: **3**

IPv6アドレスは128ビットで、IPv4（32ビット）の4倍の長さです。64ビットはIPv6のインタフェースID部分などに現れる区切りですがアドレス全体の長さではなく、256ビットという規格はありません。

</details>

**問2.** IPv6アドレスの「::」による省略の規則として、正しいものはどれでしょう？

1. 連続する全0のグループを、1か所に限り「::」に短縮できる
2. 全0のグループは何か所でも「::」に短縮できる
3. 各グループの末尾の0を省略できる
4. 16進数の部分を10進数に変換して短くできる

<details><summary>答えと解説</summary>

正解: **1**

「::」は連続する全0グループの短縮で、使えるのは1つのアドレスにつき1か所だけです。2か所に使うと、省略されたグループ数が特定できず元のアドレスを復元できません。省略できるのは各グループの先頭の0であって末尾の0ではなく、10進数への変換という規則もありません。

</details>

**問3.** fe80 で始まるIPv6アドレスの説明として、正しいものはどれでしょう？

1. インターネット全体で一意なグローバルユニキャストアドレス
2. 特定のグループ宛てのマルチキャストアドレス
3. 自分自身を指すループバックアドレス
4. 同一リンク内だけで有効なリンクローカルアドレス

正解: **4**

**問4.** IPv4には存在するが、IPv6で廃止されたものはどれでしょう？

1. ユニキャスト
2. ブロードキャスト
3. マルチキャスト
4. ヘッダのバージョン情報

<details><summary>答えと解説</summary>

正解: **2**

IPv6ではブロードキャストが廃止され、全ノード宛てマルチキャストなどで代替されます。あわせてARPも廃止され、ICMPv6の近隣探索（NDP）に置き換えられました。ユニキャストとマルチキャストはIPv6にも存在し、ヘッダのバージョン情報も引き続き持っています。

</details>
