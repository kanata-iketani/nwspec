# 第33章 午前Ⅱ模試（本試験形式25問）

本試験と同じ25問構成で挑む午前Ⅱの模試です。時計で40分を計り、本番のつもりで解いてみましょう。午前Ⅱはネットワークの専門分野なので、合格ラインの60点ではなく8割を目標にします。間違えた問題は第9〜26章に戻って穴をふさぎましょう。

## 1. 午前Ⅱ模試・前半（問1〜13）

午前Ⅱの模試です。本試験の午前Ⅱは**40分で25問**、1問あたり約95秒です。すべてネットワークとセキュリティの専門分野から出題されるので、午前Ⅰのような「広く浅く」ではなく、**深さと正確さ**が問われます。

### 午前Ⅱの目標は8割

合格ラインは60点ですが、午前Ⅱは皆さんの専門分野です。ここで8割（25問中20問）取れる実力があれば、同じ知識を使う午後試験でも戦えます。逆に午前Ⅱがぎりぎりだと、午後の長文の中で知識を使いこなすのは難しくなります。**模試で8割に届かなかった分野は、必ず該当の章に戻って覚え直しましょう。**

このチャプターは前半の問1〜13に相当し、イーサネット・VLAN・STPのレイヤ2技術、IPアドレスとサブネット計算、OSPF・BGP・VRRPのレイヤ3技術、そしてTCP/UDPを出題します。サブネット計算は午後でも頻出なので、模試でも手を動かして確実に正解したいところです。

### 確認問題

**問1.** レイヤ2スイッチがMACアドレステーブルを学習する方法として、適切なものはどれでしょう？

1. 受信したフレームの宛先MACアドレスと受信ポートを対応付けて記録する
2. 接続機器に定期的に問い合わせてMACアドレスの一覧を取得する
3. 受信したフレームの送信元MACアドレスと受信ポートを対応付けて記録する
4. 管理者がすべてのMACアドレスを手動で登録する

<details><summary>答えと解説</summary>

正解: **3**

スイッチはフレームを受信したとき、その送信元MACアドレスを「どのポートから届いたか」と対応付けてテーブルに学習します。宛先MACアドレスは学習に使うのではなく、テーブルを検索して転送先ポートを決めるために使います。機器への問合せや手動登録は基本の学習動作ではありません。

</details>

**問2.** イーサネットにおいて、同一セグメント内のすべての機器宛てに送信するときに使う宛先MACアドレスはどれでしょう？

1. FF-FF-FF-FF-FF-FF
2. 00-00-00-00-00-00
3. 自ホストと同じMACアドレス
4. デフォルトゲートウェイのMACアドレス

<details><summary>答えと解説</summary>

正解: **1**

全ビットが1である FF-FF-FF-FF-FF-FF はブロードキャストアドレスで、同一ブロードキャストドメイン内の全機器がそのフレームを受信します。ARP要求やDHCPのDISCOVERなどで使われます。全ビット0のアドレスにこの役割はなく、自ホスト宛は単なる自分への通信、デフォルトゲートウェイのMACアドレスは他ネットワーク宛てのユニキャスト転送に使うものです。

</details>

**問3.** IEEE 802.1QのVLANタグに関する説明として、適切なものはどれでしょう？

1. IPヘッダのオプション領域にVLAN番号を書き込む
2. イーサネットフレームに4バイトのタグを挿入し、その中の12ビットのVLAN IDで識別する
3. LANケーブルの色によってVLANを物理的に区別する
4. VLANごとに異なるMACアドレスを各機器に割り当てる

<details><summary>答えと解説</summary>

正解: **2**

802.1Qでは、イーサネットフレームの送信元MACアドレスの後ろに4バイトのタグを挿入し、そのうち12ビットがVLAN IDです。トランクリンクで複数VLANのフレームを1本のリンクに相乗りさせるために使います。レイヤ2の仕組みなのでIPヘッダは使わず、ケーブルの色やMACアドレスの割当てで識別する方式でもありません。

</details>

**問4.** スパニングツリープロトコル（STP）でルートブリッジに選出されるスイッチはどれでしょう？

1. ポート数が最も多いスイッチ
2. MACアドレスが最も大きいスイッチ
3. 最後にネットワークへ接続されたスイッチ
4. ブリッジプライオリティが最も小さいスイッチ（同値の場合はMACアドレスが最小のもの）

<details><summary>答えと解説</summary>

正解: **4**

STPではブリッジID（プライオリティ＋MACアドレス）が最小のスイッチがルートブリッジになります。まずプライオリティ値を比較し、同じならMACアドレスが小さい方が選ばれるので、管理者はプライオリティを小さく設定して意図したスイッチをルートにします。ポート数や接続した順番、MACアドレスの大きさは選出条件ではありません。

</details>

**問5.** IPv4ヘッダのTTLフィールドの役割として、適切なものはどれでしょう？

1. ルータを通過するたびに1ずつ減り、0になるとパケットが破棄されることで経路のループを防ぐ
2. パケットの送信時刻を記録して遅延を測定する
3. パケットの優先度を表してQoS制御に使われる
4. ヘッダの伝送誤りを検出する

<details><summary>答えと解説</summary>

正解: **1**

TTL（Time To Live）はルータを経由するたびに1減算され、0になるとそのパケットは破棄されて、送信元へICMPの時間超過が返されます。これによりルーティングループでパケットが永遠に回り続けるのを防ぎます。時刻の記録機能はなく、優先度はDSCP（ToS）フィールド、誤り検出はヘッダチェックサムの役割です。

</details>

**問6.** 192.168.10.0/26 のサブネットで利用できるホストアドレスの数はどれでしょう？

1. 30
2. 62
3. 64
4. 126

<details><summary>答えと解説</summary>

正解: **2**

/26 はホスト部が 32−26＝6ビットなので、アドレスの総数は 2の6乗＝64個。ここからネットワークアドレスとブロードキャストアドレスの2つを除いた 64−2＝62 が利用できるホスト数です。30は/27（5ビット）、126は/25（7ビット）の場合の値で、64は2つのアドレスを除き忘れた誤りです。

</details>

**問7.** IPアドレス 172.16.5.130、サブネットマスク 255.255.255.192 のホストが属するネットワークアドレスはどれでしょう？

1. 172.16.5.0
2. 172.16.5.64
3. 172.16.5.128
4. 172.16.5.192

<details><summary>答えと解説</summary>

正解: **3**

マスク 255.255.255.192 は /26 で、第4オクテットは64刻み（0、64、128、192）のブロックに分かれます。130 は 128以上192未満の範囲にあるので、ネットワークアドレスは 172.16.5.128 です。2進数で確かめても、130（10000010）と192（11000000）のANDは128（10000000）になります。ほかの選択肢は130を含まないブロックの先頭です。

</details>

**問8.** OSPFの特徴として、適切なものはどれでしょう？

1. リンクステート型のプロトコルで、各ルータがネットワーク全体の情報（LSDB）を持ち、コスト最小の経路を計算する
2. 経由するルータの台数（ホップ数）だけを基準に経路を選択する
3. AS間の経路交換を目的としたプロトコルである
4. 30秒ごとに経路表全体をブロードキャストで広告する

<details><summary>答えと解説</summary>

正解: **1**

OSPFはリンクステート型のルーティングプロトコルで、LSAを交換してリンクステートデータベース（LSDB）を構築し、ダイクストラ法でコスト最小の経路を計算します。コストは帯域幅をもとに決まります。ホップ数を基準に30秒周期で経路表を広告するのはディスタンスベクタ型のRIPの動作で、AS間の経路交換はBGPの役割です。

</details>

**問9.** BGPに関する説明として、適切なものはどれでしょう？

1. 同一AS内部の最短経路計算に特化したプロトコルである
2. UDP上で動作し、信頼性よりも速度を優先する
3. リンクの帯域幅から求めたコストのみで経路を選択する
4. AS間の経路制御に使われるパスベクタ型のプロトコルで、TCPのコネクション上で経路情報を交換する

<details><summary>答えと解説</summary>

正解: **4**

BGPはAS（自律システム）間の経路制御プロトコルで、経由するASの並び（ASパス）などのパス属性をもとに経路を選び、TCP（ポート179）のコネクション上で経路情報を交換します。AS内部の経路制御はOSPFなどのIGPの役割です。TCPを使うのでUDP上で動くという説明は誤りで、帯域ベースのコスト計算はOSPFの方式です。

</details>

**問10.** VRRPの説明として、適切なものはどれでしょう？

1. 複数の物理リンクを束ねて帯域を拡大するプロトコル
2. 複数のルータで仮想IPアドレスを共有し、マスタの故障時にバックアップが引き継ぐことでデフォルトゲートウェイを冗長化するプロトコル
3. ルータ同士が経路情報を交換するためのプロトコル
4. ルータの設定ファイルを遠隔地に自動バックアップするプロトコル

<details><summary>答えと解説</summary>

正解: **2**

VRRPでは複数のルータが1つの仮想ルータとして仮想IPアドレス（と仮想MACアドレス）を共有し、マスタの障害を検知するとバックアップが引き継ぎます。端末はデフォルトゲートウェイの設定を変えずに済むのが利点です。リンクを束ねるのはリンクアグリゲーション、経路情報の交換はOSPFやBGPなどの役割で、設定のバックアップ機能でもありません。

</details>

**問11.** TCPのコネクション確立（3ウェイハンドシェイク）でやり取りされるセグメントの順序として、正しいものはどれでしょう？

1. ACK → SYN → SYN/ACK
2. SYN → ACK → SYN/ACK
3. SYN → SYN/ACK → ACK
4. SYN/ACK → SYN → ACK

<details><summary>答えと解説</summary>

正解: **3**

接続を開始する側がSYNを送り、相手はSYNとACKのフラグを同時に立てたSYN/ACKで応答し、最後に開始側がACKを返して確立します。この3回のやり取りで、お互いのシーケンス番号の初期値を確認し合います。ほかの順序では「要求→応答→確認」という流れが成立しません。

</details>

**問12.** TCPのウィンドウサイズが表すものはどれでしょう？

1. 1つのセグメントで送れるデータの最大長
2. コネクションを維持できる最大時間
3. 再送を試みる最大回数
4. 確認応答（ACK）を待たずに連続して送信できるデータ量

<details><summary>答えと解説</summary>

正解: **4**

ウィンドウサイズは、ACKを受け取る前に送信してよいデータ量の上限で、受信側がバッファの空きに応じて通知します。これを大きくすると往復遅延（RTT）の影響を受けにくくなり、スループットが向上します。1セグメントの最大データ長はMSSと呼ばれる別の値で、再送回数やコネクションの維持時間を表すものではありません。

</details>

**問13.** UDPの特徴として、適切なものはどれでしょう？

1. コネクションの確立や再送制御を行わないため処理が軽く、音声通話やDNSの問合せなどに向く
2. 確認応答と再送によって信頼性の高いデータ転送を保証する
3. 3ウェイハンドシェイクでコネクションを確立してから通信する
4. ポート番号を持たないため、アプリケーションの識別はIPアドレスだけで行う

<details><summary>答えと解説</summary>

正解: **1**

UDPはコネクションレス型で、確認応答・再送・順序制御を行わない代わりにヘッダが8バイトと小さく、低遅延です。リアルタイム性が重要な音声・映像配信や、短い問合せで完結するDNSに適しています。信頼性の保証と3ウェイハンドシェイクはTCPの特徴です。UDPのヘッダにも送信元・宛先のポート番号はあり、アプリケーションの識別に使われます。

</details>

- 残り時間で見直すときは、「問題文が『適切なもの』と『不適切なもの』のどちらを聞いているか」の読み違いを真っ先に確認します

### 確認問題

**問1.** DNSのフルサービスリゾルバ（キャッシュDNSサーバ）の動作として、適切なものはどれでしょう？

1. 自分が管理するゾーンの情報だけを応答し、他のドメインには応答しない
2. クライアントに代わってルートサーバから順に反復問合せを行い、得た結果をキャッシュして応答する
3. 権威サーバからゾーン情報全体を定期的に複製して保持する
4. ドメイン名の登録申請を受け付けてレジストリに取り次ぐ

<details><summary>答えと解説</summary>

正解: **2**

フルサービスリゾルバはクライアントからの再帰的な問合せを受け、ルートサーバ→TLDのサーバ→権威サーバの順に反復問合せをして名前解決し、結果をTTLの期間だけキャッシュします。自ゾーンの情報を応答するのは権威サーバ、ゾーン情報の複製はセカンダリサーバが行うゾーン転送、登録申請の取次ぎはレジストラの役割です。

</details>

**問2.** クライアントがDHCPでIPアドレスを取得するときのメッセージの順序として、正しいものはどれでしょう？

1. OFFER → DISCOVER → ACK → REQUEST
2. REQUEST → ACK → DISCOVER → OFFER
3. DISCOVER → REQUEST → OFFER → ACK
4. DISCOVER → OFFER → REQUEST → ACK

<details><summary>答えと解説</summary>

正解: **4**

クライアントがブロードキャストのDISCOVERでサーバを探し、サーバがOFFERで候補アドレスを提示し、クライアントがREQUESTで使用したいアドレスを要求し、サーバがACKで確定します。頭文字をとってDORAと覚えられます。まだアドレスを持たないクライアント側から始まるため、OFFERやREQUESTから始まる順序はあり得ません。

</details>

**問3.** NAPT（IPマスカレード）の説明として、適切なものはどれでしょう？

1. 複数のプライベートIPアドレスを1つのグローバルIPアドレスで共有し、ポート番号も変換して各通信を識別する
2. プライベートIPアドレスとグローバルIPアドレスを常に1対1で固定的に変換する
3. IPアドレスからMACアドレスを解決する
4. ドメイン名をIPアドレスに変換する

<details><summary>答えと解説</summary>

正解: **1**

NAPTはIPアドレスに加えてポート番号も変換することで、多数の内部端末が1つのグローバルIPアドレスを共有できるようにする仕組みで、家庭用ルータでも使われています。1対1の固定変換は静的NATの説明です。IPアドレスからMACアドレスを解決するのはARP、ドメイン名の解決はDNSの役割で、アドレス変換とは別の機能です。

</details>

**問4.** HTTPSで使われるTLSの仕組みとして、適切なものはどれでしょう？

1. 通信のすべてを公開鍵暗号だけで暗号化する
2. サーバ証明書は暗号化とは無関係で、画面表示のために使われる
3. ハンドシェイクでサーバ証明書の検証と鍵の共有を行い、以降のデータは共通鍵暗号で暗号化する
4. 利用するにはクライアント側にも必ず証明書を導入しなければならない

<details><summary>答えと解説</summary>

正解: **3**

TLSはハンドシェイクでサーバ証明書の検証と鍵交換を行い、合意したセッション鍵（共通鍵）でアプリケーションデータを暗号化します。処理の重い公開鍵暗号は認証と鍵交換に限定して使うハイブリッド方式です。サーバ証明書はなりすまし防止の要であり飾りではありません。クライアント証明書は相互認証を行う場合にだけ使う任意の仕組みです。

</details>

**問5.** 送信ドメイン認証のSPFの仕組みとして、適切なものはどれでしょう？

1. 受信側が、送信元ドメインのDNSに公開された送信許可IPアドレスの一覧と、実際の送信元IPアドレスを照合する
2. 送信側がメールにディジタル署名を付与し、受信側がDNSで公開された公開鍵で検証する
3. メール本文を暗号化して経路上の盗聴を防ぐ
4. 添付ファイルをウイルス検査して駆除する

<details><summary>答えと解説</summary>

正解: **1**

SPFでは、ドメインの管理者が正当なメール送信元のIPアドレスをDNSのSPFレコード（TXTレコード）として公開し、受信側が送信元ドメインのレコードを引いて実際の送信元IPアドレスと照合します。ディジタル署名をDNS上の公開鍵で検証するのはDKIMの仕組みです。本文の暗号化やウイルス検査は、送信ドメイン認証とは別の対策です。

</details>

**問6.** 無線LANで CSMA/CD ではなく CSMA/CA が使われる理由として、適切なものはどれでしょう？

1. 無線では衝突が物理的に発生しないため
2. 無線では送信中に自局で衝突を検出することが困難なため、送信前の待機などで衝突を回避する必要があるから
3. CSMA/CAの方があらゆる環境で通信速度が速いから
4. 電波法でCSMA/CDの使用が禁止されているから

<details><summary>答えと解説</summary>

正解: **2**

無線では送信中の自局の電波が強すぎて他局との衝突を検出できず、互いに電波が届かない端末同士の「隠れ端末問題」もあります。そこでキャリアセンスの後にランダムな時間待ってから送信し、ACKで成功を確認するCSMA/CA（衝突回避）を使います。無線でも衝突自体は発生しますし、速度の優劣や法律上の禁止が理由ではありません。

</details>

**問7.** 有効期限内のディジタル証明書が失効していないかを確認する方法として、適切なものはどれでしょう？

1. 証明書の有効期限の欄を確認すれば十分である
2. 証明書の発行先サーバに電子メールで問い合わせる
3. 証明書のハッシュ値を自分で再計算して比較する
4. 認証局が公開するCRLを参照するか、OCSPでオンライン照会する

<details><summary>答えと解説</summary>

正解: **4**

秘密鍵の漏えいなどがあると、有効期限内でも証明書は失効されます。失効状態は、認証局が発行するCRL（証明書失効リスト）の参照か、OCSPによるリアルタイムのオンライン照会で確認します。有効期限の確認だけでは失効を検出できず、メールで問い合わせる仕組みはありません。ハッシュ値の再計算は改ざんの検知であって失効確認ではありません。

</details>

**問8.** ステートフルインスペクション型ファイアウォールの説明として、適切なものはどれでしょう？

1. パケットを1つずつ独立に評価し、通信の前後関係は考慮しない
2. アプリケーションの代理として通信を中継し、HTTPの内容まで検査する
3. 通信のセッション状態を記録し、内部から開始した通信の戻りパケットを動的に許可する
4. ウイルス定義ファイルと照合してマルウェアを検出・駆除する

<details><summary>答えと解説</summary>

正解: **3**

ステートフルインスペクションはセッションの状態テーブルを保持し、内部発の通信に対応する戻りの通信だけを動的に許可します。これにより、戻り方向の広い許可ルールを静的に開けておく必要がなくなります。1つ目は静的なパケットフィルタリング、2つ目はプロキシ型（アプリケーションゲートウェイ）、4つ目はアンチウイルス製品の説明です。

</details>

**問9.** IPsecのトンネルモードの説明として、適切なものはどれでしょう？

1. 元のIPパケット全体を暗号化・カプセル化し、新しいIPヘッダを付けて転送する
2. 元のIPヘッダはそのまま使い、ペイロード部分だけを保護する
3. TCPポート443を使い、Webブラウザだけで利用できるVPNを実現する
4. データリンク層のフレームをそのまま遠隔拠点まで延伸する

<details><summary>答えと解説</summary>

正解: **1**

トンネルモードは元のIPパケットをヘッダごと丸ごと保護し、VPN装置間の新しいIPヘッダを付加するため、拠点間VPNで社内のアドレスを隠したまま通信できます。元のヘッダを残してペイロードだけ保護するのはトランスポートモードです。ポート443でブラウザから使えるのはTLS-VPN（SSL-VPN）、レイヤ2フレームの延伸は広域イーサネットの説明です。

</details>

**問10.** IEEE 802.1X認証を構成する3つの要素の組合せとして、適切なものはどれでしょう？

1. Webサーバ・DNSサーバ・メールサーバ
2. サプリカント・オーセンティケータ・認証サーバ
3. ファイアウォール・IDS・IPS
4. ルート認証局・中間認証局・利用者証明書

<details><summary>答えと解説</summary>

正解: **2**

802.1Xでは、端末側のソフトウェアであるサプリカント、接続点となるスイッチや無線アクセスポイントなどのオーセンティケータ、認証の可否を判断するRADIUSサーバなどの認証サーバが連携し、認証に成功するまでポートを開放しません。ほかの選択肢はそれぞれサーバの種類、防御機器の種類、PKIの証明書チェーンであり、802.1Xの構成要素ではありません。

</details>

**問11.** QoS制御におけるシェーピングの説明として、適切なものはどれでしょう？

1. 契約帯域を超えたパケットをその場で破棄する
2. 特定のアプリケーションの通信をすべて遮断する
3. パケットの誤りを訂正して再送を減らす
4. 超過したトラフィックをバッファに一時的にためて送出間隔を調整し、出力を契約帯域内に平準化する

<details><summary>答えと解説</summary>

正解: **4**

シェーピングは、超過分のトラフィックをバッファリングして送出を遅らせ、出力レートをならす制御です。超過分を即座に破棄したり優先度を下げたりするのはポリシングで、両者の違いは定番の論点です。通信の遮断はフィルタリング、誤り訂正はFECなどの技術で、シェーピングの説明ではありません。

</details>

**問12.** SNMPにおいて、エージェントが障害などのイベント発生を自発的にマネージャへ通知するメッセージはどれでしょう？

1. GetRequest
2. SetRequest
3. Trap
4. GetNextRequest

<details><summary>答えと解説</summary>

正解: **3**

Trapはエージェント側から送る自発的な通知で、リンクダウンなどの発生をマネージャへ即座に知らせます。マネージャからの定期取得（ポーリング）を待たずに伝えられるのが利点です。GetRequestとGetNextRequestはマネージャがMIBの値を取得するための要求、SetRequestはマネージャが値を設定するための要求で、いずれも向きが逆です。

</details>
