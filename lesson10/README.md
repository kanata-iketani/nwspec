# 第10章 物理層とイーサネット

データが実際に流れる最下層、物理層とイーサネットの章です。ケーブルの種類と規格、MACアドレスとフレームの構造、ハブとスイッチの違い、そしてIPとMACをつなぐARPまで、LANの足回りを固めます。

## 1. 伝送媒体——UTPケーブルと光ファイバ

データが実際に流れる「道路」にあたるのが**伝送媒体**です。LANでは主に2種類を使い分けます。

### UTPケーブルと光ファイバ

| 媒体 | 特徴 |
|---|---|
| **UTPケーブル** | 銅線を2本ずつより合わせた**ツイストペアケーブル**。より合わせることで信号線間のノイズ（クロストーク）を打ち消す。安価で扱いやすいが、距離は最大100m |
| **光ファイバ** | 光で伝送するため電磁ノイズの影響を受けず、長距離・高速。コア径が細く長距離向きの**シングルモード（SMF）**と、安価で近距離向きの**マルチモード（MMF）**がある |

### イーサネットの規格名の読み方

「**1000BASE-T**」は「速度1000Mbps・ベースバンド伝送・T＝ツイストペア」と読みます。末尾がT系ならUTP、SXやLXなら光ファイバです。

| 規格 | 速度 | 媒体 |
|---|---|---|
| 100BASE-TX | 100Mbps | UTP（Cat5以上） |
| **1000BASE-T** | 1Gbps | UTP（Cat5e以上）・最大100m |
| 10GBASE-T | 10Gbps | UTP（Cat6A推奨）・最大100m |
| 1000BASE-LX | 1Gbps | 光ファイバ（長距離向き） |

UTPは**カテゴリ**（Cat5e/6/6Aなど）の数字が大きいほど、高速な規格に対応します。

> 💡 🟡 「T＝より対線で100mまで」「フロア間・長距離・ノイズ源の近くは光」。午後の構成図でも、この使い分けがそのまま登場します。

### 確認問題

**問1.** 1000BASE-T の伝送媒体と最大伝送距離の組合せとして、正しいものはどれでしょう？

1. 光ファイバで最大550m
2. 同軸ケーブルで最大185m
3. UTPケーブル（カテゴリ5e以上）で最大100m
4. UTPケーブルで最大10km

<details><summary>答えと解説</summary>

正解: **3**

末尾の「T」はツイストペア（UTP）を表し、1000BASE-TはCat5e以上のUTPで最大100mです。光ファイバを使う1Gbps規格は1000BASE-SX/LXなど別の名前になります。同軸ケーブルは昔の10BASE2などで使われた媒体で、UTPで10kmという長距離は規格上ありえません。

</details>

**問2.** 光ファイバがUTPケーブルより優れている点として、適切なものはどれでしょう？

1. 電磁ノイズの影響を受けにくく、長距離伝送に向く
2. 折り曲げに強く、施工の自由度が高い
3. どんな場合でもUTPより安価に構築できる
4. 専用工具なしでコネクタを簡単に加工できる

<details><summary>答えと解説</summary>

正解: **1**

光ファイバは電気ではなく光で伝送するため電磁ノイズの影響を受けず、数百m〜数十kmの長距離伝送が可能です。一方で曲げには弱く、ケーブルや機器・施工のコストはUTPより高めで、コネクタ加工にも専用の技術が必要です。

</details>

**問3.** UTPケーブルで2本の銅線をより合わせている目的はどれでしょう？

1. ケーブルを太くして断線を防ぐため
2. 伝送距離を10kmまで延ばすため
3. 2本の線で別々のデータを同時に送るため
4. 信号線間で生じるノイズ（クロストーク）の影響を打ち消すため

<details><summary>答えと解説</summary>

正解: **4**

より合わせ（ツイスト）によって、外部や隣のペアから受けるノイズを2本の線で打ち消し合わせるのが目的です。断線防止のためではなく、UTPの最大距離は100mのままです。2本の線は1つの信号を差動で運ぶペアであり、別々のデータを運ぶわけではありません。

</details>

**問4.** シングルモード光ファイバ（SMF）の特徴として、正しいものはどれでしょう？

1. コア径が太く、短距離を安価に結ぶのに向く
2. コア径が細く光の通り道が1つで、長距離伝送に向く
3. 銅線を使うため電磁ノイズに弱い
4. 最大伝送距離が100mに制限される

<details><summary>答えと解説</summary>

正解: **2**

SMFはコア径が細く、光がほぼ一直線のモード1つだけで進むため信号が乱れにくく、数十kmの長距離伝送に向きます。コア径が太く短距離・安価なのはマルチモード（MMF）の特徴です。光ファイバは銅線ではなくガラスなどでできており、100m制限はUTPの話です。

</details>

## 2. MACアドレスとイーサネットフレームの構造

LANの中で機器を識別する「宛名」が **MACアドレス** です。NIC（ネットワークインタフェースカード）ごとに付けられた **48ビット** の番号で、「00-1A-2B-3C-4D-5E」のように16進数12桁で表記します。

### MACアドレスの構造

| 前半24ビット | 後半24ビット |
|---|---|
| **OUI**（ベンダ識別子）。製造ベンダごとにIEEEが割り当てる | ベンダが機器ごとに割り当てる固有番号 |

全ビットが1の「**FF-FF-FF-FF-FF-FF**」は**ブロードキャストアドレス**で、同じネットワーク内の全員宛てを意味します。

### イーサネットフレームの構造

| フィールド | サイズ | 役割 |
|---|---|---|
| 宛先MACアドレス | 6バイト | 届け先 |
| 送信元MACアドレス | 6バイト | 差出人 |
| タイプ | 2バイト | 中身の上位プロトコル識別（0x0800＝IPv4） |
| データ | 46〜1500バイト | IPパケットなど |
| FCS | 4バイト | 誤り検出 |

データ部の最大値 **1500バイト** を **MTU** と呼びます。これより大きいデータは、上位層で分割してから運びます。

> 💡 🔴 「MACは48ビット・前半はOUI・全ビット1でブロードキャスト・MTUは1500」。午前Ⅱの数字を問う問題は、ほぼこの4点に集中します。

### 確認問題

**問1.** MACアドレスの長さとして、正しいものはどれでしょう？

1. 32ビット
2. 48ビット
3. 64ビット
4. 128ビット

<details><summary>答えと解説</summary>

正解: **2**

MACアドレスは48ビットで、16進数12桁で表記します。32ビットはIPv4アドレス、128ビットはIPv6アドレスの長さなので混同しないようにしましょう。64ビットはどちらのアドレス長でもありません。

</details>

**問2.** MACアドレスの前半24ビット（OUI）が表すものはどれでしょう？

1. 機器が所属するネットワークの番号
2. 機器の設置場所
3. NICの製造ベンダ
4. 対応するイーサネット規格の種類

<details><summary>答えと解説</summary>

正解: **3**

OUIはIEEEが製造ベンダごとに割り当てる識別子で、前半24ビットを見ればどのベンダのNICか分かります。後半24ビットはベンダ内での固有番号です。MACアドレスには所属ネットワークの情報は含まれず、それはIPアドレスの役割です。設置場所や対応規格も表しません。

</details>

**問3.** 宛先MACアドレスが FF-FF-FF-FF-FF-FF のフレームの扱いとして、正しいものはどれでしょう？

1. 同一ブロードキャストドメイン内のすべての機器に届く
2. 最も近くにいる1台だけが受信する
3. ルータに中継されてインターネット全体に届く
4. 不正なアドレスとしてスイッチで破棄される

<details><summary>答えと解説</summary>

正解: **1**

全ビット1のMACアドレスはブロードキャストアドレスで、スイッチは受信ポート以外の全ポートへ転送し、同じネットワーク内の全機器が受信します。ただしルータはこれを中継しないため、届く範囲はブロードキャストドメイン内に限られます。最も近い1台だけに届く仕組みではなく、正当なアドレスなので破棄もされません。

</details>

**問4.** イーサネットフレームのタイプフィールドの役割はどれでしょう？

1. フレームの送信時刻を記録する
2. 誤り検出用のチェック値を格納する
3. フレームの分割順序を示す
4. データ部に格納された上位層プロトコルを識別する

<details><summary>答えと解説</summary>

正解: **4**

タイプフィールドは中身のプロトコルを示す2バイトの値で、0x0800ならIPv4パケットが入っていることを表します。誤り検出のチェック値はフレーム末尾のFCSの役割です。イーサネットフレーム自体に送信時刻や分割順序を記録するフィールドはありません。

</details>

## 3. リピータハブとスイッチ——2つのドメインの違い

複数のPCをつなぐ集線装置には、古くからの**リピータハブ**と、現在主流の**スイッチ（L2スイッチ）**があります。両者の違いは午前Ⅱの定番テーマです。

### リピータハブ（物理層の機器）

受け取った電気信号を**全ポートにそのまま中継**します。全員が同じ通り道を共有するため、2台が同時に送信すると信号がぶつかる**コリジョン（衝突）**が発生。ハブにつながる範囲全体が1つの**コリジョンドメイン**になり、台数が増えるほど性能が落ちます。

### スイッチ（データリンク層の機器）

受信フレームの**送信元MACアドレス**から「どのポートの先に誰がいるか」を**MACアドレステーブル**に学習し、以降は**宛先のポートだけ**にフレームを転送します。

| 観点 | リピータハブ | スイッチ |
|---|---|---|
| 動作する層 | 物理層 | データリンク層 |
| 転送先 | 全ポート | 宛先のポートのみ |
| コリジョンドメイン | 全体で1つ | **ポートごとに分割** |
| 通信方式 | 半二重 | 全二重が可能 |

ただし**ブロードキャストはスイッチも全ポートへ転送**します。ブロードキャストの届く範囲（**ブロードキャストドメイン**）を分割できるのは**ルータ**（または次章のVLAN）です。

> 💡 🔴 「スイッチはコリジョンドメインを分割、ルータはブロードキャストドメインを分割」。このフレーズは午前Ⅱで繰り返し問われます。

### 確認問題

**問1.** L2スイッチがポートごとに分割するものはどれでしょう？

1. ブロードキャストドメイン
2. ネットワークアドレス
3. サブネットマスク
4. コリジョンドメイン

<details><summary>答えと解説</summary>

正解: **4**

スイッチは宛先のポートだけに転送するため、ポートごとにコリジョンドメインが分割され、衝突が起きなくなります。一方ブロードキャストは全ポートに転送されるので、ブロードキャストドメインは分割されません（分割するのはルータやVLAN）。ネットワークアドレスやサブネットマスクは第3層の概念で、L2スイッチが分割するものではありません。

</details>

**問2.** スイッチがMACアドレステーブルを作る方法として、正しいものはどれでしょう？

1. 受信したフレームの送信元MACアドレスと受信ポートの対応を記録して学習する
2. 管理者がすべてのエントリを手動で登録する
3. 各機器にブロードキャストで問い合わせて一覧を収集する
4. ルータから定期的にテーブルの配布を受ける

<details><summary>答えと解説</summary>

正解: **1**

スイッチはフレームが届くたびに「この送信元MACアドレスはこのポートの先にいる」と自動学習します。手動登録は原則不要で、問い合わせ用のプロトコルやルータからの配布という仕組みもありません。

</details>

**問3.** MACアドレステーブルに載っていない宛先MACアドレスのフレームを受信したとき、スイッチはどう動作するでしょう？

1. 宛先不明としてフレームを破棄する
2. 受信ポート以外のすべてのポートへ転送する（フラッディング）
3. 送信元へエラーを返して再送を要求する
4. デフォルトゲートウェイへ転送する

<details><summary>答えと解説</summary>

正解: **2**

宛先の居場所が分からないフレームは、受信ポート以外の全ポートへ送るフラッディングで対処します。宛先が応答すればその送信元MACアドレスを学習でき、次からは該当ポートだけに送れます。破棄やエラー応答はせず、デフォルトゲートウェイはPCがIP通信で使う概念であって、L2スイッチの転送先ではありません。

</details>

**問4.** リピータハブの説明として、正しいものはどれでしょう？

1. MACアドレスを学習し、宛先のポートだけに転送する
2. IPアドレスを見て最適な経路を選択する
3. 受信した信号を全ポートに中継するため、接続範囲全体が1つのコリジョンドメインになる
4. VLANを設定してブロードキャストドメインを分割できる

<details><summary>答えと解説</summary>

正解: **3**

リピータハブは物理層の機器で、信号を増幅して全ポートに流すだけです。そのため接続された全機器が1つのコリジョンドメインを共有します。MACアドレスの学習はスイッチ、IPアドレスによる経路選択はルータ、VLANはスイッチの機能であり、ハブにはいずれもありません。

</details>

## 4. ARPのしくみ——IPアドレスからMACアドレスを知る

宛先のIPアドレスが分かっても、イーサネットのフレームを作るには**宛先MACアドレス**が必要です。「このIPアドレスを持っているのは誰？ MACアドレスを教えて」を解決するのが **ARP**（Address Resolution Protocol）です。

### ARPの動き

1. PC-Aが「192.168.1.20 のMACアドレスを教えてください」という **ARP要求** を**ブロードキャスト**で送ります（誰が持っているか分からないので全員に聞く）
2. 自分のIPアドレスだと気づいたPC-Bだけが、自分のMACアドレスを**ユニキャスト**の **ARP応答** で返します
3. PC-Aは結果を **ARPキャッシュ** に一定時間保存し、しばらくは問い合わせを省略します

### 宛先が別ネットワークのとき

ARP要求はブロードキャストなので、ルータを越えられず**同じネットワークの中でしか使えません**。宛先が別ネットワークの場合、PCがARPで解決するのは遠くのサーバではなく、**デフォルトゲートウェイ（ルータ）のMACアドレス**です。前章で見た「宛先MACは区間ごとに変わる」は、各区間でこのARPが行われることで実現されています。

> 💡 🔴 「要求はブロードキャスト、応答はユニキャスト」「別ネットワーク宛てはゲートウェイのMACを解決」。午前Ⅱでも午後でも繰り返し登場する超頻出ポイントです。

### 確認問題

**問1.** ARPの目的として、正しいものはどれでしょう？

1. MACアドレスから対応するIPアドレスを求める
2. ホスト名から対応するIPアドレスを求める
3. IPアドレスから対応するMACアドレスを求める
4. IPアドレスを端末に自動的に割り当てる

<details><summary>答えと解説</summary>

正解: **3**

ARPは宛先IPアドレスに対応するMACアドレスを調べ、フレームの宛先を決めるために使います。逆方向（MACアドレスからIPアドレス）は歴史的にRARPと呼ばれる別の仕組みで、ホスト名からIPアドレスを調べるのはDNS、IPアドレスの自動割当てはDHCPの役割です。

</details>

**問2.** ARP要求とARP応答の送信方法の組合せとして、正しいものはどれでしょう？

1. 要求はブロードキャスト、応答はユニキャスト
2. 要求はユニキャスト、応答はブロードキャスト
3. 要求も応答もブロードキャスト
4. 要求も応答もマルチキャスト

<details><summary>答えと解説</summary>

正解: **1**

相手のMACアドレスが分からない段階の要求は全員に届くブロードキャストで送り、自分宛てだと分かった機器だけが、要求者のMACアドレス宛てのユニキャストで応答します。応答までブロードキャストにする必要はなく、ARPはマルチキャストを使いません。

</details>

**問3.** ARPキャッシュの説明として、適切なものはどれでしょう？

1. 一度学習した対応は機器を廃棄するまで永続的に保持される
2. 解決したIPアドレスとMACアドレスの対応を一定時間保存し、問い合わせの繰返しを減らす
3. ネットワーク内の全ARP要求の履歴をルータが集中管理する仕組みである
4. キャッシュがあるため、同じ宛先へのARP要求は一度しか送信できない

<details><summary>答えと解説</summary>

正解: **2**

ARPキャッシュは解決結果の一時保存で、通信のたびにブロードキャストを流す無駄を省きます。エントリには有効期限があり、期限が切れれば再び問い合わせます。永続保持でも集中管理でもなく、期限切れや削除後に再度要求することも普通にあります。

</details>

**問4.** 宛先のIPアドレスが別ネットワークに属する場合、PCが取る動作として正しいものはどれでしょう？

1. 宛先サーバのMACアドレスを直接ARPで問い合わせる
2. MACアドレスなしの特別なフレームを送信する
3. DNSサーバに宛先のMACアドレスを問い合わせる
4. デフォルトゲートウェイのMACアドレスをARPで解決し、そこへフレームを送る

<details><summary>答えと解説</summary>

正解: **4**

ARP要求はブロードキャストでルータを越えられないため、別ネットワークの機器には届きません。そこでPCは中継役であるデフォルトゲートウェイのMACアドレスを解決し、フレームをそこへ送ります。宛先MACアドレスのないイーサネットフレームは作れず、DNSが扱うのは名前とIPアドレスの対応であってMACアドレスではありません。

</details>
